# BM 캔버스 작업 규칙

이 폴더에서 BM(비즈니스 모델) 캔버스를 만들고 검증할 때 따르는 규칙이다.

## 1. 캔버스 작성 규칙

- **근거 표기**: 9개 칸 각각의 끝에 근거 파일명을 적는다. 받은 재료에 근거가 없으면 `가정`이라고 표기한다.
- **숫자 표기**: 금액, 비율, 건수 등 모든 숫자 옆에 `가정값` 또는 `확인값`을 붙인다. 출처가 있는 숫자만 `확인값`이다.
- **사실 지어내기 금지**: 기관명, 통계, 가격 같은 사실은 재료에 없으면 만들지 않는다. 재료에 `미정` 또는 `미확인`으로 적힌 내용은 그대로 옮긴다.

## 2. 후보 제시 규칙

- 후보를 요청받으면 후보만 제시한다.
- 후보 중 하나를 고르는 결정은 사람이 한다.

## 3. 레드팀 검증 규칙

- 검증은 아래 서브에이전트 3개를 **동시에** 실행한다. 정의 파일은 `.claude/agents/`에 있다.
  - `redteam-investor`
  - `redteam-customer`
  - `redteam-competitor`
- 메인 세션이 직접 지적을 만들지 않는다. 지적은 서브에이전트만 만든다.
- 서브에이전트는 **읽기만** 한다. 파일을 수정하거나 만들지 않는다.
- 메인 세션은 `bm/redteam/` 폴더를 만들고, 서브에이전트 결과 원문을 수정 없이 그대로 저장한다.
- 메인 세션은 원문을 바탕으로 `bm/redteam_log.md`에 표를 만들어 3개 결과를 합친다.
- **결정은 사람이 한다.** 표의 결정 칸에 `수용`, `수정`, `반려` 중 하나를 사람이 적는다. AI는 결정 칸을 대신 채우지 않는다.
  - `수용`: 지적을 받아들인다. 버튼을 누르면 결정만 기록하고 캔버스는 바로 고치지 않는다.
  - `수정`: 지적은 받아들이되 내용을 사람이 고쳐서 기록한다. 고친 문장이 캔버스 반영 대상이다.
  - `반려`: 지적을 무시한다. 캔버스를 고치지 않는다.
- **캔버스 반영은 일괄로 한다.** `bm/monitor.html`의 "캔버스 반영" 버튼을 누르면 결정이 `수용`인 줄과 `수정`인 줄을 한꺼번에 캔버스에 반영한다. 결정이 `반려`인 줄은 고치지 않는다.
- 모니터 화면은 `bm/monitor.html`이다. 실행 버튼을 누르면 레드팀 3개가 동시에 실행되고, 실행 중에는 상태 표시가 깜빡인다. 검토가 끝나면 로그가 남고, 하단 표에서 결정을 기록한다.

## 4. 완료 기준

- 9개 칸이 모두 채워져 있고, 칸마다 근거 파일 또는 `가정`이 있다.
- 모든 숫자에 `가정값` 또는 `확인값` 표시가 있다.
- `bm/redteam_log.md`의 결정 칸 빈칸이 0개다.
- 결정 칸의 값은 `수용`, `수정`, `반려` 중 하나만 쓴다. 다른 표기(`반영`, `보류`, `반박`)는 쓰지 않는다.

## 5. 경로 기준

- 모든 경로는 이 폴더(`D13 BM설계`)를 기준으로 한다.
- 캔버스와 검증 산출물은 `bm/` 아래에 둔다.
