## 1. 목적

### 1.1 서비스 목적 (한 문장)
서문시장 야시장에 처음 가는 구매자가 줄을 서기 전에 매대의 영업 여부, 결제 수단, 품절 메뉴를 알 수 있게 한다. (근거: painpoint_def P1·P2·P3)

### 1.2 목적별 정리

| 관점 | 목적 | 근거 |
|---|---|---|
| 방문객 | 헛걸음, 결제 수단 때문에 줄을 다시 서는 일, 품절 허탕을 줄인다 | journey_map · jtbd J1–J6 |
| 상인 | 장사 전 한 번 입력으로 정보를 알리고, 품절은 직접 표시한다 | bm 7 · D-01 · D-04 |
| 상인회 사무국 | 운영 공지를 제공하고 정보 제공 동의를 관리하며, 틀린 정보를 처리한다 | bm 4 · bm 8 · D-03 · D-07 |
| 사업 (가정) | 상인회가 매대 1곳당 월 단위로 비용을 낸다. 금액 범위 5천~1만 원은 가정값이다. | bm 5 · ideas_top3 "돈" (확인 필요: 상인회 예산) |

### 1.3 목적 밖 (이 명세에서 하지 않는 것)
- 관광 안내나 맛집 추천 챗봇 (bm 캔버스의 대상 아님)
- 주문·결제 대행, 대기 시간 예측, 실시간 재고 (2위·3위 아이디어 범위)

## 2. 배경

- **문제 (근거)**: 결제 수단 정보 없음(P1, 점수 60), 운영 정보 불일치(P2, 36), 품절·대기 정보 없음(P3, 32). journey_map에서 주문·결제 단계 감정이 가장 낮다(-2).
- **해결 방향 (제안)**: 상인이 올린 정보로 매대 정보 카드를 한 화면에 보여 준다. AI는 입력 재료에서 카드 초안을 만들고, 게시는 상인이 확인한 뒤에 한다.
- **차별점 (근거)**: 자료 내에서 "정보 제공 확인 + 게시 전 확인" 구조는 ideas_top3 1위 기준. 다른 지역 사례 비교는 이 명세에 없음.

## 6. 스토리

> 형식: ~로서, ~하고 싶다, ~하기 위해. 인수조건은 "~할 때, 시스템에서는 ~한다". 장면별 상세와 As-Is 근거는 spec/시나리오.md.

### US1 · 영업 여부 확인 · 필수
- **스토리**: 대구 직장인 구매자로서, 야시장에 가기 전에 오늘 영업 여부와 개장 시간을 한 곳에서 보고 싶다. 헛걸음하지 않기 위해.
- **인수조건**
  1. 매대판을 열 때, 시스템에서는 오늘 날짜 기준 영업 여부와 개장 시간을 카드마다 보여 준다.
  2. 상인이 영업 정보를 올리지 않았을 때, 시스템에서는 "정보 없음"으로 표시하고 영업 여부를 추정하지 않는다.
  3. 카드를 표시할 때, 시스템에서는 "AI 정리 · 상인 입력 hh:mm 기준"을 함께 보여 준다.
- **예외**: 정보 없음 → "정보 없음" / 오늘 안 나옴 → "오늘 영업 안 함", 휴장이 가장 먼저 보인다 (D-05) / 휴장 사유 표시 방식은 **확인 필요**.

### US2 · 결제 수단 확인 · 필수
- **스토리**: 현금 없이 처음 온 구매자로서, 줄 서기 전에 매대마다 받는 결제 수단을 알고 싶다. 줄을 다시 서거나 구매를 포기하지 않기 위해.
- **인수조건**
  1. 매대 카드를 열 때, 시스템에서는 상인이 입력한 결제 수단(현금, 카드, 계좌이체)을 목록으로 보여 준다. (D-08)
  2. 결제 수단이 현금만일 때, 시스템에서는 "현금 필요"를 줄 서기 전 화면에 먼저 표시한다.
  3. 결제 수단을 입력하지 않았을 때, 시스템에서는 "정보 없음"을 표시하고 현금 가능 여부를 추정하지 않는다. 방문객은 줄을 설 수 있다. (D-06)
- **예외**: 정보 없음 / 휴장이면 "오늘 영업 안 함"이 먼저 (D-05) / 품절이면 US3와 함께 표시 / 정보 불일치는 정보를 올린 상인이 책임 (D-02, 법적 검토 **확인 필요**).

### US3 · 품절 확인 · 필수
- **스토리**: 먹고 싶은 메뉴를 정해 온 구매자로서, 그날 품절 메뉴를 도착 전에 알고 싶다. 두 번 허탕 치지 않기 위해.
- **인수조건**
  1. 상인이 메뉴를 품절로 표시할 때, 시스템에서는 해당 메뉴 옆에 "품절"을 표시한다.
  2. 상인이 품절 정보를 입력하지 않은 메뉴일 때, 시스템에서는 품절 여부를 추정하지 않고 "정보 없음"을 표시한다.
  3. 상인이 품절을 해제할 때, 시스템에서는 "품절"을 지우고 해제 시각을 보여 준다. (D-04 · 해제 시각 표시 방식은 **확인 필요**)
- **예외**: 정보 없음 / 휴장이면 "오늘 영업 안 함"이 먼저 (D-05).

### US4 · 틀린 정보 신고 · 나중
- **스토리**: 틀린 정보를 본 구매자로서, 신고해서 고치고 싶다. 다음 방문객이 같은 헛걸음을 하지 않기 위해.
- **인수조건**
  1. 틀린 정보를 신고할 때, 시스템에서는 신고 내용과 시각을 상인회 사무국에 전달한다. (D-07 · 접수 채널은 **확인 필요**)
  2. 신고가 접수되었을 때, 시스템에서는 해당 카드에 "확인 중"을 표시한다.
  3. 사무국이 정정했을 때, 시스템에서는 정정 시각을 카드에 표시한다.
- **예외**: 정보 없음 → 사유를 기록 / 휴장일 신고 → 다음 영업일 처리 (**확인 필요**).

### 공통 — 상인 입력·AI 카드 초안·게시·가림 · 필수
- **인수조건**
  1. 상인이 사진과 한마디를 올릴 때, 시스템에서는 결제 수단, 영업 여부, 품절 메뉴를 추출해 카드 초안을 만든다. 입력에 없는 항목은 "정보 없음"으로 둔다.
  2. 카드 초안을 만들 때, 시스템에서는 손님 얼굴과 계좌번호를 자동으로 가린다. (D-09)
  3. 상인이 미리보기에서 '맞음'을 누를 때, 시스템에서는 카드를 게시한다. 확인하지 않으면 게시하지 않는다. (D-01)
- **예외**: 추출 실패 → 초안을 만들지 않고 상인에게 알림 (처리 방식은 **확인 필요**).

## 8. 비기능 · 제약

- **형식 (근거)**: 모바일 웹. 채널은 가정이며 QR 안내판과 상인회 공지 링크로 본다 (bm 3).
- **개인정보**: 게시 전 손님 얼굴과 계좌번호를 가린다 (D-09). 사진 원본 보관 기간은 **확인 필요** (O-07).
- **데이터 출처 표시**: 카드마다 AI 정리 여부와 입력 시각을 표시한다 (F-11).
- **추정 금지**: 입력이 없는 값은 추정하지 않고 "정보 없음"으로 표시한다. 영업 여부, 결제 수단, 품절 모두 적용. (제안: 설계 규칙)
- **가독성 (제안)**: 본문 글자는 16px 이상, 모바일 한 화면에서 가로 스크롤 없이 표시.
- **시범 범위**: 첫 시범은 매대 10곳 (D-10).

## 9. 검증 기준

### 9.1 검증 질문 (가설)
- **H1**: 줄 서기 전에 결제 수단을 알면, 현금 없이 방문한 구매자가 구매를 포기하거나 줄을 다시 서는 일이 줄어든다. (근거: P1 · journey_map 5단계)
- **H2**: 상인은 입력과 확인을 한 번에 마칠 수 있다. (제안: 한 매대 기준 5분 이내)
- **H3**: 카드의 영업·결제·품절 정보가 현장과 맞다. (제안: 일치율 90% 이상)

## 12. 화면 구성 · 디자인 시스템

> 목표: 야시장의 저녁 분위기처럼 따뜻하고 경쾌한 화면. 정보는 한눈에, 색은 기분 좋게. 색만으로 상태를 전달하지 않는다.
> 표기: **(제안)** = 이 명세가 정한 값, 팀 확정 필요 · **확인 필요** = 실제 기기·시범에서 검증해야 함

### 12.1 디자인 원칙 (제안)
1. **따뜻하게, 그러나 정확하게**: 밝고 따뜻한 색을 쓰되, 영업·결제·품절 정보는 색 + 글자 + 아이콘을 함께 쓴다.
2. **저녁 빛**: 등불(랜턴)과 야시장 간판의 따뜻한 톤을 배경과 강조색으로 쓴다.
3. **한 화면, 한 판단**: 카드 하나에서 영업·결제·품절 판단이 끝나야 한다 (줄 서기 전 판단, US1–US3).
4. **장식은 절제**: 샤방함은 배경의 옅은 빛과 강조색 포인트로 낸다. 움직임과 그림자는 최소로 한다.

### 12.3 글자 (제안)
- 서체: 한글 기본 서체는 기기 기본 고딕을 쓴다 (Apple SD 산돌고딕, 맑은 고딕, Noto Sans KR 순서). 별도 웹폰트는 **확인 필요** (용량·라이선스).
- 크기 단계: 제목 24px / 소제목 20px / 매대명 18px / 본문 16px / 보조 14px / 최소 13px.
- 굵기: 제목과 매대명 700, 본문 400, 배지 600.
- 줄 간격: 본문 1.6, 제목 1.3.

### 12.4 간격 · 모양 · 그림자 (제안)
- 간격 단위: 4px 배수 (4 · 8 · 12 · 16 · 24 · 32). 화면 좌우 여백 16px.
- 모서리: 카드 16px, 칩과 배지 999px(알약), 입력창 12px.
- 그림자: `0 4px 12px rgba(43, 35, 48, 0.08)` 한 가지만 쓴다.
- 터치 영역: 버튼과 칩은 최소 44×44px.

### 12.5 아이콘 · 이미지 (제안)
- 선형 아이콘 한 세트만 쓴다 (예: Lucide). 이모지는 쓰지 않는다. 상태는 배지 글자로 먼저 말한다.
- 음식 사진은 카드 상단에 4:3 비율로 둔다. 사진이 없으면 등불 모양 기본 이미지를 쓴다 (사진 없음 = 정보 없음이 아님, 표시 구분).
- 배경 장식: 헤더에만 등불 점 패턴을 6% 불투명도로 깐다. 본문 영역에는 장식을 두지 않는다.

### 12.6 움직임 (제안)
- 전환은 150~200ms의 투명도 변화만 쓴다. 카드 목록 자동 갱신 시 깜빡임을 피한다.
- 기기 설정의 "동작 줄이기"를 켜면 모든 움직임을 끈다.

### 12.7 공통 컴포넌트 (제안)

| 컴포넌트 | 구성 | 상태 규칙 |
|---|---|---|
| 상태 배지 | 아이콘 + 글자 + 배경색 | 영업중 / 오픈 전 · 시각 / 마감 / 오늘 영업 안 함 / 정보 없음 |
| 결제 칩 | 현금 · 카드 · 계좌이체 | 받는 수단은 진한 색 + ✓ 표시 글자, 안 받는 수단은 옅은 색 + "안 받음" 글자. 입력 없음이면 "정보 없음" 칩 1개 |
| 품절 메뉴 | 메뉴명 취소선 + "품절" 배지 | 취소선만으로 전달하지 않는다 (배지 함께) |
| 요약 타일 | 숫자 + 짧은 이름 3개 | 영업중 · 오픈 전 · 전체 |
| 검색창 · 카테고리 칩 | 둥근 검색창 + 가로 스크롤 칩 | 선택된 칩은 주조색 배경 + 흰 글자 |
| 업데이트 표시 | "상인 입력 hh:mm 기준 · AI 정리" | 카드 하단 고정 (F-11) |
| 신고 링크 | "정보가 틀렸나요?" 글자 링크 | 나중 기능 (F-14), 1차 출시에서는 숨김 |

### 12.8 화면 구성 (제안)

**(1) 방문객 · 매대판 목록** — 기본 화면
- 헤더 (등불 패턴): 야시장 이름, 오늘 날짜와 기준 시각, 요약 타일 3개 (영업중 · 오픈 전 · 전체).
- 검색창과 카테고리 칩 (전체 · 먹거리 · 간식 · 음료 · 소품 — 분류는 **확인 필요**).
- 카드 목록: 정렬은 영업중 → 오픈 전 → 마감 순 (제안). 카드 구성:
  - 상단: 매대 번호 · 상태 배지
  - 사진 (4:3, 없으면 기본 이미지)
  - 매대명 (18px 굵게), 대표 메뉴 2개 (품절은 취소선 + 배지)
  - 결제 칩 한 줄
  - 하단: 운영 시간 · 업데이트 시각 · 신고 링크(나중)
- 카드 탭 시 상세 화면으로 이동.

**(2) 방문객 · 매대 상세** (보조)
- 전체 메뉴와 가격 (가격은 상인 입력 기준, 없으면 "정보 없음"), 결제 수단 목록, 품절 목록, 운영 시간, 업데이트 시각.
- 하단 고정 버튼: "이 매대 줄 서기 전 확인 완료" 같은 버튼은 두지 않는다 (판단은 방문객이 한다).

**(3) 상인 · 장사 전 입력** (상인 화면)
- 영업 시작·종료 시각 입력 (큰 입력창 2개), 휴장 토글.
- 메뉴별 품절 스위치 (해제는 상인이 직접, D-04).
- 결제 수단 체크 3개 (현금 · 카드 · 계좌이체, D-08).
- 사진 업로드 + 한마디 입력 (음성 또는 글).
- "AI 카드 만들기" → 미리보기 (가림 처리 결과 표시, 손님 얼굴·계좌번호는 가림 표시로 보임).
- 하단 고정: "맞음 · 게시하기" 주조색 버튼 (D-01).

**(4) 상인 · 가입 동의** (상인 온보딩)
- 이용 약관 전문 링크 + 동의 체크 (D-03). 필수 동의는 체크해야 다음 단계로 간다.

**(5) 신고 · 나중** (방문객 신고 시트)
- 틀린 항목 선택(영업 · 결제 · 품절 · 기타) + 짧은 설명. 제출 후 카드에 "확인 중" 배지 (US4).

**(6) 사무국 · 신고 목록** (나중, 보조)
- 신고 목록: 매대별 신고 내용, 상태(접수 · 확인 중 · 정정 완료), 정정 시각 입력.

### 12.9 접근성 (제안)
- 색만으로 상태를 전달하지 않는다. 모든 배지는 글자를 함께 쓴다.
- 글자 크기 조절에 레이아웃이 깨지지 않게 한다 (카드 높이 자동).
- 스크린리더: 카드는 "매대명, 상태, 결제 수단, 메뉴" 순서로 읽힌다.
- 한 손 조작을 기준으로 주요 버튼은 화면 하단에 둔다.

### 12.10 확인 필요
- 실제 대비 측정값 (12.2) · 웹폰트 사용 여부 (12.3)
- 카테고리 분류 (12.8 · 1)
- 사진 없는 매대 기본 이미지 디자인 (12.5)
- 상인 화면 사용 기기(휴대폰 기준 여부) · 야간 다크 모드 기본값
