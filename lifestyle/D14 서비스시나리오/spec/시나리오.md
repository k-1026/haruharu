# 시나리오 명세 — 야시장 오늘의 매대판 (수업 예시 · 가상 데이터)

> 갱신: 2026-11-12 · 결정 D-01 ~ D-10 반영 (spec/decision_log.md). 전체 명세는 spec/spec.md.

## 0. 전제

- **상황**: 대구 직장인 남성 구매자 1명. 금요일 저녁, 현금 없이 **처음** 서문시장 야시장에 간다. 여러 매대 음식을 사려고 한다.
- **근거 문서**: painpoint/journey_map.md · painpoint/painpoint_def.md · ax/jtbd.md · ax/ideas_top3.md · bm/bm_canvas.md
- **범위**: 1위 아이디어 "야시장 오늘의 매대판"만 다룬다. 2위(운영 정보 대조 알림)와 3위(대기·품절 미리 보기)는 이 명세에 넣지 않는다.
- **표기 규칙**
  - 자료에 없는 사실은 쓰지 않는다. 자료가 비어 있는 부분은 **확인 필요**로 표시한다.
  - 우선순위: **필수** = 이번 MVP에 있어야 함 / **나중** = MVP 뒤에 다룸.
  - 결정 사항은 **(D-xx)**로 표시한다.
- **가정의 출처**: 금요일 저녁, 직장인이라는 설정은 이 명세의 가정이다. 야시장이 금요일에 여는지는 자료에 없어서 **확인 필요**다.

## 2. As-Is 장면 상세 (금요일 저녁, 현금 없음, 처음 방문)

- **AS1 알아보기**: 퇴근 후 검색창에 "서문시장 야시장 오늘"을 입력한다. 결과마다 개장 시간이 6시, 7시, 7시 반으로 다르다(journey_map r_170). 확인하려고 전화를 걸까 고민하다가 그냥 나간다(r_190).
- **AS2 도착**: 시장에 도착했는데 임시 휴장이다. SNS에는 정상 운영이라고 적혀 있었다(r_005). 헛걸음을 한다.
- **AS3 둘러보기**: 매대를 돌면서 먹을 것을 고른다. 가고 싶던 매대가 그날 나오지 않았다(r_097). 또 어떤 매대는 품절이었는데 재고가 언제 떨어지는지 알려 주지 않는다(r_080).
- **AS4 주문·결제**: 고른 매대 앞에 줄을 선다. 차례가 와서 보니 계좌이체만 된다. 현금이 없어서 줄을 다시 서거나 못 사고 돌아간다(r_028, r_050). 결제 수단을 줄 서기 전에 알 방법이 없었다.

## 3. To-Be 장면 상세

- **TB1 알아보기**: 매대판 링크를 열면 오늘 영업 여부와 개장 시간이 보인다. (상인이 장사 시작 전에 올린 정보 기준)
- **TB2 도착 전 확인**: 가려는 매대의 영업 여부와 결제 수단을 카드에서 확인한다. 정보가 없으면 "정보 없음"이 표시된다.
- **TB3 줄 서기 전 결제 확인**: 매대 카드에서 "현금 · 카드 · 계좌이체" 중 받는 수단을 확인하고, 현금 없이 살 수 있는 매대를 고른다. (D-08)
- **TB4 품절 확인**: 카드에서 오늘 품절 메뉴를 본다. 상인이 올린 정보 기준이며, 실시간 재고가 아니다. 품절은 상인이 직접 해제한다. (D-04)

## 4. 스토리 (바뀌는 장면마다 1개)

> 형식: ~로서, ~하고 싶다, ~하기 위해.
> 인수조건: "~할 때, 시스템에서는 ~한다" 2~4개.
> 예외조건: 정보 없음 / 오늘 안 나옴 / 품절 중 하나 이상.
> 카드 표시 우선순위: **휴장 > 품절 > 결제** (D-05)

### US1 · 장면 S1 → TB1 · 알아보기 · **필수**

- **스토리**: 대구 직장인 구매자로서, 야시장에 가기 전에 오늘 영업 여부와 개장 시간을 한 곳에서 보고 싶다. 헛걸음하지 않기 위해.
- **인수조건**
  1. 매대판을 열 때, 시스템에서는 오늘 날짜 기준 영업 여부와 개장 시간을 카드마다 보여 준다.
  2. 상인이 영업 정보를 올리지 않은 날일 때, 시스템에서는 "정보 없음"이라고 표시하고 영업 여부를 추정하지 않는다.
  3. 카드에 "AI 정리 · 상인 입력 hh:mm 기준"을 표시할 때, 시스템에서는 정보가 올라온 시각을 함께 보여 준다.
- **예외조건**
  - 정보 없음: 상인이 그날 영업 정보를 올리지 않았다 → "정보 없음" 표시.
  - 오늘 안 나옴: 매대가 그날 휴장이다 → "오늘 영업 안 함"으로 표시 (휴장이 가장 먼저 보임, D-05). 휴장 사유 표시 방식은 **확인 필요**.
  - 품절: 이 스토리 범위 밖, US3에서 다룬다.

### US2 · 장면 S4 → TB3 · 줄 서기 전 결제 수단 확인 · **필수**

- **스토리**: 현금 없이 처음 온 구매자로서, 줄을 서기 전에 매대마다 어떤 결제 수단을 받는지 알고 싶다. 줄을 다시 서거나 구매를 포기하지 않기 위해.
- **인수조건**
  1. 매대 카드를 열 때, 시스템에서는 상인이 입력한 결제 수단(현금, 카드, 계좌이체)을 목록으로 보여 준다. (D-08)
  2. 결제 수단이 "현금만"인 매대를 고를 때, 시스템에서는 "현금 필요"를 줄 서기 전 화면에 먼저 표시한다.
  3. 상인이 결제 수단을 입력하지 않은 매대일 때, 시스템에서는 "정보 없음"을 표시하고 현금 가능 여부를 추정하지 않는다. 방문객은 이 매대에 줄을 설 수 있다. (D-06)
- **예외조건**
  - 정보 없음: 결제 수단 입력이 없다 → "결제 수단 정보 없음" + 줄 서기 가능 안내.
  - 오늘 안 나옴: 휴장이면 결제 수단 정보와 관계없이 "오늘 영업 안 함"이 먼저 표시된다 (D-05).
  - 품절: 결제 수단은 맞는데 메뉴가 품절이면 결제 수단과 별도로 "품절"이 표시된다 (US3). 품절이 결제보다 먼저 보인다 (D-05).
  - 정보 불일치: 줄을 선 뒤 결제 수단이 다르면 정보를 올린 상인이 책임진다 (D-02). 법적 책임 검토는 **확인 필요**.

### US3 · 장면 S3 → TB4 · 품절 메뉴 확인 · **필수**

- **스토리**: 먹고 싶은 메뉴를 정해 온 구매자로서, 그날 품절된 메뉴를 도착 전에 알고 싶다. 두 번 허탕 치지 않기 위해.
- **인수조건**
  1. 매대 카드를 열 때, 시스템에서는 상인이 올린 품절 메뉴를 메뉴 옆에 "품절"로 표시한다.
  2. 상인이 품절 정보를 올리지 않은 메뉴일 때, 시스템에서는 품절 여부를 추정하지 않고 "정보 없음"을 표시한다.
  3. 상인이 품절을 직접 해제할 때, 시스템에서는 "품절"을 지우고 해제 시각을 함께 보여 준다. (해제는 상인이 직접 함, D-04 · 해제 시각 표시 방식은 **확인 필요**)
- **예외조건**
  - 정보 없음: 메뉴별 품절 입력이 없다 → "정보 없음".
  - 오늘 안 나옴: 매대 전체가 휴장이면 "오늘 영업 안 함"이 먼저 표시된다 (D-05).
  - 품절 중: 주문하려던 메뉴가 품절이면 같은 매대의 다른 메뉴 목록을 보여 준다 (화면 구성은 **확인 필요**).

### US4 · 잘못된 정보 신고 · **나중**

- **스토리**: 매대판에서 틀린 정보를 본 구매자로서, 신고해서 고치고 싶다. 다음 방문객이 같은 헛걸음을 하지 않기 위해.
- **인수조건**
  1. 틀린 정보를 신고할 때, 시스템에서는 신고 내용과 시각을 상인회 사무국에 전달한다. 접수와 처리는 사무국이 맡는다. (D-07 · 접수 채널은 **확인 필요**)
  2. 신고가 접수됐을 때, 시스템에서는 해당 카드에 "확인 중"을 표시한다.
  3. 사무국이 정정했을 때, 시스템에서는 정정 시각을 카드에 표시한다.
- **예외조건**
  - 정보 없음: 신고 대상 카드에 정보가 없다 → 신고는 받되 "정보 없음"을 신고 사유로 기록.
  - 오늘 안 나옴: 신고한 날 휴장이면 처리는 다음 영업일로 넘긴다 (**확인 필요**).
  - 품절: 품절 정보 신고는 US3의 품절 표시를 기준으로 처리한다.
