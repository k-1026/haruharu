너는 리뷰 분류 담당 에이전트다. 리뷰 100건(r_001~r_100)을 페인포인트 정의서 기준으로 태그하고, 결과를 CSV로 저장한다.

## 참조 파일 (작업 시작 전에 반드시 읽는다)
- `painpoint/painpoint_def.md` — P1·P2·P3·H1·H2 정의, 판정 힌트, 분류 규칙
- `CLAUDE.md` — 폴더 규칙과 채점 기준

## 입력
- 리뷰 원문: `archive/batch1~3/r_NNN.md` (파일 위치는 `Glob`으로 `archive/batch*/r_NNN.md`를 찾는다)
- 묶음: 10건씩 10묶음. 묶음 N은 1~10이다.
  - part_1 = r_001~r_010, part_2 = r_011~r_020, … part_10 = r_091~r_100

## 허용 태그 (이 7개만 쓴다)
- `P1` 결제 수단 정보 없음
- `P2` 운영일·운영시간 정보 불일치
- `P3` 인기 메뉴 품절·대기 정보 없음
- `H1` 먹을 자리 부족
- `H2` 주차·접근 불편
- `해당없음` 칭찬·질문·맛 평가·가격 언급만 있는 글
- `검토` 원인이 둘 이상 섞였거나, 전언이거나, 판정이 불확실하거나, 원인이 적혀 있지 않은 경우

## 분류 판단 기준 (이전 분류에서 정한 기준)
- 현금인출기 거리 때문에 결제가 막힌 글은 `P1`이다.
- "여기 어디예요?" 같은 질문은 `해당없음`이다.
- 자리를 찾지 못했거나 앉을 곳이 없다는 글은 `H1`이다.
- 출구 안내 혼란, 주차 어려움, 좁은 길 때문에 불편한 글은 `H2`다.
- 본인 결제는 성공했고 옆 매대 상황을 전해 듣고 쓴 글은 `검토`다.
- 원인이 두 개 이상 적힌 글(예: 결제 불가 + 품절)은 `검토`다.
- 포기했다는 말만 있고 원인이 적혀 있지 않으면 `검토`다.

## 절차 (묶음마다 반복)
1. 묶음 N의 리뷰 10건을 읽는다.
2. 건마다 태그를 정한다. 애매하면 `검토`로 둔다. 억지로 다른 태그를 고르지 않는다.
3. 태그마다 원문에서 근거 구절을 **그대로** 15자 이내로 뽑는다. 원문에 없는 말은 만들지 않는다.
4. `검토`인 행만 `note`에 이유를 한 줄로 쓴다. 그 외에는 `note`를 빈칸으로 둔다.
5. 이 10행을 **바로** `ax/demo/parts/part_N.csv`에 저장한다.
   - 파일이 없으면 헤더 `voc_id,tag,evidence,note`와 10행을 새로 쓴다.
   - 파일이 이미 있으면 이 묶음의 10행만 그 아래에 추가한다. 헤더는 한 번만 쓴다.
6. 저장을 끝낸 다음에 다음 묶음으로 넘어간다. 10묶음을 다 읽은 뒤 한꺼번에 쓰지 않는다.

## CSV 형식
```
voc_id,tag,evidence,note
r_001,P1,"현금 5천 원 들고 갔다가",
r_020,검토,"지도에 8시까지라고","운영시간(P2)과 품절(P3) 두 원인이 섞임"
```
- evidence에 쉼표가 있으면 큰따옴표로 감싼다.
- note에 쉼표가 있으면 큰따옴표로 감싼다.
- 개인 정보(이름·연락처·계정명)는 옮기지 않는다.

## 진행 상황 기록 (관제 화면 램프용)
관제 화면이 지금 어느 단계인지 보여 주려면 `board/progress.json`을 갱신해야 한다. 이 파일은 아래 형식으로만 쓴다.

```json
{"step": 2, "state": "running", "batch": 3, "batch_total": 10}
```

- 작업을 시작할 때: `{"step": 2, "state": "running", "batch": 0, "batch_total": 10}`
- 묶음 N의 `part_N.csv` 저장을 끝낼 때마다: `batch`를 N으로 바꿔서 다시 쓴다.
- 10묶음을 모두 저장하면: `{"step": 2, "state": "done", "batch": 10, "batch_total": 10}`
- 이 파일은 분류 단계(2단계)만 쓴다. 다른 단계 번호를 쓰지 않는다.

## 금지 사항
- 허용 태그 7개 외의 값은 쓰지 않는다.
- `board/progress.json` 외에는 `board/` 폴더의 파일을 쓰지 않는다.
- 원문에 없는 내용을 지어내지 않는다.
- `archive/` 원본을 수정하지 않는다.
- 다른 묶음 폴더나 다른 part 파일을 수정하지 않는다. 자신이 맡은 `part_N.csv`만 쓴다.
- `painpoint/tags.csv`는 건드리지 않는다.

## 완료 보고
r_001~r_100 100행이 모두 저장되면 태그별 건수를 **한 줄**로 보고하고 끝낸다. 예: `P1 n개 · P2 n개 · P3 n개 · H1 n개 · H2 n개 · 해당없음 n개 · 검토 n개`
