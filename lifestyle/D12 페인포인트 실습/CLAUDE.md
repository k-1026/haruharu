# D12 페인포인트 실습 — 작업 규칙

이 폴더는 VOC(고객 목소리) 300건을 페인포인트 정의서(`painpoint/painpoint_def.md`) 기준으로 분류하는 실습 작업 공간이다.
상위 규칙은 `haruharu/CLAUDE.md`(팀 규칙)를 따르며, 이 파일은 이 폴더에만 적용되는 추가 규칙이다.

## 1. 폴더 구조

| 경로 | 용도 | 수정 |
|---|---|---|
| `archive/batch1~3/r_NNN.md` | 원본 VOC (블로그 · 지도앱 리뷰 · 영상 댓글) | 금지 |
| `archive/metadata.csv` | VOC 목록 (voc_id · source · date · file) | 금지 |
| `painpoint/painpoint_def.md` | 페인포인트 정의서 · 분류 규칙 · 판정 힌트 | 팀과 합의 후에만 |
| `painpoint/tags.csv` | 분류 결과 (AI 초안 + 검토 상태) | 분류 작업 시 갱신 |
| `.claude/agents/review-tagger.md` | 분류 담당 에이전트 (r_001~r_100을 10건씩 읽고 `ax/demo/parts/part_N.csv`에 즉시 저장) | 필요 시 |
| `.claude/agents/review-grader.md` | 채점 담당 에이전트 (part 파일 검사 · 점수표 보고, 수정하지 않음) | 필요 시 |
| `ax/demo/parts/part_1~10.csv` | 분류 결과 묶음 (헤더 `voc_id,tag,evidence,note`, 묶음당 10행) | 분류 에이전트만 씀 |

- `archive/`의 원본 파일은 내용을 고치지 않는다. 파일명 변경도 하지 않는다.
- 새 폴더 체계를 임의로 만들지 않는다. 위치가 불명확하면 먼저 제안한다.

## 2. 분류 원칙

- 판정 기준은 항상 `painpoint/painpoint_def.md`를 따른다. 기준을 임의로 바꾸지 않는다.
- 허용 태그: `P1` · `P2` · `P3` · `H1` · `H2` · `해당없음` · `검토` 중에서만 고른다.
- 칭찬 · 질문 · 맛 평가 · 가격 언급만 있는 글은 `해당없음`.
- 원인이 둘 이상 섞여 한 태그로 정하기 어렵거나, 본인 경험이 아닌 전언이거나, 판정이 불확실하면 `검토`로 두고 이유를 적는다.
- 태그마다 원문에서 근거 구절을 **그대로** 인용한다 (15자 이내). 원문에 없는 문장을 만들지 않는다.

## 3. 분류 결과 기록 (`painpoint/tags.csv`)

열: `voc_id,tag,evidence,note,review_status`

- `review_status`: 처음에는 모두 `AI초안`. 사람이 확인하기 전에는 `검토완료`로 바꾸지 않는다.
- `note`: `검토` 태그일 때 이유, 그 밖에는 비워 둘 수 있다.
- 한 VOC 행은 한 번만 쓴다. 다시 분류하면 같은 행을 갱신한다.

## 4. 작업 방식

- 대량 분류(여러 batch)는 `review-tagger` 서브에이전트에게 맡길 수 있다. 결과는 위 형식으로 받아 `tags.csv`에 합친다.
- 집계(태그별 건수, 빈도 · 점수 계산)는 `painpoint_def.md`의 점수 공식(빈도 × 강도 × 해결 가능성)대로 계산하고, 계산식을 함께 남긴다.
- 수치 주장에는 기준 범위(batch, 기간, 태그 기준)를 적는다.
- 관제 화면의 진행 램프는 `board/progress.json`으로 움직인다. 분류 에이전트는 2단계, 채점 에이전트는 4단계 상태만 이 파일에 기록한다 (형식: `{"step", "state", "batch", "batch_total"}`).

## 5. 채점 기준 (VOC 읽기 · 태그 검증)

VOC를 읽고 `tags.csv`에 쓸 때 아래 세 묶음을 모두 확인한다. 세 묶음 모두 80점 이상이어야 통과다. 한 묶음이라도 80점 미만이면 **재작업**으로 판정한다.

### 5-1. 채점 묶음 한눈에 보기

| 묶음 | 항목 | 통과 기준 | 확인 방법 | 담당 |
|---|---|---|---|---|
| ① 범위 점수 | voc_id 누락 · 중복 | 누락 0건, 중복 0건 (r_001~r_100 전부) | `ax/demo/parts/part_1~10.csv`의 id를 r_001~r_100과 대조 | 채점관 |
| ② 근거 판정 | 원문 인용 근거 유무 | 모든 행에 `evidence` 값이 있고, 원문에 그대로 존재 | 인용 구절을 `archive/batch*/r_NNN.md`에서 찾기 | 채점관 |
| ③ 형식 점수 | 허용 태그 7개 준수 | 모든 `tag`가 `P1` · `P2` · `P3` · `H1` · `H2` · `해당없음` · `검토` 중 하나 | 태그 값 목록 검사 | 채점관 |

### 5-2. 검토 태그 기준

| 항목 | 기준 |
|---|---|
| 검토 비율 | 전체 100건 중 `검토` 5% 이하 (5건 이하) |
| 검토 이유 | `검토` 행마다 `note`에 이유가 적혀 있어야 함 (빈칸 0건) |
| 관제 화면 | 검토 건수와 비율을 관제 화면에 표시 |

### 5-3. 관제 화면 요구사항

| 요소 | 내용 |
|---|---|
| 검토 숫자 | `검토` 건수 · 전체 대비 비율을 표시 |
| 채점 패널 | 묶음 ①·②·③ 점수와 통과(80점 이상) 여부를 표시 |

### 5-4. 분류 · 채점 흐름 (에이전트)

| 단계 | 담당 | 내용 |
|---|---|---|
| 분류 | review-tagger | r_001~r_100을 10건씩 읽고, 묶음마다 즉시 `ax/demo/parts/part_N.csv`에 10행 저장 (한꺼번에 쓰지 않음) |
| 완료 보고 | review-tagger | 100행 저장 후 태그별 건수를 한 줄로 보고 |
| 채점 | review-grader | part 파일 검사 후 ①②③ 점수와 검토 비율을 점수표로 보고 (수정하지 않음) |

- 채점 점수 방식(묶음별 감점 기준)은 `review-grader.md`에 적혀 있다.
- 기존 `painpoint/tags.csv`(300건 분류)는 참고용으로 남긴다.

### 5-5. 최종 승인 기준

| 항목 | 기준 |
|---|---|
| 사람 대조 | 사람이 임의로 고른 10건을 대조 |
| 동의율 | 10건 중 9건 이상 AI 태그에 동의 |
| 승인 주체 | 최종 승인은 **사용자가 직접** 한다. AI는 `review_status`를 `검토완료`로 바꾸지 않는다. |

## 6. 금지 사항

- 원본 VOC를 수정 · 삭제하지 않는다.
- 작성자 개인 정보(이름 · 연락처 · 계정명)를 결과 파일에 옮기지 않는다.
- 실존 업체 · 매장을 비난하는 판정 문구를 만들지 않는다. 결과는 "고객 여정의 막힌 지점"으로만 기술한다.
- 커밋 · push는 사용자가 요청할 때만 한다. 팀 규칙(`haruharu/CLAUDE.md` 6번)에 따라 개인 브랜치에서 작업한다.
