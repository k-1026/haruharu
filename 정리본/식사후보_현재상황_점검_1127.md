# 식사 후보 묶음 — 현재 동작과 확인 결과 (2026-11-27)

## 한 줄 결론

지금의 **후보 묶음 저장**은 공통 코스의 장소·시간·동선을 바꾸는 기능이 아니라, 관광객이 나중에 고를 수 있는 식당 목록만 새 코스 버전에 기록하는 기능이다. 따라서 저장 후 일정표가 크게 달라지지 않는 것은 현재 설계대로지만, **저장 결과가 눈에 띄지 않고 지도 핀·실제 QR 화면까지 이어지지 않는 문제**는 남아 있다.

## 1. 사용자가 기대한 것과 현재 구현의 차이

| 항목 | 사용자가 자연스럽게 기대하는 동작 | 현재 구현 |
|---|---|---|
| 후보 묶음 저장 | 저장 뒤 후보가 지도·일정·관광객 화면에서 바로 달라짐 | 새 버전에 후보 목록만 저장하고 공통 일정은 그대로 유지 |
| 지도 | 저장한 후보가 식당 핀으로 뚜렷하게 보임 | 저장 후보만 핀으로 보이도록 코드가 있으나, 실제 화면에서 핀이 보였다는 확인은 아직 없음 |
| QR 랜딩 | 홍보물 QR로 들어간 관광객이 후보 중 하나를 선택 | 직원 화면의 **시연용 미리보기**만 있음. 실제 QR 랜딩의 식사 선택 연결은 아직 미완료 |
| 점심 | 후보를 안 고르면 자유롭게 해결 가능 | 시간 블록만 남기고 후보 저장은 선택 사항 |
| 저녁 | 여러 후보 중 관광객이 선택 | 2곳 이상 저장해야 하며, 그중 치킨 후보 1곳 이상이 필요 |

## 2. 저장 버튼을 누르면 실제로 바뀌는 것

1. 선택한 식당 후보를 운영·이동 정보와 다시 비교한다.
2. 조건을 통과하면 코스의 **새 버전**을 만든다.
3. 해당 식사 칸에 `추천후보`, `후보묶음(관광객 선택)`을 기록한다.
4. 공통 코스의 방문 장소, 시간, 순서, 다른 일정은 바꾸지 않는다.
5. 저장 직후 직원 화면은 최신 버전을 다시 열고, “후보 묶음을 저장했습니다”라는 안내를 보여 준다.

즉, 후보 묶음은 “식당을 코스에 확정해 넣기”가 아니라 “관광객에게 보여 줄 선택지 만들기”다. 그래서 저장 전후에 관광 동선이 같아 보이는 것이 정상이다.

## 3. 현재 화면에서 확인된 것

- 점심 칸에는 `점심 시간 블록`과 선택 사항인 후보 영역이 보인다. 저장한 후보가 있으면 후보 수와 이름을 표시한다.
- 저녁 칸에는 `관광객에게 제공할 저녁 후보` 영역이 보인다. 치킨 후보를 1곳 이상 포함하지 않으면 저장할 수 없다.
- `관광객 화면 미리보기`는 직원 화면 안에서 선택 동작만 확인하는 시연 도구다. 화면에도 `시연용 · QR 연결 전`이라고 명시되어 있다.
- 동일한 후보 목록을 다시 저장하면 서버는 `이미 같은 후보 묶음입니다`라고 처리한다. 이 경우 새 버전이나 화면 변화가 없다.

## 4. 왜 “저장했는데 아무것도 안 바뀐 것처럼” 보이는가

### 의도된 부분

- 공통 코스를 유지하도록 만든 기능이므로 일정표·시간·방문 장소는 바뀌지 않는다.
- 점심은 후보 저장 자체가 선택 사항이어서, 자유식이라는 큰 흐름도 바뀌지 않는다.

### 보완이 필요한 부분

- 저장 완료 뒤에 **어느 후보가 어떤 버전에 저장됐는지**를 독립된 완료 카드로 크게 보여 주지 않는다.
- 지도 핀은 저장 후보만 보이게 하려는 코드가 있지만, 실제 사용자 화면에서 핀이 나타난 것을 아직 확인하지 못했다. 사용자 제보대로 핀이 안 보인다면 별도 오류로 봐야 한다.
- 관광객 선택은 현재 직원 화면의 미리보기까지만 가능하며, 홍보물 QR 랜딩으로 이어지지 않는다. 홍보물의 코스 QR 연결과 “식사 후보 선택” 연결은 다른 기능이다.
- 현재 관련 코드 변경은 로컬 작업 폴더에만 있고 아직 커밋되지 않았다. 다른 서버·브랜치·배포 화면에서는 같은 동작이 보장되지 않는다.

## 5. 저장 실패 또는 변화가 없는 경우 확인할 것

| 화면 문구/상황 | 뜻 |
|---|---|
| `후보 묶음을 저장했습니다` | 새 버전이 만들어졌고 후보 목록이 기록됨 |
| `이미 같은 후보 묶음입니다` | 기존 저장 목록과 완전히 같아서 새 버전을 만들지 않음 |
| `자료 보완이 남은 초안 후보 묶음…` | 확인 필요 후보가 있어 동의 체크가 필요함 |
| 저녁 저장 버튼 비활성 | 치킨 후보 1곳 이상 또는 최소 2곳 조건이 충족되지 않음 |
| 저장 후 지도 핀이 없음 | 저장 성공 여부와 별개로 지도 렌더링을 점검해야 하는 미확인 문제 |

## 6. 발표에서 현재 기능을 설명하는 안전한 표현

> 직원은 코스를 다시 바꾸지 않고, 점심·저녁 시간대에 관광객이 고를 식당 후보 묶음을 구성합니다. 저장하면 공통 일정은 유지되고 후보 목록만 다음 버전에 기록됩니다. 현재는 직원 화면의 시연 미리보기로 선택 흐름을 보여 주며, 실제 QR 랜딩에서의 식사 선택 연결과 지도 핀 노출은 후속 점검 대상입니다.

“QR에서 바로 식당을 고를 수 있다” 또는 “저장하면 코스 동선이 바뀐다”라고 발표하면 현재 구현보다 크게 말하게 된다.

## 7. 다음 수정 우선순위 제안 (아직 적용하지 않음)

1. 저장 직후 `저장 완료 · N개 후보 · 코스 vN` 카드와 저장 후보 목록을 고정 표시한다.
2. 저장 후보 핀을 지도에 확실히 노출하고, 핀 클릭 시 후보 이름·선택 상태를 보여 준다.
3. 홍보물 QR 랜딩에서 해당 코스의 식사 후보를 조회·개인 선택하도록 연결한다.
4. 직원용 시연 미리보기와 실제 관광객 QR 화면을 명확히 분리해 이름과 안내를 정리한다.

## 8. 확인 범위와 남은 검증

- 코드와 로컬 직원 화면에서 점심/저녁 후보 구성 영역, 저장 요청, 저장 후 최신 버전 재조회 흐름을 확인했다.
- 실제 지도 핀 표시와 실제 QR 랜딩 식사 선택은 완료로 확인하지 않았다.
- 운영일·시각·이동시간의 사람 검토, 관광객 실기기 QR 접속도 별도 검증이 필요하다.
- 이 문서는 현황 점검용이며, 팀 합의·외부 공개·운영 승인 완료를 뜻하지 않는다.
