# 피치 근거 점검표 갱신 지침

점검표는 피치 7장(문제 · 해결 · 시장 · BM · MVP · 팀 · 요청사항)마다 근거가 팀 자료 어디에 있고 무엇이 비었는지 보여 준다. 갱신은 **바뀐 것만 고친다.** 처음부터 다시 쓰지 않는다.

- 파일: `발표/MMDD_피치구조_근거점검.html` (지금은 `1120_`). 폴더에 하나만 둔다.
- 작성 브랜치: `신민지`. main에는 올리지 않는다.

## 1. 새 자료 찾기

1. `git fetch --all --prune`. 로컬 `신민지`가 원격보다 뒤면 먼저 맞춘다. 커밋하지 않은 남의 변경은 건드리지 않는다.
2. 점검표 맨 위 "기준" 시각 이후의 커밋을 모든 원격 브랜치에서 본다.
   - `git log --since="<기준 시각>" --format="%h %ci %s" <브랜치>`
3. 피치와 관련 있는 것만 고른다. 정리본 · 지침 · 기획서 · 밸류체인 · 발표 · MVP 실행 기록이 해당한다. 캐릭터 이미지나 원본 데이터만 바뀐 커밋은 넘긴다.
4. 고른 문서는 요약 표나 결정 칸을 직접 읽는다. 커밋 메시지만 보고 판정을 바꾸지 않는다.

## 2. 판정 규칙

| 표시 | 언제 |
|---|---|
| 있음 | 우리 주제로 완성된 산출물이 있다 |
| 초안 | 산출물은 있으나 "팀 검토 전" |
| 부분 | 관련 자료만 있거나 산출물 형태가 아니다 |
| 자료없음 | 찾지 못했다. 이 경우 **내용을 지어내지 않는다** |

- 근거 등급은 `원문`(원자료 직접 확인) · `보도`(언론) · `가정` · `미확인`으로 단다.
- 고객은 "대구 관광 담당자 전반"이고, 중구청은 MVP 사례다. 관광객 리뷰는 담당자 목소리로 세지 않는다.
- 수업 예시(lifestyle/D12~D14)는 넣지 않는다.
- 숫자에는 대상 · 기간 · 등급을 붙인다. 가정값이면 가정이라고 쓴다.

## 3. 고치는 곳

각 장은 같은 4칸이다. 해당 칸만 고친다.

1. **증명할 것** — 한 문장. 팀 결정이 바뀌었을 때만 고친다.
2. **발표에서 쓰는 근거** — 3~4개 항목, 등급 표시.
3. **근거 산출물** — 산출물마다 카드 1개. 상태 칩, 1~2줄 설명, 파일 경로는 "파일 위치" 접기 안에 둔다. 경로 앞에 브랜치 표시(민지 · 예진 · 밸류체인 · main)를 붙인다.
4. **남은 일** — 끝난 항목은 지우고 새로 생긴 일을 넣는다.

함께 맞출 곳:

- **한눈에 보기 카드:** 상태 칩과 "지금" 한 줄을 장별 상세와 같게 맞춘다.
- **우선순위:** 끝난 것을 빼고 순서를 다시 매긴다.
- **맨 위 "기준" 시각과 버전:** v4 → v5처럼 올린다.
- **변경 이력:** 한 줄 추가 (무엇이 무엇 → 무엇으로 바뀌었는지).
- **전제 카드(고객 · 지역 · 언어 등):** 팀 결정이 바뀐 경우만 고친다.

본문에 "11/xx 갱신" 같은 날짜 표시를 붙이지 않는다. 날짜는 변경 이력에만 쓴다.

## 4. 파일명

- 파일명 날짜는 **사용자가 요청할 때만** 바꾼다. `git mv`로 이름을 바꾼다.
- 바꾸면 옛 이름을 참조하는 곳을 찾아 고친다: `git grep "<옛 이름>"`. 다른 브랜치에 있는 참조는 고치지 않고, 사용자에게 알린다.

## 5. 확인과 커밋

1. 브라우저에서 열어 데스크톱과 모바일(375px)을 확인한다. 가로로 넘치는 곳이 없어야 한다.
2. 사용자에게 바뀐 판정과 남은 확인 사항을 짧게 보고한다.
3. 커밋은 사용자가 요청했을 때만 한다. 점검표와 이 갱신으로 바꾼 파일만 커밋한다. 이미 staged된 다른 파일(예: CLAUDE.md)은 섞지 않는다.
   - 메시지 예: `docs: 피치 근거 점검표에 <무엇> 반영 (v5)`
4. push가 거부되면 멈추고 원인을 알린다. 강제 push는 하지 않는다.
