## 2. 파이프라인

```
조건 입력 (S1)
  → ① 수요·타깃
  → ② 장소·동선
  → ③ 저녁·체류
  → ④ 스탬프·인센티브 (2차)
  → ⑤ 근거 검증 (게이트)  ← 모든 에이전트 출력이 여기를 거친다
  → ⑥ 홍보·다국어 (2차 일부)
  → 산출물 묶음 저장 (S5)
```

- 담당자 확인 지점: ③ 뒤 (S3, 운영 조건 충돌), ⑥ 뒤 (S4, 홍보 검토)
- 시스템이 자동으로 판별해 진행을 막는 기능은 아직 합의되지 않았습니다 (유저플로우 기준). 1차에서는 표시만 하고 막지 않습니다.
- 오케스트레이터는 조건을 각 에이전트에 나눠 주고, 결과와 근거 상태를 모아 기획안으로 묶습니다.

## 3. 에이전트별 명세

### ① 수요·타깃 에이전트

| 항목 | 내용 |
|---|---|
| 역할 | 방문객 유형과 시기에 맞는 기본 구조 선택 (당일형 또는 1박형) |
| 입력 | 방문 시기, 방문객 유형 (외국인), 테마, 예산 |
| 출력 | 기본 구조 (당일형 / 1박형), 방문객 프로파일, 근거 목록 |
| 근거 데이터 | KOSIS 2024 대구관광실태조사 외국인 방문지 (서문시장 83.6%, 동성로 76.9%, 약령시 33.6%, 근대골목 30.1%, n=1,010); 외국인 당일치기 비율 (여름 18.7%, 나머지 6~7%, 여름 표본 약 72명); 관광데이터랩 빅데이터 (출발지, 외국인 출발국) |
| 공백 | 구별 외국인 숙박 위치 없음. 외지인 방문자 정의 (고유 방문자 또는 방문 건수) 미확인. 구별 거주지 파일 값 이상 |
| 표시 규칙 | 여름 당일형은 "표본 작음, 옵션"으로 표시. 숙박 위치는 주장하지 않고 "공급 규모"까지만 씀 |

### ② 장소·동선 에이전트

| 항목 | 내용 |
|---|---|
| 역할 | 낮 관광 장소 순서, 이동 시간, 체류 시간 제안 |
| 입력 | 조건 (①의 구조), 장소 목록 (서문시장, 동성로, 약령시, 근대골목 등) |
| 출력 | 시간표 초안 (낮, 저녁 전 연결, 야간, 숙박형이면 다음 날 오전) |
| 근거 데이터 | 장소 목록과 기존 자산 (중구청 제공 예정). 이동 시간은 지도 공개 정보 |
| 공백 | **운영시간, 휴무, 요금 자료 없음 (1순위 공백).** 방문 시간대별 이동 시간 미확인 |
| 표시 규칙 | 운영 정보가 없는 장소는 시간표에 넣되 "운영 정보 미확인"으로 표시. 확인 전 확정 시간으로 쓰지 않음 |

### ③ 저녁·체류 에이전트

| 항목 | 내용 |
|---|---|
| 역할 | 선호 음식별 식당 후보 제안. 치킨은 고른 경우에만 포함. 저녁 체크포인트 설계 |
| 입력 | 선호 음식 (찜갈비, 콩국, 납작만두, 불고기, 비빔밥, 김밥, 삼겹살, 치킨 중 선택), 방문 시간 |
| 출력 | 음식별 식당 후보 (영업 상태와 위치를 확인한 곳만), 저녁 체크포인트 위치 |
| 근거 데이터 | 외국인 추천 음식 (치킨 1+2순위 3.8%). 중구 치킨 점포 74곳 (2026.09, 동구 262곳). 내국인 맛집 탐방 목적 0.5% (2023) |
| 공백 | 식당 영업 상태 미확인. **중구 치킨 역사 자료 확인 필요** |
| 표시 규칙 | 치킨은 기본 추천에 넣지 않음. 치킨 해설은 "확인 필요" 항목이 해결되기 전까지 주장으로 쓰지 않음 |

### ④ 스탬프·인센티브 에이전트 (2차)

| 항목 | 내용 |
|---|---|
| 역할 | 기존 스탬프와 연결, 저녁 체류 인증 기준 설계, 인센티브 참고 요건 표시. 독립 상품이 아니라 저녁 체크포인트 모듈로만 사용 |
| 입력 | 코스 초안, 기존 스탬프 목록 |
| 출력 | 스탬프 연결안, 체류 인증 기준, 인센티브 "참고 충족 / 미충족 (이유)" 표 |
| 근거 데이터 | 근대골목 스탬프투어 (12곳, 할인 연계), 약령시 한방로드 스탬프 (5곳, 2026.8 시작), 진흥원 인센티브 참고 요건 |
| 공백 | 스탬프 현행 운영 여부 미확인 |
| 표시 규칙 | 참고 요건은 "참고용이며, 인센티브 요건 판단은 진흥원 공고 기준을 따른다"를 항상 함께 표시. 미충족이어도 코스를 막지 않음. 기준 날짜를 함께 씀 |

인센티브 참고 요건 (공고 시기와 예산에 따라 바뀜): 외국인 6인 이상, 대구 1박 이상, 관광지 2곳 이상 (유료 1곳 이상 포함), 1박마다 관광지 1곳 추가. 반경 1km 이내 두 곳은 1곳으로 계산.

### ⑤ 근거 검증 에이전트 (게이트)

| 항목 | 내용 |
|---|---|
| 역할 | 모든 주장에 출처와 기준시점을 붙이고, 확인되지 않은 부분을 표시 |
| 입력 | 다른 에이전트의 모든 출력, `research/sources.md`, `research/crosscheck.md` |
| 출력 | 근거표 (주장별 등급: 확실, 중간, 약, 없음 / 확인 필요) |
| 근거 데이터 | CLAUDE.md 5장 출처 등급 (공식, 통계, 언론, 개인, AI 생성). 교차검증 판정 (일치, 부분일치, 불일치, 단일출처) |
| 공백 | 없음 (규칙 기반이므로 데이터가 없어도 동작). 단, 입력된 근거가 부족하면 "없음"으로 표시 |
| 표시 규칙 | "없음" 또는 "확인 필요"인 주장은 기획안 본문에 확정 표현으로 쓰지 않음. 근거가 없는 수치를 그대로 넘기지 않음 |

### ⑥ 홍보·다국어 에이전트

| 항목 | 내용 |
|---|---|
| 역할 | 방문 국가별 홍보 메시지, 번역 초안, 홍보물 시안 (포스터, SNS 카드), 영상 기획안 (2차) |
| 입력 | 확정된 코스, 방문 국가 (대만, 중국, 미국 등 빅데이터 기준), 언어 |
| 출력 | 다국어 홍보 문구, 포스터·SNS 카드 문구와 배치, (2차) 영상 스크립트, 장면 순서, 자막 초안 |
| 근거 데이터 | 외국인 출발국 (대만 중심, 2022~2025), 외국인 방문 증가 추세 (2022 하반기 이후). 캐릭터 (하랑이) 활용 여부 미정 |
| 공백 | 번역 언어와 범위 미정. 영상 활용 범위 미정 |
| 표시 규칙 | 수치를 넣은 문구는 근거표 번호를 붙임. "대구는 치킨 도시" 같은 자체 주장은 쓰지 않음 (CLAUDE.md 4장). 영상은 완성본을 만들지 않고 기획안까지만 만듦 |

## 4. 산출물 묶음

| 산출물 | 포함 시기 | 생성 주체 | 비고 |

영상 기획은 storyboard/ 폴더의 디지털 내러티브 틀을 이어 씁니다.

## 5. 역할 경계

| 일 | 에이전트 (우리 팀) | 사람 |
|---|---|---|
| 코스 기획, 근거 검증, 해설 콘텐츠, 홍보 기획, 스탬프 체크포인트 설계 | 초안 작성 | 팀 검토 |
| 상품화, 가격, 숙박 계약, 예약, 판매, 인센티브 신청 | 해당 없음 (숙박은 위치와 규모 정보만) | 여행사 |
| 발주 승인, 장소 자산 제공, 검수, 예산 | 해당 없음 | 중구청 |
| 스탬프 앱, QR, 보상 발급, 정산 | 해당 없음 (체류 기준만 설계) | 운영 파트너 |

## 6. 범위

| 단계 | 에이전트 | 산출물 |
|---|---|---|
| **1차 (MVP)** | ①, ②, ③, ⑤ | 중구 야간·1박 연계 기획안 PDF, 근거표 |
| 2차 | ④, ⑥ (홍보 문구, 홍보물 시안) | 다국어 홍보 초안, 포스터·SNS 카드 시안 |
| 3차 | ⑥ (영상 기획안) | 영상 기획안 |

1차를 ①②③⑤로 잡은 이유는 데이터가 있는 에이전트만 먼저 돌리기 위해서입니다. ②는 운영 정보가 들어오기 전까지 "미확인" 표시로 동작합니다.

## 7. 공통 규칙

- 근거 등급 표기는 프로젝트 정리 기준을 따릅니다: 확실 (공식 통계), 중간, 약, 없음 / 확인 필요.
- 수치에는 기준시점, 지역, 대상, 단위를 함께 씁니다.
- 사실과 팀의 해석·제안을 구분합니다.
- 제안한 시설이나 상품을 실제 운영 사례처럼 쓰지 않습니다.
- 생존 인물과 실존 업체는 공개된 공식 기록 범위에서만 다룹니다.

## 9. 다음 단계

1. 근대골목 투어 1~5코스 시간대를 확인합니다. 야간·1박 차별점의 전제입니다.
2. 중구청 관광과 인터뷰로 발주 적합과 도구 수요를 확인합니다.
3. 야간·1박 연계 샘플을 이 파이프라인으로 한 번 통과시킵니다. 가장 큰 공백은 ② 운영정보입니다.
4. 팀 검토 후 이 문서를 확정하고 커밋 여부를 정합니다.
