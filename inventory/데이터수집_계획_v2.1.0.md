# 데이터 수집 계획 v2.1.0 (기획방향 v2.1 기준 · 외국인 MVP)

- 상태: 팀 검토용 초안. 커밋 전.
- 기준: `기획방향_기준_v2.1.md`, `에이전트_구성_v2.1.md` (이 워크트리 `inventory/`). v2.0.1 계획은 이 버전으로 대체 (v2.0.1 파일은 변경하지 않음).
- 변경 요약: 직원 입력을 **방문 월 하나**로 줄임. 에이전트를 **오케스트레이터 + 서브 4개**로 재편. 홍보를 **1차 포함**, 인센티브·스탬프·영상·측정은 **2차 이후**. 산출물은 **제안서 HTML + 홍보물**.
- 마감: 2026-12-01 · 인원: 2명

## 0. 우리가 만드는 것

| 산출물 | 만드는 에이전트 | 1차 (MVP) |

직원이 입력하는 것은 **방문 월 하나**입니다. 나머지는 시스템이 정하거나 데이터 기본값을 씁니다.

| 입력 | 처리 | 연결 데이터 |
|---|---|---|
| 방문 월 (직원 선택) | **입력** | 시기별 구조 규칙 (B-1) |

| 음식 후보 | 직원 선택 없음. **데이터 기본값** | A-5, A-11, A-12 (참고용) |
| 인원 | 입력 없음. 제안서에 **가정값 (예: 2명)** 표기 | 동행 데이터 미확인 |

### 2-1. 장소 층과 투어 층

장소는 투어와 상관없이 모두 담고, 투어는 장소 위에 얹는 정보로 따로 기록합니다.

| 중구 | 서문시장 | 밤마실 A 도착 | 금·토 19~21시 (밤마실 기준) | 음식 기본값 |
| 중구 | 계산성당 | 밤마실 A 경유 | 미확인 | — |

**코스 설계 판단 순서**
1. 장소를 먼저 고릅니다.
2. 그 장소에 **투어가 있으면** 투어 시간과 코스를 붙입니다.
3. 투어가 **없으면** 장소의 운영 정보만으로 짭니다. 정보가 없으면 "미확인"으로 표시합니다.

## 4. 서브 에이전트별 데이터 명세

`에이전트_구성_v2.1.md` 기준입니다. 서브 4개와 오케스트레이터로 구성합니다.

### 오케스트레이터
- **입력:** 방문 월
- **역할:** 월로 기본 구조 결정 → 서브 A → B → C 실행 → C 결과 확인 → D 실행 → 묶음 저장
- **필요 데이터:** B-1
- **출력:** 제안서 HTML, 근거표, 홍보물, 실행 기록

### A. 코스 설계 (수요 + 동선)
- **입력:** 기본 구조 (1박형 / 당일형 옵션), 장소 목록
- **필요 데이터:** A-3, A-4, A-6, A-10, B-1, B-5, B-8
- **출력:** 일자별 시간표 초안, 체크포인트 후보 위치 (스탬프는 한 줄 연계만)
- **공백 처리:** A-4가 없는 장소는 "운영 정보 미확인". 확정 시간으로 쓰지 않음
- **1차 최소:** 장소 5~8곳, 그중 운영 정보 확인 5곳

### B. 저녁·음식
- **입력:** 저녁 위치 (A 결과), 음식 기본값 목록
- **필요 데이터:** A-5, A-11, A-12, A-15, B-2
- **출력:** 음식 선택지 3~4개 (식당 2~3곳씩), 치킨 선택지 1개, 해설 지점 1곳
- **공백 처리:** 영업 미확인 식당은 "영업 확인 필요". 치킨 역사가 미확인이면 해설에 역사 주장 금지

### C. 근거 검증 (게이트)
- **입력:** A, B, D의 모든 출력
- **필요 데이터:** A-14, B-4
- **출력:** 근거표 (주장, 출처 ID, 등급, 기준 시점), 미확인 목록
- **공백 처리:** 출처 없는 주장은 "없음" 표시. 1차에서는 막지 않고 표시만 함

### D. 홍보
- **입력:** C를 통과한 코스 내용, 언어 (영어 1순위, 중국어 번체 2순위)
