# 관리자 화면과 담당자 기획 기록 구성안

- 작성일: 2026-11-22
- 상태: 구성안. 첫 구현은 로컬 실행 결과 조회이며, 화면 구현·배포 완료를 뜻하지 않는다.
- 기준: `유저플로우_v1.md`, `반영사항/유저플로우_미정항목_결정및반영시점_1122.md`

## 1. 목적과 화면 구분

같은 서비스에 담당자용 화면과 운영팀용 관리자 화면을 둔다. 관리자 화면은 버리는 시험 화면이 아니라 향후 운영에 사용하되, 고객 화면으로 그대로 바꾸지는 않는다. 실행 데이터와 근거표·경고 표시 기능은 재사용한다.

| 사용자 | 화면 | 목적 |
|---|---|---|
| 관광·홍보 담당자 | 조건 입력 → 근거·코스·홍보 검토 → 산출물, 내 기획 기록 | 기획 생성·선택·수정·저장·이전 기획 불러오기 |
| 운영팀 | 실행 기록·결과·오류·비교 | 실행 실패 원인 확인, 지침 변경 전후 비교 |

## 2. 첫 구현: 저장 결과 조회

`app/runs/`의 기존 파일을 읽는 로컬 조회 화면부터 만든다. AI 실행은 우선 터미널을 사용한다. 로그인·DB·실행 버튼을 먼저 완성할 필요는 없다.

| 영역 | 내용 |
|---|---|
| 실행 목록 | 실행 일시, 조건, 회차, 결과 파일 유무 |
| 단계별 결과 | 1단계 자료·알림·선택, 2단계 요약·근거표·경고·선택 |
| 전달 검사 | 통과·실패, 오류와 관련 R/W ID, 검사 범위 |
| 원문 | Markdown·JSON 펼쳐 보기 |

- 표는 접고 펼칠 수 있게 한다. 출력이 길어도 전달 데이터는 생략하지 않는다.
- 파일 생성, 전달 검사 통과, 원표 대조 완료, 담당자 확정을 구분한다.
- 실제 연결하지 않은 3·4·5단계를 실행 완료로 표시하지 않는다.
- 화면 조회·재표시만으로 AI를 다시 호출하지 않는다. 원본 실행 결과를 수정하지 않는다.

## 3. 실행 기록

실행 → 회차 → 단계로 식별한다. 현재 저장하는 조건·결과·담당자 선택·검사결과를 먼저 활용한다.

이후 단계 시작·완료·실패 시각, 사용 모델·제공자, 실제 사용한 지침 버전, 토큰·비용을 수집한다. 파일 수정 뒤 버전을 추정하지 않도록 실행 시점에 지침 식별값을 남긴다. 미수집 값은 미수집으로 표시하며 추정 비용과 실제 청구액을 구분한다.

로그 저장은 결과 파일 저장뿐 아니라 단계별 실패와 담당자 선택도 포함한다. API 키·인증정보는 기록하지 않는다.

## 4. 발전 순서

1. 기존 결과 조회: 실행 목록, 단계 결과, 검사 오류, 원문.
2. 화면에서 실행: 조건 입력, 진행·실패 상태, 담당자 선택, 회차 보존.
3. 비교: 같은 조건에서 지침·모델 버전별 결과와 시간·오류 비교.
4. 담당자 서비스: 동일한 데이터 처리를 이용하되 고객에게 필요한 선택·검토 흐름으로 구성.

파일 읽기와 화면 표시를 분리해 서버·DB로 저장 방식이 바뀌어도 재사용한다. 첫 조회 화면에 DB를 선행 조건으로 두지 않는다.

## 5. 담당자의 내 기획 기록

기획 이름·조건·입력 데이터·근거·경고·담당자 결정·코스·홍보물·산출물과 초안/확정/다시 확인 필요 상태를 조회하고 불러온다. 운영팀 디버깅 로그와 구분한다. 현재 앱이 이 기능 전체를 구현했다는 뜻은 아니다.

## 6. 공유·상용 서비스 전 준비

- 담당자·운영팀의 인증과 접근 권한, 사용자별 기록 분리.
- 서버 측 AI 호출·API 키 관리, 민감한 입력을 포함한 로그의 노출 범위.
- 저장·복원·보관·삭제·백업 정책. Supabase 사용 범위는 WBS와 대조 후 확정.
- 실제 사용한 지침·모델·실행을 연결하고 앞 단계 변경 결과를 최신 확정본과 구분.

## 7. 시험과 완료 기준

자동 테스트는 코드 동작, 실제 에이전트 시험은 자료 선택·수치·출력 준수, 화면 시험은 읽기·선택·오류 찾기를 검증한다. 화면이 생겨도 앞의 검사를 유지한다.

첫 화면의 완료 기준은 저장 결과를 수정하거나 AI를 재호출하지 않고 회차별로 열어 보며 원문과 검사 오류를 찾을 수 있는 것이다. 실제 구현·시험 뒤에만 반영 목록에 완료를 기록한다.

## 8. WBS 보완안

- 웹 뼈대·호출 연결 작업에 단계별 실행 기록 수집을 포함.
- 관리자 결과 조회 화면을 데모 직전까지 미루지 않고 먼저 구현.
- 담당자 기록은 저장뿐 아니라 목록·조회·불러오기 범위를 명시.
- 비교·집계는 기본 조회와 실행 연결 이후 확장. 본 항목은 WBS 반영 전 제안.
