# MVP 시연 기준과 기관 데이터 연결

- 작성일: 2026-11-25
- 목적: 시연에서 반드시 보여 줄 일과 빠진 연결을 함께 정리한다.
- 상태: **사용자가 명시한 요구와 이번 검토의 제안을 구분한 문서**다. 팀 전체 합의·구현 완료·실제 AI 시험 완료를 뜻하지 않는다.
- 작업 범위: 코드·실행 기록·서버·설정·Git 상태는 변경하지 않고 현재 파일을 읽어 확인했다. 이 문서 작성과 반영 목록의 문서 링크 기록만 한다.

## 1. 사용자 요청으로 정해진 기준

| 항목 | 이번 시연 기준 |
|---|---|
| 대상·시기·지역·기간 | 일본인 커플·가을·중구·1박2일 |
| 다른 지역 기능 | 기존 지역 선택과 동구 자료는 보존. 이번 시연 코스를 위해 동구로 넓히지 않음 |
| 저녁 | 치킨은 선택 사항. 대구 방문 외국인 음식 선호 설문을 참고하고, 해당 국가 자료·표본·기간·한계를 구분 |
| 조건 처리 | 필수 조건은 AI가 바꾸지 않음. 못 지키거나 확인할 수 없으면 이유를 표시 |
| 대안과 수정 | 중구 안에서 A/B 비교·부분 수정. 희망을 바꾸면 무엇을 왜 바꿨는지 설명 |
| 담당자 보유 자료 | 사이트에서 파일을 올리고, 기존 저장소 자료와 함께 분석해 코스 추천에도 반영하는 흐름이 필요 |
| 현재 문제 | 사용자가 코스 생성 시 B안이 나오지 않는다고 보고함. 업로드 경로도 사이트에서 빠져 있음 |

기관 자료 반영은 단순히 파일명을 보여 주거나 요약문을 추가하는 것으로 끝나지 않는다. 어떤 업로드 행을 어떤 코스 판단에 사용했는지 연결해야 한다.

## 2. 이번에 파일에서 확인한 사실

| 확인 대상 | 현재 코드에 있는 것 | 부족한 것·주의점 |
|---|---|---|
| `app/기획실행.py` | 저장소 CSV에서 근거를 뽑고 코스 작성으로 전달. 자율이용·대안 비교 요청 설정 | 실행 중 기관 데이터를 `기관 데이터: 없음`으로 고정. 업로드한 파일을 가져오는 연결 없음 |
| `app/upload.py` | 로컬 경로의 CSV 복사, XLSX의 시트별 CSV 변환. 원본 수정 없음 | 브라우저 업로드 수신·열 의미 확인·분석·근거 연결까지 해주는 기능은 아님 |
| `app/관리자조회.py` | JSON 요청으로 기획 시작·부분 수정 등을 받음 | 파일 업로드 전용 수신·미리보기·확인 경로는 확인되지 않음. 현재 JSON 본문 제한을 그대로 대용량 파일 처리에 쓰면 안 됨 |
| `app/근거추출.py` | 저장소의 조건별 데이터 행 선택·근거표·경고를 코드로 작성 | 담당자 업로드 자료를 같은 구조로 합치는 경로 필요 |
| `app/관리자실행.py` | 자율이용 코스 작성 요청에 A/B와 대안 불가 이유를 요구하는 코드 있음 | 요청을 보냈다는 것과 실제 B안이 만들어졌다는 것은 다름 |
| `app/기록가져오기.py` | 대안 비교 요청이 있으면 응답의 `대안제안`을 등록 | 예전 저장본에 요청·결과 필드가 없으면 새 기능으로 자동 복구되지 않음 |
| `app/대안비교.py` | 다른 구성·이유·선택 지역을 검사해 B 등록. 미등록 이유 기록 | B 누락·동일 일정·잘못된 형식·이유 누락·필수 조건 변경·지역 위반 등에 따라 미생성 처리 |
| `지침/2_수요근거/입력_형식.md` | CSV·XLSX, 8열 템플릿, 읽은 내용 확인 절차가 제안돼 있음 | 형식·상한·자유 형식 지원 범위는 팀 최종 확정으로 취급하지 않음 |

읽은 최근 공유 기획 기록 3개에는 A만 있었고 대안상태·실행정책은 없었다. 이것만으로 사용자가 지금 보고 있는 실행의 원인을 확정할 수는 없다. 해당 화면의 실행 ID로 요청·AI 응답·등록 결과·서버 반영 버전을 대조해야 한다.

## 3. 권하는 전체 시연 흐름 — 구현 기준 제안

1. 담당자가 일본인 커플·가을·중구·1박2일 조건과 희망을 입력한다.
2. 기관 자료가 있으면 CSV/XLSX를 올리고, 없으면 기존 자료만 사용한다.
3. 코드가 파일을 읽어 표·행 수·출처·기간·대상·지역·단위를 미리 보여 준다.
4. 담당자가 읽은 내용과 사용할 시트·열을 확인한다. 모호한 열은 추측하지 않는다.
5. 코드가 기존 자료와 업로드 자료를 구분해 정리하고, 조건·단위·표본·기간 차이와 중복을 검사한다.
6. AI는 확인된 근거를 바탕으로 요약하고 A/B 코스를 제안한다. 양쪽 안 모두 기존 자료와 채택한 업로드 자료를 함께 받는다.
7. 코드가 각 안의 필수 조건·일정·참조·차이를 검사한다. 담당자는 바뀐 점과 자료 사용 이유를 보고 비교한다.
8. “저녁만 다시” 같은 부분 수정에도 같은 자료와 조건을 유지하고 수정본을 다시 검사한다.
9. 사람이 선택·검토한 결과를 기존 홍보·산출물 경로로 넘긴다. 선택과 판매·예약·번역 확정을 같은 것으로 기록하지 않는다.

예시(가상): 기관 설문에 일본인 응답자의 덜 매운 식사 선호가 있다면, 그 행을 근거로 식사 후보를 검토한다. 이를 곧바로 특정 식당이 덜 맵다거나 예약 가능하다는 증거로 사용하지 않는다. 후보 식당의 운영·메뉴 정보는 별도로 필요하다.

## 4. 코드와 AI의 역할

| 코드가 맡을 일 | AI가 맡을 일 |
|---|---|
| 파일 수신·보관·CSV/XLSX 읽기 | 확인된 근거의 의미와 한계를 쉽게 설명 |
| 미리보기·시트 선택·열 연결 | 음식·관광·체류 근거를 종합한 코스 제안 |
| 숫자·단위·결측·기간·표본 검사 | A/B의 구성 차이·장단점 설명 |
| 조건별 필터·정해진 합계/비율 계산 | 희망을 지키기 어려운 이유와 대안 설명 |
| 출처와 원래 행 위치 기록 | 사람의 요청에 따른 부분 수정 |
| 근거표·경고 생성과 전달·일관성 검사 | 정해진 규칙만으로 판단하기 어려운 기획 해석 |

파일 읽기와 숫자 계산은 코드로 처리하는 방향을 권한다. 그렇다고 여행 코스 추천 전체를 정해진 규칙만으로 바꾸는 것은 별도 결정이다.

### 기관 자료를 합칠 때 지킬 것

- 원본 파일·시트·행·출처·기간·대상·지역·단위·표본을 보존한다.
- 기존 자료와 기관 자료에 서로 구분되는 근거 ID를 부여한다. 이름 규칙은 구현 시 정한다.
- 같은 조사를 복사한 자료를 독립된 두 근거로 세거나 중복 합산하지 않는다.
- 대상·지역·단위가 다른 수치를 섞거나 단순 평균하지 않는다.
- 기관 자료라는 이유만으로 기존 자료보다 무조건 우선하지 않는다. 시점·대상·품질을 비교한다.
- 비교가 안 되면 제외하거나 별도 참고로 남기는 선택을 보여 준다.
- 코스에는 “사용한 업로드 근거”와 “참고하지 못한 이유”를 연결한다. 파일을 올렸다는 이유만으로 모든 행이 반영됐다고 쓰지 않는다.
- 업로드 파일을 바꾸면 영향을 받는 코스·홍보·문서를 다시 확인 대상으로 표시한다.

## 5. B안 미생성을 어떻게 다룰까 — 정책 제안

- 정상 시연의 목표는 실제 차이가 있는 중구 A/B 두 안을 비교하는 것이다. 희망을 입력하지 않았다는 이유만으로 비교 기능이 사라지지 않게 한다.
- 다르게 짠다는 것은 장소·방문 순서·식사·자율 구간·이동 구성 등의 차이다. 이름만 바꾸거나 A를 복제해 성공으로 처리하지 않는다.
- AI가 B를 누락하거나 형식을 틀린 경우는 “대안이 원래 불가능함”과 구분한다. 기존 호출 한도 안의 보완 요청 여부를 구현 전에 정한다.
- 자료상 대안을 만들 수 없는 경우는 부족한 자료와 필요한 확인을 구체적으로 보여 준다.
- B가 지역·기간 등 필수 조건을 어기면 이를 완성된 대안으로 내보내지 않는다. 위반 이유를 표시하고 허용된 범위에서 보완한다.
- 두 안 비교가 목표인 시연에서 A만 나온 상태는 전체 성공으로 표시하지 않는 방향을 권한다. 부분 성공·B 미생성 사유를 별도로 표시한다.
- 기존 기록의 B 없음과 새로 생성한 결과의 B 실패를 구분한다. 이전 원본은 고치지 않는다.

정확한 오류 원인은 아직 재현·확정하지 않았다. 특정 실행 ID에서 코스 작성 요청 → 원문 `대안제안` → `대안비교.등록` → 화면 표시를 순서대로 확인해야 한다.

## 6. 수정 순서 제안

| 순서 | 작업 | 기존 파일·기능 활용 | 완료 확인 |
|---|---|---|---|
| 1 | B 미생성 사례 확인 | `관리자실행.py`, `기록가져오기.py`, `대안비교.py`, 해당 runs 기록 | 누락·등록 거절·기존 기록·화면 문제를 구분 |
| 2 | 정상 A/B 비교와 실패 표시 보완 | 위 파일과 `총괄.py`, 담당자 화면 | 차이 있는 A/B 표시, 이유 없는 A 단독 성공 방지 |
| 3 | CSV/XLSX 업로드·미리보기·읽은 내용 확인 | `upload.py`, 서버, 담당자 화면, 기존 템플릿 | 실제 파일이 들어오고 선택 시트·열·메타정보를 확인 |
| 4 | 기관 자료를 기존 근거와 연결 | `근거추출.py`, 2단계 전달·공유 기획 기록 | 원본 위치·별도 근거 ID·비교 경고 보존 |
| 5 | 코스와 부분 수정에 반영 | `기획실행.py`, `처리기.py`, 3단계 입력 | A/B와 수정본에서 업로드 근거 사용 이유 확인 |
| 6 | 처음부터 끝까지 시연 | 입력 → 업로드 확인 → A/B → 부분 수정 → 기존 후속 단계 | 미리 준비한 저장 결과가 아닌 새 실행으로 확인 |

## 7. 아직 선택이 필요한 범위

| 결정 | 권하는 첫 구현 | 아직 확정으로 기록하지 않을 것 |
|---|---|---|
| 파일 종류 | CSV·XLSX | PDF·HWP·이미지 표 읽기 |
| 표 구조 | 기존 8열 템플릿을 기준으로 열 연결·미리보기 제공 | 어떤 복잡한 자유 형식 엑셀도 자동 해석한다는 약속 |
| 파일 내용 | 설문·방문·음식·숙박 등 수치 표 | 개인별 응답·명부를 그대로 저장하는 방식 |
| 시트 처리 | 시트별 미리보기 후 사용할 시트 선택 | 사용자가 선택하지 않은 모든 시트의 자동 채택 |
| 실행 한도 | 기존 시간·호출 한도 유지, 보완 호출 정책 별도 명시 | 무제한 재시도·일정 시간 내 완료 보장 |
| 파일·행 수 제한 | 구현 전에 상한과 초과 안내 정의 | 임의 숫자를 팀 합의로 표시하는 것 |

## 8. 이번 문서 작성의 확인 결과

아래는 최초 문서 작성 시점의 기록이다. 후속 사용자 요청으로 구현한 내용은 9절에 구분한다.

- 진행 중인 앱·화면·조사 원본·기존 실행·설정·서버·브랜치를 변경하지 않았다.
- 실제 AI 호출·파일 업로드 시험·B안 재생성 시험을 실행하지 않았다. 코드 읽기로 확인한 상태와 사용자 보고를 구분했다.
- 이 문서의 제안 항목은 사용자·담당자 검토 전이다. 수정 구현·시험·팀 합의 완료로 표시하지 않는다.

## 9. 후속 요청에 따른 구현과 확인 (2026-11-25)

사용자가 B 미생성 조사·수정, CSV/XLSX 업로드 연결과 가상 예제 작성을 명시적으로 요청했다. 팀 공통 운영정책의 최종 합의와는 구분한다.

| 구분 | 확인·반영한 내용 |
|---|---|
