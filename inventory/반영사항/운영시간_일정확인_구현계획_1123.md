# 운영시간·숙박·자유시간 확인 입력

사용자 요청: AI 재실행 없이 운영 확인 결과와 일정 시작·끝을 입력해 기존 초안에 반영하고 4단계 준비 여부를 검사한다.

- 기존 로컬 관리자 서버·저장본 선택을 사용한다. 별도 새 통합시험 수정본에 입력·코스·검사를 보존한다. 원본과 담당자 지침·Git 기록은 변경하지 않는다.
- 방문 시작일, 장소/자유식 후보별 운영 여부·영업시간·주문/입장 마감·확인 출처/등급/날짜·방문일 확인을 입력한다. 후보 제외는 자유식 추천 후보에만 적용한다.
- 일정별 시작/종료 일차와 시각·장소/권역·이후 연결 확인을 입력한다. 숙박과 자유시간도 같은 방식으로 편집한다. 미정은 보존하며 운영·이동정보를 추정하지 않는다.
- 명시적으로 입력한 기간으로 머무는 시간과 식사 시각을 동기화한다. 운영시간에 맞추려면 야시장 등 일정 기간도 담당자가 수정할 수 있다. 자동 AI 조정은 없다.
- 준비 검사는 일차·시작/종료·필수 일정 기간·시간 충돌·운영시간/마감/휴무·출처 정보·이동 연결 확인·E7 처리·담당자 최종 검토를 본다. 입력 자료의 진실성을 자동 검증한 것으로 주장하지 않는다. 일반 경고는 유지한다.
- 최종 검토는 기본 미선택이며, 사람이 체크하고 검사까지 통과해야 준비 완료로 표시한다. 입력/조건이 달라지면 이전 확인을 그대로 재사용해 완료 처리하지 않는다. 4단계 AI는 실행하지 않는다.
- 파일: `app/운영검토.py`, `app/관리자실행.py`·`관리자조회.py`, 관리자 화면 별도 JS/CSS, 의미 있는 순수 함수·서비스·HTTP·UI 상태 시험.
- 검증: 실패 시험 → 구현 → 전체 자동시험·JS 검사·실제 로컬 읽기 API 확인. 실제 운영값은 임의 입력하지 않는다. 브라우저 조작 권한 거부를 우회하지 않는다. 커밋·push 없음.

## 구현 확인

- Python 110개, Node 화면 상태 시험 24개 통과. 실제 로컬 조회의 일정·운영 항목 연결 확인.
- 외부 AI·운영 정보 검색 없이 구현·시험했다. 실제 운영값·담당자 확인은 임의 기입하지 않았다.
- 기간 편집은 숙박/자유시간 외 일반 일정도 지원한다. 운영시간 초과를 발견해도 저장된 실제 확인값 없이 자동 단축하지 않는다.
- 준비 완료의 근거는 사용자 입력과 실제 체크이며 4단계 호출은 별도다. 이후 조건 변경 시 재검토가 필요하다.
