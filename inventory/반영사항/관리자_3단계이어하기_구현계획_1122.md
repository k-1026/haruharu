# 관리자 코스 조건 입력·3단계 이어하기 구현 계획

> 실행: executing-plans로 현재 통합 폴더에서 직접 진행한다. 기존 사용자 변경·원격 브랜치·3·4단계 지침을 보존한다. 커밋·push는 이번 요청에 포함하지 않는다.

## 사용자 요청과 설계

검사 통과한 기존 2단계 실행을 선택해 코스 조건을 입력하고 3단계만 이어서 시험한다. 앞 대화에서 제시한 기존 관리자 화면 확장안을 사용자가 선택했다. 별도 터미널 재실행은 1·2단계를 반복하고, 별도 웹 앱은 현재 조회 기능을 중복하므로 기존 Python 서버·HTML/JS를 확장한다.

- Python 표준 HTTP 서버, 기존 Claude Agent SDK 실행기와 코스 검사 재사용. 새 의존성 없음.
- 시작·종료 지점과 시각, 운영 방식, 치킨 옵션, 2일차 오전, 각 식사의 방식·지정 식당·식비를 입력한다. 빈 값은 미정으로 유지한다. 당일은 2일차 항목 제외.
- 조건 저장은 AI 호출 없이 원본 아래 새 통합시험 폴더에 스냅샷을 만든다. 이후 ‘3단계 AI 시험 시작’을 눌러야 외부 AI를 호출한다. 1·2단계 및 4·5단계는 호출하지 않는다.
- 저장된 통과 표시만 믿지 않고 최신 전달 검사 재실행. 입력 변경 시 저장부터 다시 한다. 중복 클릭은 같은 시험을 중복 실행하지 않는다. 실행 중에도 조회 가능하도록 백그라운드 작업한다.
- 실행 중·초안 생성·검사 확인 필요·실행 실패를 구분한다. 기존 엄격한 코스 검사는 확정 준비 검사로 사용한다. 미정 입력을 담당자 확정으로 바꾸지 않는다. AI 실패 사유에 비밀 값·traceback을 노출하지 않는다.
- 상태·조건·3단계 입력·결과·검사를 파일로 보존. 결과는 시간표와 경고로 읽기 쉽게 표시하며 JSON 원문도 조회 가능.
- 로컬 바인딩 유지. 쓰기 요청은 같은 출처·임의 세션 토큰·JSON 형식·크기 검사. runs 밖과 원본 덮어쓰기를 거부한다.

## 파일과 작업 순서

1. `app/test_관리자실행.py`: 실패 검사·조건 검증·별도 저장·원본 보존·중복 실행·AI 실패·미정 초안·HTTP 쓰기 경계 시험을 먼저 작성하고 실패를 확인한다.
2. `app/관리자실행.py`: 입력 검증, 스냅샷 저장, 최신 전달 검사, 3단계만 실행하는 서비스. 실행함수 주입으로 실제 AI 없이 검증한다.
3. `app/관리자조회.py`: 서비스와 POST 조건 저장·실행·GET 상태 API 연결. 읽기 API 보존.
4. `app/관리자화면/`: 입력 폼, 저장/실행 버튼, polling, 결과 시간표·경고, 오류·중복 클릭 처리.
5. 전체 unittest, JS 문법 검사, 임시 서버의 실제 HTTP 왕복 검증. 소유한 로컬 조회 서버를 새 코드로 재시작. 브라우저 자동 조작은 앞선 거부를 우회하지 않는다.
6. 반영 목록과 사용 안내에 실제 확인 범위·남은 실제 AI 시험을 기록한다.

## 중점 검토

- 오래된 검사 통과 또는 편집된 전달 JSON → 최신 검사로 거부.
- 미선택·당일/숙박·잘못된 시각·자유식 잔여 식당 → 조건 보존 또는 구체적 오류.
- 다른 실행 선택/조건 수정/중복 클릭 → 원본·잘못된 실행에 쓰지 않음.
- 실행 예외/서버 재시작 → 계속 실행 중처럼 표시하지 않음.
- 불완전한 AI JSON → 원문 보존, 성공·확정으로 표시하지 않음.
