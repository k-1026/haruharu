# 관리자 결과 조회 구현 계획

- 사용자 승인: 로컬 통합 브랜치에서 관리자 조회 화면을 먼저 만들고, 담당자 화면은 이후 연결.
- 설계: `../관리자화면_기획기록_구성안_1122.md`.
- 기술 선택: 기존 Python 앱에 표준 라이브러리 HTTP 서버와 HTML/CSS/JS를 추가한다. 새 프로젝트·DB·외부 패키지·배포 없이 같은 저장 데이터를 재사용한다.
- 범위: 조회만. AI 실행·수정·삭제·고객 인증·비용 수집은 이번 구현에 포함하지 않는다.

## 작업과 시험

- [ ] 저장소 읽기: 실행·회차·통합시험 폴더 목록, 조건·파일·전달 검사 요약. 잘못된 JSON·빈 폴더·실행 중 파일에도 목록 유지.
- [ ] 읽기 API: 허용된 md/json 결과만 조회. 경로 이탈·심볼릭 링크·원본 자료·인증 파일 노출 차단, 쓰기 요청 거부 시험.
- [ ] 화면: 실행 검색, 회차 선택, 단계 선택, 요약·근거표·경고·원문. 파일 생성과 검사 통과·원표 대조를 구분. 미수집 비용·시간은 미수집 표시.
- [ ] 안전한 표시: AI 출력은 HTML로 실행하지 않고 텍스트·표로 렌더. 긴 표 펼치기·검색, 모바일·키보드 접근성 확인.
- [ ] 통합 자동 시험과 로컬 HTTP·브라우저 확인. 실제 기존 결과를 조회하되 AI 재호출과 원본 변경 없음.
- [ ] 처리 목록·실행 안내 갱신, 로컬 커밋. 원격 push·배포·실제 AI 호출 제외.

## 경계

- 서버는 기본 127.0.0.1에만 열고 runs 밖의 파일을 제공하지 않는다.
- 2단계 전달 결과와 3·4단계 검사 결과는 각각 기록된 검사 범위로 표시한다.
- 현장 검증·원표 대조·사람 확정은 기록이 없으면 완료로 표시하지 않는다.
- 예진 3·4단계와 원본 데이터는 수정하지 않는다. 기존 미추적 원본 파일도 포함·삭제하지 않는다.
