## 1. 새 HTML 작성 기준

참고 파일 두 개는 이미 작성된 것으로 그대로 둔다. 아래 기준은 새로 만드는 HTML에만 적용한다. 참고 파일은 형식만 본다.

| 항목 | 참고 파일 | 새 HTML에서의 기준 | 근거 |
|---|---|---|---|
| 서비스 이름 | 공공 관광기관 담당자 기획 서비스 | **대구 체류 기획 도구** | 기획방향 §1 |
| 고객 | 재단 등 공공 관광기관 담당자 | **대구 기초지자체 관광 담당 부서** (예: 구청 관광과). MVP 1차 대상은 중구청 관광콘텐츠팀이지만, 본문에는 특정 구청을 고정하지 않는다 | 기획방향 §8, 역할분담 §1 |
| 지역 범위 | 대구 중구→동구 숙박형 코스 | **1단계는 중구만.** 동구는 2단계 옵션으로 표시 | 중구_선정_근거 §6 |
| 치킨 | "치킨 스토리는 모든 코스에 포함" (고정 원칙) | **고정 원칙 아님.** 음식 선택지 중 하나, 해설 요소로만 씀. 기본 추천에서는 제외 | 기획방향 §4 |
| 시기 단위 | 월·계절 | **계절 단위가 기본.** 월별은 검증용 | 기획방향 §11 항목 8 |
| 당일형 | 당일형도 ②를 거친다 | 당일형은 숙박 데이터 없이 기획 가능. 상품 유형은 숙박형/당일형 선택 | 기획방향 §6 |
| 여행사 | 언급 없음 또는 고객처럼 표시 | **실행 파트너** (숙박·교통·예약·판매). 고객이나 도구 사용자가 아님 | 기획방향 §11 항목 6 |

## 2. 문서 구조 (반드시 이 순서)

1. **헤더:** 제목, 부제(서비스 목적 한 문장), 기준일, 메타 3칸 (서비스 목적 / 주 사용자 / 최종 결과물)
2. **범례:** 아래 네 가지 태그를 모두 정의한다.
   - `확정` (팀이 정한 조건, 외부 검증 완료 아님)
   - `근거` (공식 통계·공고·언론으로 확인된 사실. 출처 번호 표기)
   - `해석` (자료를 바탕으로 한 판단)
   - `가설` (검증 전 값) / `미정` (자료나 결정이 필요함)
3. **단계 격자 (5단계 이상):** 열 = 단계, 행 = 행동 / 생각(가설 질문) / 터치포인트 / 문제 가설 / 개선 기회
4. **흐름도 (선택):** 정상 진행과 예외 경로를 구분한다. 예외는 점선과 주황색으로 표시
5. **근거 목록:** 각 태그에 연결된 출처를 번호로 적는다. 출처는 `research/sources.md`의 ID를 쓴다
6. **미정 항목:** 확정하지 않은 기능을 따로 모은다 (예: 스탬프 앱, 운영 주체 전달)

## 3. 단계 구성 (기본안)

| 단계 | 이름 | 확인할 것 |
|---|---|---|
| S1 | 기획 조건 정하기 | 계절, 방문객 유형(국가·언어권), 기간, 예산, 상품 유형(숙박형/당일형) |
| S2 | 수요 근거 확인하기 | 언어권별 관심 관광지, 거주지(국가) 비율, 방문율. 기준 시점과 지역을 함께 적는다 |
| S3 | 코스 검토·수정하기 | 장소 순서, 영업시간·휴무, 이동 시간, 체류 시간, 음식 선택지, 저녁 체크포인트 |
| S4 | 홍보 콘텐츠 검토하기 | 언어(영어·일본어·중국어 간체·번체), 국가별 문구, 코스와 장면 일치 |
| S5 | 기획안 확정·PDF 저장 | 근거표 포함 여부, 인센티브 참고 표시 여부. 운영 주체 전달은 범위 밖 |

## 4. 태그와 표기 규칙

- 근거 태그에는 반드시 출처 ID와 기준 시점을 붙인다. 예: `근거 · S02 · 2024`
- 언론 출처는 `근거(언론)`처럼 등급을 함께 표시한다. 중구청 공식 실적이 없으면 "미확인"이라고 적는다.
- 여행사 수수료, 판매 실적, 숙박 요금처럼 자료가 없는 항목은 `가설` 또는 `미정`으로 둔다. 추정값을 채우지 않는다.
- 치킨은 "음식 선택지" 또는 "해설 요소"로만 적는다. 메인 콘셉트나 모든 코스의 고정 항목으로 쓰지 않는다.
- 동구는 2단계 옵션으로만 쓴다. 본 코스에 넣지 않는다.
- 수치에는 시점·지역·대상·단위를 함께 적는다.

## 5. 디자인 규칙 (참고 파일 형식 따름)

- 색은 CSS 변수(`:root`)로 정의하고, `prefers-color-scheme: dark`와 `[data-theme="dark"]` 모두에 다크 값을 준다.
- 외부 스크립트는 cdnjs, cdn.jsdelivr.net/npm, unpkg 중에서만 가져오며 버전을 명시한다. 흐름도가 필요할 때만 mermaid를 쓴다.
- 최대 너비는 1240px 이하, 모바일(폭 375px)에서 가로 스크롤이 생기지 않게 한다.
- 파일은 HTML 하나로 만든다. 제목(`<title>`)은 2–4단어로 쓴다.

## 6. 작성 순서

1. 기준 표(1절)를 확인하고 참고 파일과 다른 점을 HTML 상단 "변경 사항"에 적는다.
2. 근거 목록을 먼저 만든다 (`research/sources.md`, `inventory/*.md`).
3. 단계 격자를 채운다. 각 칸에 태그를 하나 이상 붙인다.
4. 흐름도와 예외 경로를 그린다.
5. 미정 항목을 따로 모은다.
6. 브라우저에서 열어 확인한다 (라이트·다크, 모바일 폭).

## 7. 완료 기준

- 참고 파일의 "치킨 고정", "동구 본 코스", "재단 고객" 표현이 없다.
- 모든 수치에 출처 ID와 기준 시점이 있다.
- 가설과 근거가 태그로 구분된다.
- 여행사는 실행 파트너로만 나온다.
