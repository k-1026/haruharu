## 1. 새 HTML 작성 기준

참고 파일 두 개는 이미 작성된 것으로 그대로 둔다. 아래 기준은 새로 만드는 HTML에만 적용한다. 참고 파일은 형식만 본다.

| 항목 | 참고 파일 | 새 HTML에서의 기준 | 근거 |
|---|---|---|---|
| 서비스 이름 | 공공 관광기관 담당자 기획 서비스 | **대구 체류 기획 도구** | 기획방향 §1 |
| 고객 | 재단 등 공공 관광기관 담당자 | **대구 기초지자체 관광 담당 부서** (예: 구청 관광과). MVP 1차 대상은 중구청 관광콘텐츠팀이지만, 본문에는 특정 구청을 고정하지 않는다 | 기획방향 §8, 역할분담 §1 |
| 지역 범위 | 대구 중구→동구 숙박형 코스 | **1단계는 중구만.** 동구는 2단계 옵션으로 표시 | 중구_선정_근거 §6 |
| 치킨 | "치킨 스토리는 모든 코스에 포함" (고정 원칙) | **고정 원칙 아님.** 음식 선택지 중 하나, 해설 요소로만 씀. 기본 추천에서는 제외 | 기획방향 §4 |
| 시기 단위 | 월·계절 | **계절 단위가 기본.** 월별은 검증용 | 기획방향 §11 항목 8 |
| 당일형 | 당일형도 ②를 거친다 | 당일형은 숙박 데이터 없이 기획 가능. 상품 유형은 숙박형/당일형 선택 | 기획방향 §6 |
| 여행사 | 언급 없음 또는 고객처럼 표시 | **실행 파트너** (숙박·교통·예약·판매). 고객이나 도구 사용자가 아님 | 기획방향 §11 항목 6 |

## 2. 문서 구조 (반드시 이 순서)

1. **헤더:** 제목, 부제(서비스 목적 한 문장), 기준일, 메타 3칸 (서비스 목적 / 주 사용자 / 최종 결과물)
2. **범례:** 아래 네 가지 태그를 모두 정의한다.
   - `확정` (팀이 정한 조건, 외부 검증 완료 아님)
   - `근거` (공식 통계·공고·언론으로 확인된 사실. 출처 번호 표기)
   - `해석` (자료를 바탕으로 한 판단)
   - `가설` (검증 전 값) / `미정` (자료나 결정이 필요함)
3. **단계 격자 (5단계 이상):** 열 = 단계, 행 = 행동 / 생각(가설 질문) / 터치포인트 / 문제 가설 / 개선 기회
4. **흐름도 (선택):** 정상 진행과 예외 경로를 구분한다. 예외는 점선과 주황색으로 표시
5. **근거 목록:** 각 태그에 연결된 출처를 번호로 적는다. 출처는 `research/sources.md`의 ID를 쓴다
6. **미정 항목:** 확정하지 않은 기능을 따로 모은다 (예: 스탬프 앱, 운영 주체 전달)

## 3. 단계 구성 (기본안)

| 단계 | 이름 | 확인할 것 |
|---|---|---|
| S1 | 기획 조건 정하기 | 계절, 방문객 유형(국가·언어권), 기간, 예산, 상품 유형(숙박형/당일형) |
| S2 | 수요 근거 확인하기 | 언어권별 관심 관광지, 거주지(국가) 비율, 방문율. 기준 시점과 지역을 함께 적는다 |
| S3 | 코스 검토·수정하기 | 장소 순서, 영업시간·휴무, 이동 시간, 체류 시간, 음식 선택지, 저녁 체크포인트 |
| S4 | 홍보 콘텐츠 검토하기 | 언어(영어·일본어·중국어 간체·번체), 국가별 문구, 코스와 장면 일치 |
| S5 | 기획안 확정·PDF 저장 | 근거표 포함 여부, 인센티브 참고 표시 여부. 운영 주체 전달은 범위 밖 |

## 4. 태그와 표기 규칙

- 근거 태그에는 반드시 출처 ID와 기준 시점을 붙인다. 예: `근거 · S02 · 2024`
- 언론 출처는 `근거(언론)`처럼 등급을 함께 표시한다. 중구청 공식 실적이 없으면 "미확인"이라고 적는다.
- 여행사 수수료, 판매 실적, 숙박 요금처럼 자료가 없는 항목은 `가설` 또는 `미정`으로 둔다. 추정값을 채우지 않는다.
- 치킨은 "음식 선택지" 또는 "해설 요소"로만 적는다. 메인 콘셉트나 모든 코스의 고정 항목으로 쓰지 않는다.
- 동구는 2단계 옵션으로만 쓴다. 본 코스에 넣지 않는다.
- 수치에는 시점·지역·대상·단위를 함께 적는다.

## 5. 디자인 규칙 (참고 파일 형식 따름)

- 색은 CSS 변수(`:root`)로 정의하고, `prefers-color-scheme: dark`와 `[data-theme="dark"]` 모두에 다크 값을 준다.
- 외부 스크립트는 cdnjs, cdn.jsdelivr.net/npm, unpkg 중에서만 가져오며 버전을 명시한다. 흐름도가 필요할 때만 mermaid를 쓴다.
- 최대 너비는 1240px 이하, 모바일(폭 375px)에서 가로 스크롤이 생기지 않게 한다.
- 파일은 HTML 하나로 만든다. 제목(`<title>`)은 2–4단어로 쓴다.

## 5-1. 밸류체인 맵 형식 (`value_chain_map.html` 참고)

밸류체인 맵은 SVG 한 장(1600×900)으로 만든다. 참고 파일의 구조를 따르되, 아래 항목을 우리 프로젝트에 맞춘다.

**구조 (행 4개 × 열 단계)**

| 행 | 내용 | 표기 |
|---|---|---|
| 활동 (단계) | 단계 상자. 상자 안에 단계 이름과 우리 역할 한 줄 | 단계 간 화살표 |
| 이해관계자 | 단계별 주체. **굵게** = 하는 사람, (괄호) = 영향 주는 사람 | 괄호 안에 근거 태그 |
| 돈 흐름 | 주황 띠. 돈이 **소비자 → 원천 방향**으로 흐른다 | 금액이나 비율은 출처 번호와 함께 적는다 |
| 데이터 흐름 | 파랑 띠. 단계마다 생기는 데이터와 보유 주체 | 앞 단계에서 뒤 단계로 점선 화살표 |

- 열은 **7단계**(①자원 확보 ~ ⑦사후·성과)를 쓴다. 가로가 좁으면 상자 너비를 줄인다.
- 피드백은 **뒤 단계에서 앞 단계로** 가는 점선 곡선 한 개로 표시한다 (예: ⑦ 성과 → ① 자원 재조사).
- 바닥글에 범례를 넣는다: `[U]` 미확인, `[I]` 해석, `[H]` 가설, `[N-xx]` 출처 번호, `§n` 절 번호.

**추가 항목 (`valuechain_v1.html` 형식에서 보강)**

- **돈 흐름 행:** 시작점과 끝점을 명시한다. 예: "시작점 ○○ [U] → 끝점 ○○". 돈 흐름 방향을 화살표 옆 글로 적는다. 금액이 없으면 `[U]`로 쓰고 숫자를 채우지 않는다.
- **데이터 흐름 행:** 각 칸에 "데이터명 · 보유자"를 적는다. 보유자를 모르면 `[U]`.
- **피드백 행:** 뒤 단계에서 앞 단계로 가는 회수 경로를 적는다. 회수 경로가 없으면 ✕ 표시와 "데이터 단절"을 명시한다.
- **팀 자산 행:** 우리 팀이 이미 가진 자산(예: 캐릭터, 코스 설계안, 수요 데이터)을 단계별로 적는다.
- **마커 (칸 위 작은 표지):**
  - `B` 병목: 흐름을 막는 문제 (근거와 함께)
  - `C` 비용: 드는 비용 (근거 또는 `[I]`)
  - `O` 기회: 우리가 개입할 수 있는 지점. 괄호에 "보류" 등 상태를 적는다
  - `✕` 단절: 피드백 경로 없음
- **근거 줄:** 맵 하단에 "수치 출처"와 "근거 표" 경로를 적는다. 예: `research/…/analysis.md`
- **제목 줄:** "사례 이름 밸류체인 맵 vN · 기준일 · 기준 사례 · 검토 상태"를 한 줄로 적는다.
- **범례:** 돈 흐름(주황), 데이터(파랑), 팀 자산, 병목, 비용, 기회의 색과 기호를 하단에 한 줄로 설명한다.

**색 (참고 파일과 같게)**

- 단계 상자: 연한 녹색 (`#E7F5F1`, 테두리 `#9FD4C6`)
- 돈 흐름 띠: 연한 주황 (`#FFF5DE`, 화살표 `#E8A23A`)
- 데이터 흐름 띠: 연한 파랑 (`#E9F0FB`, 화살표 `#3B6FD8`)
- 마지막 단계 상자는 진한 남색 (`#1E2B2F`)으로 강조 (우리 프로젝트에서는 ⑦ 사후·성과)

**우리 프로젝트에 맞춘 내용 (참고 파일의 노랑풍선 예시를 그대로 쓰지 않는다)**

- 돈 흐름: 발주 기관 → 우리 (기획 용역비, 규모 [U]) / 여행사 ← 인센티브·지원금 (진흥원, 구청 지원, 금액은 공고 기준) / 여행사 → 판매 수익 (수수료 [U])
- 데이터 흐름: ① 장소 목록 (구청) → ② 관심·거주지 데이터 (관광데이터랩, 우리 보유) → ③ 숙박·요금 (여행사) → ⑦ 체크포인트 방문 기록 (우리가 설계, 보유 주체 정함)
- 이해관계자: 중구청 관광콘텐츠팀 (MVP 고객), 대구 기초지자체 관광 부서 (확장 고객), 여행사 (실행 파트너), 진흥원 관광본부 (인센티브·판로, 참고)
- 고객을 특정 구청으로 고정하지 않는다 (2절 고객 기준 적용).
- 음식(치킨)은 단계 상자에 넣지 않는다. ②에서 선택지 하나로만 적는다.

**작성 규칙**

- 모든 칸에 근거 태그를 하나 이상 붙인다. 근거가 없으면 `[H]`를 쓴다.
- 여행사 수수료, 판매 건수, 요금처럼 자료가 없는 값은 빈칸으로 두지 않고 `[U]`로 표시한다.
- 개념도임을 바닥글에 명시한다 ("개념도 · 실제 데이터 아님").

## 5-2. 사례 페이지 가치사슬 형식 (`daegu_dcaf_stamp_road20.html` 기준)

사례 페이지의 가치사슬 칸은 아래 네 줄과 하단 설명으로 구성한다. 표가 아니라 그림으로 그린다.

**구성 (위에서 아래로)**

1. **활동 (단계):** 단계 상자 5~7개를 가로로 나열한다. 상자 안에 단계 이름과 한 줄 설명을 넣는다.
2. **이해관계자:** 단계별 주체를 상자로 표시한다. **굵게** = 하는 사람, (괄호) = 영향 주는 사람, 근거가 없으면 `[U]`.
3. **돈 흐름:** 주황 띠. 화살표 옆에 금액 또는 `[U]`를 적는다. 시작점을 명시한다.
4. **데이터 흐름:** 파랑 띠. 화살표 옆에 "데이터명 · 보유자"를 적는다.
5. **마커 줄:** 칸 위에 `B` 병목, `C` 비용, `O` 기회·강점, `✕` 단절을 표시하고 괄호에 상태를 쓴다.

**하단 설명 (고정 문구)**
- `[U]` = 자료 없음, `[I]` = 해석, 괄호 = 영향 주는 사람
- 칸의 사실은 리서치 칸과 같은 출처 번호를 쓴다.

**점검 섹션 (가치사슬 바로 아래)**
- "지금 병목 · 보완해야 할 점"을 번호 목록으로 쓴다. 각 항목에 근거 또는 `[I]`를 붙인다.
- "유지할 강점"을 따로 적는다.

**근거 목록 (맨 아래)**
- 번호, 자료명, 발행처, 링크. 본문의 숫자는 이 번호와 연결한다.

## 6. 작성 순서

1. 기준 표(1절)를 확인하고 참고 파일과 다른 점을 HTML 상단 "변경 사항"에 적는다.
2. 근거 목록을 먼저 만든다 (`research/sources.md`, `inventory/*.md`).
3. 단계 격자를 채운다. 각 칸에 태그를 하나 이상 붙인다.
4. 흐름도와 예외 경로를 그린다.
5. 미정 항목을 따로 모은다.
6. 브라우저에서 열어 확인한다 (라이트·다크, 모바일 폭).

## 7. 완료 기준

- 참고 파일의 "치킨 고정", "동구 본 코스", "재단 고객" 표현이 없다.
- 모든 수치에 출처 ID와 기준 시점이 있다.
- 가설과 근거가 태그로 구분된다.
- 여행사는 실행 파트너로만 나온다.
