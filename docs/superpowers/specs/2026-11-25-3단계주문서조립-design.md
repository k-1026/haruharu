# 3단계 코스 작성: AI는 주문서, 코드는 조립 (2026-11-25)

## 왜

- 11/25 시연용 CSV(일본인 커플·중구·가을·1박2일, 자율이용 A/B)로 관리자 3단계를 돌리자 60초 제한에서 끊겼다 (`app/runs/20261125_155826/01회차/통합시험_155847_423675`).
- 실측한 크기:
  - AI가 받는 양: 지침 12개와 장소·이동 CSV를 합쳐 약 8.4만 자. 여기에 입력 약 5만 자(그중 근거목록 129줄이 4.2만 자)와 공통 넘김 규칙 8천 자가 더해진다.
  - AI가 쓰는 양: A·B 완성 코스 JSON 약 5만 자(11/22 성공본 기준, 들여쓰기 포함).
- AI는 읽기는 빠르고 쓰기는 느리다. 따라서 느린 원인은 **쓰는 양**이다.
- 11/22 성공본을 항목별로 나눠 보면, AI의 판단이 필요한 부분(칸목록+식사목록)은 약 2,400자다. 나머지 약 2만 자(남은경고·미확인사항·체크리스트·장소별근거·겹침이력 등)는 2단계 결과와 CSV를 옮겨 적고 규칙대로 확인하면 만들 수 있다.
- 사용자 요구:
  - 담당자가 기다리는 시간은 **1분 안팎**이어야 한다.
  - 토큰을 최소로 써야 한다.
  - 실제 데이터는 지금 예시보다 훨씬 크므로, **데이터가 커져도 AI가 받는 양이 늘지 않아야** 한다.

## 목표

1. 3단계 AI 호출 한 번이 `역할_제한초['코스검토.md']=60` 안에 끝난다. 시연 CSV 1박2일 A/B를 실제 AI로 돌려 확인한다.
2. AI가 쓰는 답은 A안 전체와 B안의 바뀐 칸만 담은 **주문서**다. 목표 크기는 3천 자 이하.
3. AI가 받는 양은 장소 데이터 크기와 상관없이 일정하다. 코드가 후보를 걸러 상한(기본 30곳) 안에서만 넘긴다. 목표 크기는 1.5만 자 이하.
4. 코드가 주문서를 **지금과 같은 형식의 완성 코스 JSON**으로 조립한다. 그래서 화면(`담당자화면/plan.js`)과 검사(`단계연결.코스_검사`, `시간표검사`, `검사분류`, `운영검토`), 4·5단계는 그대로 동작한다.
5. 관리자 3단계(`관리자실행.py`)와 자율 기획 흐름(`처리기.코스짜기`·`부분수정`)이 같은 부품을 쓴다.

## 하지 않는 것

- AI 제한 시간을 늘리는 것 (사용자가 거절함).
- 지침 `지침/3_코스검토/*.md` 12개와 `.claude/agents/코스검토.md`를 고치거나 지우는 것. 이 파일들은 팀 규칙 문서이자 사람2 담당 공용 파일이다. 새 짧은 지시문은 별도 파일로 둔다.
- 화면 디자인 변경, 4단계 이후 변경.
- 모델 교체(Haiku 등). 필요하면 이 구조 위에서 따로 시험한다.

## 실패로 보는 것

- 시간은 줄었는데 AI가 장소 이름·운영시간·이동시간을 직접 써서 CSV와 다른 값이 나오는 것. 이런 사실 값은 코드만 쓴다.
- 데이터가 커질 때 후보표나 근거표가 같이 커지는 것.
- 조립 결과가 지금 형식과 달라 화면이나 검사가 깨지는 것.
- 주문서가 틀렸을 때(없는 장소 ID 등) 코드가 조용히 추측해서 채우는 것. 틀린 주문서는 문제로 표시한다.

## 방법

- **검토한 방법**
  - 가. 주문서 + 코드 조립
  - 나. 지금 방식에서 답만 압축 (들여쓰기 제거, 코드가 만들 수 있는 항목 생략)
  - 다. A·B·일차별로 AI 여러 번 동시 호출
- **결정: 가** (사용자 결정, 2026-11-25).
  - 나는 장소·시각·이동을 여전히 AI가 써서 1박2일 A/B에서 60초를 넘길 수 있고, 데이터가 커지면 다시 느려진다.
  - 다는 기다리는 시간은 줄지만 같은 자료를 여러 번 읽어 토큰이 늘고, 일차끼리 맞지 않을 위험이 있다.
- **B안: A안과 같은 호출에서 바뀐 칸만** (사용자 결정, 2026-11-25).

## 흐름

```
3단계 입력 ──► ① 후보표 만들기 (코드) ──► ② AI 주문서 (1회, 60초) ──► ③ 주문서 검사 (코드) ──► ④ 조립 (코드) ──► 기존 검사·저장
```

### ① 후보표 만들기 — 코드, 새 모듈 `app/코스조립.py`

- **장소 후보**
  - 장소 CSV(`설정.자료_파일`의 `HARUHARU_PLACES_FILE`)에서 다음 조건으로 거른다:
    - 조건의 구 안에 있음 (C8)
    - 치킨을 선택하지 않았으면 치킨 식사 장소 제외 (C2)
    - 휴무 요일 정보로 출발 가능 요일이 하나도 없는 장소는 뒤로 보냄
  - 상태(`확인`·`미확인`·`미입력`)로는 거르지 않는다. 근대골목·김광석길처럼 핵심 장소도 지금 `미입력`이기 때문이다. 상태는 후보표에 그대로 넘기고, 조립할 때 운영정보 `미확인`으로 표시한다. (빌더 판단)
  - **치킨 장소 판별**: 장소명에 `(치킨 옵션)` 표기가 있으면 치킨 장소로 본다. 지금 CSV의 3곳(7·8·14번)이 모두 이 표기를 쓴다. 표기 규칙이 깨지면 시험이 실패하게 만든다. 나중에 CSV에 `치킨` 열을 따로 두는 것이 낫다(데이터 담당에 제안). (빌더 판단)
  - **가족 술 제외**: 후보표에서 장소를 빼지 않는다. 프로젝트 규칙상 가족 코스는 "술 없이" 짜는 것이지 치킨 식당을 빼는 것이 아니기 때문이다. 주문서 지시문에 "가족이면 치맥·야시장 음주 구성 금지"를 넣고, 조립 단계에서 가족 코스의 `이유` 문장에 술 관련 낱말(맥주·치맥·술·주점)이 있으면 문제로 표시한다. (빌더 판단)
  - 시간칸(`코스칸`)별로 고르게, 최대 30곳(설정값 `HARUHARU_COURSE_CANDIDATES`, 기본 30)만 남긴다. 단, 고쳐 쓰기·부분수정일 때 **이전 코스에 들어 있던 장소는 항상 후보표에 넣는다**. 상한을 넘는 만큼은 다른 후보를 덜어서 총합을 30으로 유지한다. (빌더 판단)
  - 넘기는 줄 형식: `P{순번}|장소명|구|코스칸|장소유형|운영시간|정기휴무|상태`.
- **이동 후보**: 남은 후보끼리의 이동 CSV 행만 넘긴다. 형식: `P{a}>P{b}|도보분|대중교통분`.
  - **이름 맞추기**: 이동 CSV와 장소 CSV는 장소 이름 표기가 다르다(예: "뉴욕통닭 (동성로 치킨)" ↔ "뉴욕통닭 (치킨 옵션)"). 그래서 **괄호 앞 이름**(공백 제거)으로 맞춘다.
    - 괄호 앞 이름이 같은 장소가 둘 이상이면 맞추지 않는다. 그 구간은 이동시간 `미확인`으로 두고 `미확인사항`에 "이름 대응 불명확"으로 적는다. 정해진 규칙만 쓰고 추측하지 않기 위해서다.
    - 장기적으로는 이동 CSV에 장소 순번 열을 두는 것이 맞다(데이터 담당에 제안). (빌더 판단)
- **근거 후보**
  - 근거목록 전체 대신 `근거ID|항목|한 줄 요약` 형식으로 넘긴다. 한 줄 요약은 원자료항목명과 수치_원문으로 만든다.
  - 후보 장소 이름이나 조건(언어권·계절)과 관련된 근거를 먼저 넣고, 최대 40줄까지만 넘긴다.
  - 이미 있는 `근거추출.py`의 코드근거추출 결과를 우선 쓴다.
- **운영주체 후보표**: `11_운영주체_후보.md` 표를 `O번호|한 줄 설명` 형식으로 넘긴다(약 1~2천 자). CSV의 `운영주체후보` 열은 18행 중 17행이 비어 있고, 11번 표는 장소명이 아니라 사업 설명으로 쓰여 있다. 그래서 코드가 고정 대응을 할 수 없다. 장소에 어느 운영주체가 맞는지는 지금처럼 **AI가 고르고**(주문서 `운영`), 코드는 그 O번호가 표에 있는지만 검사한다. CSV 열에 값이 있으면 그 값을 우선한다. (빌더 판단)
- **담당자 조건**: `코스작성조건`, 확정체류기간, 기획모드, 희망(자율 흐름), 부분수정 정보를 그대로 넘긴다. 이 부분은 짧다.
- **기록**: 후보표 원본(P번호와 CSV 행의 대응)을 실행 폴더에 `3단계_후보표.json`으로 저장한다. 조립과 재검사는 이 파일을 쓴다. CSV가 나중에 바뀌어도 그 실행을 다시 만들 수 있게 하기 위해서다.

### ② AI 주문서 — 새 지시문 `.claude/agents/코스주문.md`

- 지침 12개 중 **AI가 판단해야 하는 규칙만** 2~3천 자로 줄여 담는다:
  - 하루 구조(낮 관광 → 저녁 선택 → 근거리 귀가 / 원거리 야경·숙박·다음 날 오전)
  - 타깃에 맞는 장소 고르기
  - 치킨은 저녁 선택 1번까지
  - 가족은 술 없음
  - 대표 관광지 1곳 이상
  - 같은 날 지정식 음식 겹침 피하기
  - 이동 부담 줄이기
  - B안은 이동·운영 부담을 줄이는 방향
- 계산·대조로 판정하는 규칙(이동 상한, 운영시간, 겹침, 운영주체, 체크리스트 결과)은 넣지 않는다. 코드가 한다.
- `run_stage.에이전트_읽기`에서 `코스주문.md`는 지침·CSV를 동봉하지 않는다. 후보표가 입력에 들어 있기 때문이다.
- 제한초 60초는 `역할_제한초`에 `코스주문.md: 60`으로 추가한다.
- **주문서 형식** (압축 JSON 한 줄, 들여쓰기 없음):

```json
{"A":{"칸":[{"칸ID":"낮-1","일차":1,"시간칸":"낮","장소":"P1","머무는분":90,"근거":["R19"],"운영":["O1"],"이유":"한 줄"}],
      "식사":[{"칸ID":"점심-1","방식":"자유식","권역":"P2","후보":["P5"]}],
      "희망반영":[{"희망id":"h1","반영":"지킴","이유":"한 줄"}]},
 "B":{"이유":"한 줄","무엇을":"한 줄","바꾼희망":{},"바꾼칸":[{...A 칸과 같은 모양}],"뺀칸":["낮-2"]},
 "대안불가이유":""}
```

- 식사 칸은 `칸`에도 한 줄을 두고(장소는 지정식 식당 P번호, 자유식은 권역 P번호), `식사`에는 방식과 후보만 적는다.
- **CSV에 없는 칸은 AI가 쓰지 않는다.** 숙박, 2일차 오전 자유시간, 코스 시작·종료 지점(역 등)은 코드가 정해진 문장으로 넣는다. (빌더 판단)
  - 숙박: 1박2일이면 1일차 마지막에 숙박 칸을 자동으로 넣는다. 장소명은 `숙소 (○○구 도심, 업체 미고정)`이고 시각은 `가정`이다.
  - 2일차 오전: 담당자가 고른 `2일차오전구성`대로 넣는다. 자유시간이면 `자유시간 (담당자 선택)` 칸, 후보일정추가면 AI가 P번호로 주문한다.
  - 시작·종료 지점: `코스작성조건` 값 그대로 쓰고, 없으면 `미확인`으로 둔다.
  - 그래서 11/22 성공본 비교 시험에서 이 칸들은 장소명이 아니라 "칸이 있는지"만 비교한다.
- **자율 흐름에서 한 안만 쓸 때**: 처음 작성, 보완요청 고쳐 쓰기, B안 단독 작성, `대안비교.보완` 모두 주문서는 `{"안":{…A와 같은 모양…}}` 한 안짜리다. A+B를 함께 쓰는 형식은 관리자 화면 자율이용 A/B에서만 쓴다. 고쳐 쓸 때는 이전 버전을 주문서 모양(P번호 목록)으로 바꿔 입력에 넣는다. 완성 코스를 통째로 넘기지 않는다. (빌더 판단)
- `희망반영`은 자율 흐름에서 희망이 있을 때만 쓴다. 자율 흐름에서 원래 요청과 다른 안이면 `대안설명`(무엇을·왜·좋아진점·남은문제, 각 한 줄)을 더한다. 지금 `처리기.코스입력`의 출력추가 요청을 이 짧은 형식으로 옮긴 것이다.
- 시각은 AI가 쓰지 않는다. 순서와 머무는 시간만 쓰고, 시각은 코드가 계산한다(④). AI가 시각을 계산하다 틀리는 일을 없애기 위해서다.
- B안을 만들 수 없으면 `"B":null`로 두고 `대안불가이유`를 쓴다.

### ③ 주문서 검사 — 코드

- JSON을 읽을 수 없거나 다음 경우에 해당하면 **문제 목록**으로 돌려준다:
  - 후보표에 없는 P번호
  - 입력 근거목록에 없는 근거ID
  - 같은 안 안에서 칸ID 중복
  - 당일인데 2일차 칸이 있음
  - B안의 `바꾼칸`이나 `뺀칸`이 A안에 없는 칸ID를 가리킴
- 문제는 추측해서 고치지 않는다.
  - 관리자 화면에서는 지금처럼 `검사확인필요` 상태로 보여 준다.
  - 자율 흐름에서는 지금처럼 `실행_기록` 실패로 남겨 총괄이 보완 요청을 다시 보내게 한다.
- 자동 재호출은 하지 않는다. 60초 안에 두 번 부를 여유가 없기 때문이다.

### ④ 조립 — 코드

주문서 + 후보표 + 3단계 입력 → 지금 형식의 완성 코스 JSON. 필드별로 만드는 곳은 다음과 같다.

| 필드 | 만드는 법 | 지금 규칙 출처 |

- **대체안**: 충돌(휴무·운영시간 밖·이동 상한 초과)이 난 칸은 같은 시간칸·같은 구의 다른 후보를 코드가 `대체후보`로 붙인다. 자동으로 바꾸지는 않는다(`10_대체_규칙.md`의 "담당자 선택" 원칙).
- **저장 파일**: AI 주문서 원문은 새 파일 `3단계_주문서.json`에 저장한다. `3단계_결과.md`와 `3단계_구조화.json`에는 **조립한 완성 코스**를 지금처럼 쓴다. 관리자실행의 `수정반영`·`검토정보`·`_이전칸`·`검토반영`·`재검사`·`수정가능` 판단이 모두 `3단계_결과.md`를 완성 코스로 읽기 때문이다. 이렇게 하면 수정 기능을 고치지 않아도 된다. (빌더 판단)
- 재검사는 지금처럼 `3단계_결과.md`(조립본)로 한다. 조립 규칙이 바뀌어 다시 조립해야 할 때는 `3단계_주문서.json`과 `3단계_후보표.json`으로 AI 호출 없이 다시 만든다.
- **부분수정 시각**: 유지칸은 장소·머무는 시간·**시각까지** 그대로 고정한다. 바뀐 칸만 그 사이에 이어 계산한다. 담당자가 "저녁만 다시"라고 하면 낮 시간표가 움직이지 않을 것을 기대하기 때문이다. 바뀐 칸이 다음 유지칸 시각을 넘기면 고치지 않고 `시간표검사` 충돌로 보여 준다. (빌더 판단)

## 연결할 곳

- `관리자실행.py._실행`: 긴 요청문 대신 ①→②→③→④를 부른다. `_결과검사`는 조립 결과를 받도록 `원문` 대신 결과 객체를 넘기는 경로를 하나 더 둔다.
- `처리기.코스짜기`: `호출(...)`에 `코스주문.md`와 후보표 입력을 넘기고, 받은 주문서를 조립한 값을 지금처럼 `코스안`에 넣는다. `부분수정`은 바꿀시간칸만 주문하게 입력에 적고, 유지칸은 지금처럼 `유지칸_되살리기`로 되돌린다.
- `run_stage.py`: `코스주문.md`는 동봉 없이 짧은 본문만 보낸다. 제한초는 60.
- 매 호출마다 `받은글자`·`쓴글자`·`경과초`를 실행 폴더에 기록한다. 하네스 검증과 시연 때 "1분 안에 끝났다"를 보여 줄 근거가 된다.

## 확인 방법

- **단위 시험**(가짜 AI 응답):
  - 후보표 상한 30 유지(장소 CSV를 300행으로 부풀려도 같은 크기)
  - 주문서 검사(없는 P번호, 근거ID, 칸 중복)
  - 조립 결과가 `단계연결.코스_검사`·`시간표_검사`를 통과하는 형식인지
  - B안 바꾼칸 적용
  - 11/22 성공본과 같은 장소 순서를 주문서로 넣었을 때 칸목록 장소명·머무는시간·근거ID가 같은지
- **실제 AI 시험**: 시연 CSV 1박2일 A/B와 당일 1회씩 돌려 경과초 60초 이하, 받은 글자 1.5만 이하, 쓴 글자 3천 이하인지 기록한다.
- 기존 시험(`app/test_*.py`, `*.cjs`)은 모두 통과해야 한다.
