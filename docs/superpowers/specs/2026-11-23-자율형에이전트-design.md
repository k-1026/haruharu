# 자율형 에이전트 구조 설계 (2026-11-23)

> 근거: 팀 방향성 문서 「프로젝트 방향성」(2026-11-23 사용자 제공). 이 문서가 `2026-11-23-담당자화면-design.md`의 2~5단계(새 코스 · A/B안 · 다시 만들기 · 시작 장소)를 흡수한다. 그 문서의 1단계(화면 분리 + 지도)는 완료(커밋 e9d2612~a7061f4).

## 왜
- 지금 `app/orchestrator.py`는 1→2→3→4 순서를 고정하고, 사람이 단계마다 승인한다. AI 에이전트가 판단하는 모습이 드러나지 않고, "운영 정보 미확인" 같은 빈칸이 나오면 그대로 멈춘다.
- 관리자 창은 줄글 결과 · 검사 기록을 그대로 쏟아 놓아 무엇을 봐야 할지 모른다.
- 방향성: 총괄이 계획 · 분배 · 재요청, 자료 수집 에이전트가 빈칸을 채우고, 검증은 만든 쪽과 분리, 공유 기획 기록이 중심, 사람은 처음과 끝에만.
- 길게 가져갈 구조이지만 발표까지 며칠 남아 빠르게 세운다.

## 목표 (방향성 5개 항목)
1. **총괄 에이전트:** 목표를 받아 다음 할 일을 정하고, 일을 나눠 주고, 결과가 부족하면 해당 에이전트에 다시 맡긴다.
2. **자료 수집 에이전트:** 코스 쪽 요청("평일 밤 후보가 없다", "운영 정보 미확인")을 받아 찾아서 **후보**로 올린다.
3. **검증 에이전트 분리:** 수치 · 출처 등급 · 홍보 표현을 독립적으로 점검하고, 통과하지 못하면 되돌린다. 각 에이전트가 자기 결과에 경고를 다는 방식을 대체한다.
4. **공유 기획 기록:** 조건 · 근거 · 장소 후보 · 코스안 · 경고 · 결정 이력을 구조화된 한 곳에서 읽고 쓴다. 숫자 조회 · 시간표 계산 · 요일 검사는 코드 도구가 맡고 에이전트는 호출만 한다.
5. **사람은 처음과 끝:** 담당자는 목표 · 제약을 주고, 완성 초안과 남은 쟁점을 한 번에 검토해 확정한다. 중간에는 에이전트가 풀지 못한 문제만 올라온다.

자율형으로 가능해지는 것: 되돌아가는 흐름(빈칸 → 수집, 홍보 문제 → 코스, 검증 탈락 → 재작업), 병렬 작업(평일안 · 주말안, 타깃별 안, 언어별 번역).

## 안전장치 (반드시 지킴)
- **권한 분리:** AI가 수집한 정보는 기록의 `후보` 영역에만 쓴다. 확정 자료(장소 CSV · 근거 데이터)는 사람이 승인해야 바뀐다.
- **상한:** 같은 일의 재시도 횟수와 실행당 비용(AI 호출 수 · 토큰)에 한도를 둔다. 넘으면 멈추고 담당자에게 올린다. 기본값은 빌더가 정하고 설정으로 바꿀 수 있게 한다.
- **기록:** 누가(어느 에이전트 · 사람) 무엇을 근거로 무엇을 결정했는지 전부 결정 이력에 남긴다. 공공 결재 문서에 쓰기 위한 필수 조건.

## 하지 않는 것
- 관광객용 화면, 판매 · 예약.
- 확정 자료를 AI가 직접 고치는 것.
- 2단계 기관 자료 RAG(이 구조 위에 다음 작업으로 올림).

## 실패로 보는 것
- 에이전트끼리 긴 글을 주고받거나, 기록 밖에 상태를 두는 것.
- 검증 에이전트가 만든 쪽 결과를 그대로 통과시키는 구조(같은 에이전트가 만들고 검증).
- 한도 없이 되돌아가기가 반복되는 것.
- 담당자 화면에 내부 로그 · 검사 코드가 다시 섞이는 것.

## 방법 (고른 것)
- 검토한 방법: ① 기록부터 만들고 총괄은 코드 규칙 ② 총괄까지 처음부터 AI ③ 지금 구조에 기능만 덧붙이기.
- **결정: ①로 세우고 바로 ②로 교체** (사용자 결정, 2026-11-23). ③은 공유 기록 · 되돌림이 빠져 다시 만들어야 해서 제외. ②를 처음부터 하면 며칠 안에 안정시키기 어려움.
- 핵심: 총괄의 판단을 함수 하나로 분리한다.
  `다음_할일(기록) -> 행동` · 행동 = `수집 | 코스 | 검증 | 홍보 | 담당자에게`(+ 대상 · 이유).
  ①에서는 함수 안이 규칙, ②에서는 AI 호출. 실행 · 한도 · 권한 검사는 항상 코드가 하고, AI가 고른 행동이 허용 메뉴 밖이거나 한도를 넘으면 코드가 막고 담당자에게 올린다. 규칙 버전은 비교 기준 · 예비로 남긴다.

## 진행 순서
1. **공유 기획 기록:** 기획 하나 = 기록 파일 하나(JSON). 영역: `조건` · `근거` · `후보` · `코스안`(여러 안) · `경고` · `결정이력` · `실행`(에이전트 활동 · 재시도 · 비용). 기존 저장본(runs/)을 이 형태로 읽어 오는 변환 도구. 코드 도구(시간표 검사 · 요일 검사 · 운영 검토)는 기록을 입력으로 받게 맞춘다.
2. **수집 · 검증 에이전트 + 규칙 총괄:** 기존 1~4단계 에이전트를 기록을 읽고 쓰는 방식으로 감싼다. 수집 · 검증 에이전트 지침을 새로 쓴다(3 · 4단계 지침은 사람2 담당이라 협의). 규칙 총괄 + 실행기(한도 · 권한 포함).
3. **관리자 창을 기록 뷰로:** 활동 타임라인(에이전트 · 행동 · 이유 · 결과 · 재시도 · 비용), 기록 영역별 표(조건 · 근거 · 후보 · 코스안 · 경고 · 결정), 오류(실패 · 검증 탈락 · 한도 초과). 줄글 원문은 접어 둔다. 담당자 화면은 처음(목표 · 제약 입력 = "새 코스 만들기")과 끝(완성 초안 · 코스안 비교 · 남은 쟁점 · 확정)만.
4. **총괄을 AI로 교체:** 총괄 지침 · 허용 메뉴 검사 · 시험. 병렬 안(평일 · 주말 등)은 총괄이 코스안을 여러 개 요청하는 방식으로.

각 단계는 별도 구현 계획을 쓰고, 끝날 때마다 사이트에서 확인한다.

## 정한 것 (이전 결정 유지)
- 고객 = 대구시 관광 담당자. `/plan/` 담당자 화면, `/admin/` 관리자 창(팀용).
- 지도: OpenStreetMap + 네이버 링크, 네이버 지도 API 키가 생기면 교체. 좌표는 장소 CSV `위도` · `경도`(빈칸 = 미확인, 추정 금지).
- AI 제공자: `.env`의 `AI_PROVIDER`(Gemini 기본).

## 빌더에게 맡기는 것
- 기록 JSON의 세부 필드 이름 · 파일 위치(runs/ 안 또는 옆), 한도 기본값, 관리자 창 레이아웃.
