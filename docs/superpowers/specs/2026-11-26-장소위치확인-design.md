# 장소 위치 확인과 지도 길 자동 수집 (2026-11-26)

## 왜
- 새 장소가 코스에 들어오면 지도에 '경로 미확인'이 뜬다. 길 선에는 확인된 좌표와 도보 경로가 모두 필요하다. 지금은 사람이 `좌표받기.py`·`도로경로.py`를 직접 돌려야 한다.
- 사용자 결정(11/26): 길은 코드가 자동으로 모은다. 좌표는 코드가 찾고, **관리자**가 '맞다'를 누른다. 기획자는 확인 전 장소를 '지도 경로 준비 중'으로 보고, 이상한 위치는 신고만 한다.

## 하지 않는 것
- 확인 없이 자동 좌표를 지도에 쓰는 것. 기획자 화면에서 좌표를 고치는 것.
- 화면 조회·AI 실행 중에 외부 서버에 묻는 것(1분 목표 보호). 외부 조회는 관리자 서버의 뒤쪽 작업에서만, 1초 1회.

## 구성 (`app/장소위치.py`)
- `지도점(이름)`: 지도와 같은 규칙. 장소 CSV의 확인된 좌표, 없으면 `지도_대표위치.json` 중심.
- `확인대기()`: 지도점이 없는 장소 + 열린 신고가 있는 장소. 후보는 `장소좌표_검토용.csv`(팀 검토표)와 `research/data/좌표후보_자동.json`(코드가 찾은 것)에서 보여 준다.
- `후보찾기()`: 확인 대기 장소 중 후보가 없는 곳만 주소 → 이름 순으로 OpenStreetMap에서 찾아 `좌표후보_자동.json`에 저장. 자동 반영 없음.
- `확인(장소명, 위도, 경도, 근거URL, 근거설명)`: 장소 CSV의 좌표·검토 열을 채운다(검토상태 '사람확인완료', 검토자 '관리자(화면)', 위치기준 '시설대표점'). 다른 행·열은 그대로 둔다. 그 장소의 신고는 처리됨.
- `길수집()`: 지도점이 있는 장소끼리 직선 3km 이내 쌍 중 `담당자화면/road-routes.json`에 없는 것만 `도로경로.경로수집`으로 모은다. 실패는 failures에 남기고 다시 묻지 않는다.
- `자동작업`: 서버 시작 때, '맞다' 뒤, 그리고 장소 CSV·지도 대표위치 파일이 바뀔 때(2분마다 수정 시각만 확인, 화면 밖에서 직접 고친 경우 포함) 뒤쪽 스레드로 후보찾기 → 길수집. 한 번에 하나만.
- 신고: `runs/장소위치_신고.json`에 `{장소명, 내용, 시각, 상태}`.

## 화면
- 관리자: `/admin/places-review` "장소 위치 확인". 장소마다 후보 좌표·지도 링크·근거와 '맞다' 버튼, 직접 입력 칸. 위쪽에 자동 작업 상태.
- 기획자: 장소 패널에 '위치가 이상해요' 버튼 → 신고.

## 확인
- 네트워크 없이 가짜 응답으로 단위 시험. CSV는 확인한 행·열만 바뀌는지(다른 바이트 그대로) 시험.
