# 담당자 화면 · 관리자 창 분리 설계 (2026-11-23)

## 왜
- 지금 관리자 화면(`app/관리자화면/`, `/admin/`) 한 곳에 기획 화면과 운영정보·출처·검사·실행 이력이 섞여 있어 무엇을 봐야 하는지 알기 어렵다.
- 고객은 **대구시 관광 담당자**다(관광객은 고객이 아님). 담당자는 결과와 판단 이유만 보고, 로그·오류는 팀이 따로 본다.
- 지금은 AI가 한 번 만들고 담당자가 승인하는 한 방향이라 AI 에이전트의 역할이 보이지 않는다. **"데이터를 분석해 추천하고, 근거가 부족하면 스스로 대안을 내는 순간"**을 화면 중심에 둔다.
- 반영 자료: 팀 피드백(근거 부족 시 B안 · 지도 시간대별 동선 · 다시 만들기), 시안 `app/시안/담당자화면_시안.html`(사용자 확인 완료).

## 목표
1. **화면 분리:** `/plan/` 담당자 화면, `/admin/` 팀용 관리자 창(로그 · 원문 · 검사 결과 · 오류 · 운영정보 상세).
2. **AI 추천 카드:** 조건 · AI가 본 것과 판단(2~3줄) · A안(요청 조건) / B안(근거 부족 시 조건을 바꾼 안) 비교 · 선택.
3. **지도 동선:** 1박2일 일정을 지도에 번호 · 선으로, 옆에 시간표. 장소마다 "네이버 지도에서 열기" 링크.
4. **다시 만들기:** 다른 동선 / 반대 방향으로 다시 생성해 지도에서 비교.
5. **새 코스 만들기:** 저장 목록 옆 버튼 → 조건 입력 → 1~3단계 실행.
6. **시작 장소 정리:** "전체 여행 시작 장소"와 "첫 관광지"를 따로 받지 않는다. 첫 일정 장소 = 시작 장소. 집결 장소가 따로 필요하면 메모로만 남긴다.

## 하지 않는 것 (이번 범위 밖)
- 관광객용 페이지, 판매 · 예약 기능.
- 2단계 기관 자료 RAG(다음 작업으로 따로 설계).
- 4 · 5단계 화면 변경.

## 실패로 보는 것
- 담당자 화면에 검사 코드 · 원문 · 경고 ID 같은 내부 정보가 다시 섞이는 것.
- AI가 만든 B안 · 이유 문장을 출처 없이 사실처럼 보여 주는 것(이유마다 근거 ID 또는 앱 검사 이름을 붙인다).
- 확인되지 않은 좌표 · 이동시간을 확정값처럼 쓰는 것.

## 방법 (고른 것)
- 검토한 방법: ① 지금 앱을 나눠 고치기 ② 담당자 화면 새로 만들기 ③ 시안 먼저. → **③ 시안 확인 후 ①** (사용자 결정).
- ①: 지금 Python 서버(`관리자조회.py`)와 화면 코드를 그대로 쓰고 주소만 나눈다. 기존 검사(요일 · 운영시간 · E7)와 저장 기록을 이어 쓴다.

## 단계별 진행 (각 단계가 끝나면 사이트에서 확인)
1. **화면 분리 + 지도:** `/plan/` 새 화면(시안 디자인), `/admin/`은 기존 화면을 관리자 창으로 정리. 장소 CSV에 `위도` · `경도` 열 추가(값은 네이버 지도로 확인해 입력, 모르면 빈칸 → 지도에서 빼고 "좌표 미확인" 표시). 저장된 코스를 지도 · 시간표로 표시.
2. **새 코스 만들기:** 화면에서 조건 입력 → 서버가 1 · 2단계(`orchestrator` 흐름) → 3단계 실행. 진행 상태 표시. AI 비용 발생 안내.
3. **AI 추천 카드 A/B안:** 3단계가 A안과 함께, 2단계 근거가 약할 때(E3 경고 등) 조건을 바꾼 B안과 "무엇을 왜 바꿨는지"를 낸다. 3단계 지침 수정이 필요해 **사람2와 협의**.
4. **다시 만들기:** 같은 장소로 다른 순서 · 반대 방향 동선을 3단계에 다시 요청(식사 시간 고정, 운영시간 · 요일 검사 재실행).
5. **시작 장소 정리:** 코스 조건 화면에서 시작 장소 입력을 첫 일정과 합침. 기존 저장본은 그대로 읽기.

## 정한 것
- 지도: 시안은 OpenStreetMap(Leaflet). **네이버 지도 API 키를 받으면 네이버 지도로 교체**(키 발급은 사용자). 키 전까지 OpenStreetMap + 네이버 링크.
- 이동시간은 지금처럼 이동시간 CSV 값만 쓴다. 지도 선은 직선이며 실제 경로가 아님을 표시.

## 빌더에게 맡기는 것
- `/plan/` 화면 파일 구성, 기존 `/admin/` 코드에서 기획 부분을 걷어 내는 방법.
- 상태 표시 방식(폴링 등), 지도 마커 · 색 디자인(시안 기준).

## 남은 확인
- 3단계 지침에 B안 · 다시 만들기를 넣는 것은 사람2 담당 영역이라 협의 후 진행.
- 네이버 지도 API 키 발급 여부.
- 장소 좌표 입력 담당(사람1 · 사람2 중).
