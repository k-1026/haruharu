# 수집 · 검증 에이전트 + 규칙 총괄 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 공유 기획 기록 위에서 총괄(규칙)이 다음 할 일을 정하고, 코스 · 수집 · 점검 · 검증 에이전트를 불러 결과를 기록에 쓰며, 부족하면 되돌아가고, 한도에 걸리거나 끝나면 담당자에게 올린다.

**Architecture:** `app/에이전트실행.py`가 기록 조각을 JSON으로 만들어 에이전트를 부르고(기존 `run_stage.단계_실행`), 응답의 JSON 블록을 파싱하고, 한도 확인 · 실행 기록을 맡는다. 에이전트별 처리기(`app/처리기.py`)가 결과를 기록 영역에 쓴다. `app/총괄.py`의 `다음_할일(기록)`은 순수 규칙 함수이고, `돌리기(...)`가 반복 실행기다. 총괄 판단은 다음 계획에서 AI로 교체하므로 `다음_할일`의 입출력을 고정한다.

**Tech Stack:** Python 3 표준 라이브러리, 기존 `run_stage`(Gemini/Claude), unittest(가짜 실행 함수 주입).

**Spec:** `docs/superpowers/specs/2026-11-23-자율형에이전트-design.md` (진행 순서 2)

## Global Constraints
- 총괄 인터페이스(다음 계획에서 AI로 교체): `다음_할일(기록: dict) -> {'행동': '코스'|'수집'|'점검'|'검증'|'담당자에게', '대상': str, '이유': str}`.
- 권한: 수집 결과는 `후보` 영역에만(`기획기록.추가`가 상태를 `후보`로 강제). 에이전트는 `조건`을 바꾸지 않는다. 확정 자료 파일(장소 CSV 등) 쓰기 없음.
- 한도: 모든 AI 호출 전 `기획기록.한도_확인`. 막히면 실행하지 않고 `담당자에게`로 끝내며 사유를 기록.
- 기록: 모든 호출은 `실행_기록`(AI호출=1)으로, 결과 쓰기는 `추가`로 결정이력에 남는다. 에이전트끼리 긴 글을 주고받지 않는다(입력 = 기록 조각 JSON, 출력 = JSON 블록).
- 검증은 만든 쪽과 분리: 검증 에이전트는 별도 지침 파일, 코스 에이전트 결과를 수정하지 않고 판정 · 문제 · 되돌릴 곳만 낸다.
- 수집 에이전트 조회 범위: 이번 계획은 **저장소 안 자료(`research/`)만** Read/Grep/Glob로 찾는다. 웹 검색 허용은 스펙의 남은 확인 항목이라 열지 않는다. 출처 없는 후보는 기록하지 않고 경고로 남긴다.
- 테스트는 가짜 실행 함수로만(AI 비용 0). 실제 AI 실행은 마지막에 사용자 승인 후 한 번.
- 새 지침 파일: `.claude/agents/자료수집.md`, `.claude/agents/검증.md`. 3 · 4단계 지침(`지침/3_코스검토/`, `지침/4_홍보검토/`)은 수정하지 않는다(사람2 담당).
- 커밋 메시지 `종류: 내용` + `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus
- 에이전트 응답에 JSON 블록이 없거나 깨진 경우 → 실행 결과 `실패`로 기록, 기록 영역은 그대로, 같은 일 재시도 한도로 결국 담당자에게. (Task 1)
- 총괄 규칙이 같은 행동을 끝없이 고르는 경우 → `돌리기`의 `최대단계`(기본 12)와 재시도 한도로 멈춤. (Task 5)
- 수집 후보의 출처등급이 `AI 생성` · 빈칸 → 후보로 쓰지 않고 경고. (Task 2)
- 검증이 되돌릴 곳으로 허용 밖 값(`홍보` 등 아직 없는 단계)을 낸 경우 → `담당자에게`로 올림. (Task 4)
- 실행 중 예외(네트워크 등) → 실행 결과 `실패` 기록 후 기록 저장, 예외는 다시 올리지 않고 다음 판단으로. (Task 1)

### Task 5: 규칙 총괄과 실행기

**Files:**
- Create: `app/총괄.py`
- Test: `app/test_총괄.py`

**Interfaces:**
- Consumes: Task 2~4 처리기, `기록도구.코스_점검`, `기획기록.저장 · 한도_확인`
- Produces:
  - `다음_할일(기록) -> dict` 규칙(위에서부터 첫 해당):
    1. 코스안 없음 → `코스`, 대상 `A`
    2. 최신 안의 가장 최근 검증 경고 중 되돌릴곳 `담당자` 있음 → `담당자에게`
    3. 최신 안이 마지막 검증 이후 새 버전이 아니고, 마지막 검증이 반려이며 되돌릴곳 `수집` 있음, 그 뒤 수집 실행 없음 → `수집`(대상 = 문제 내용 합친 요청)
    4. 위 반려에 되돌릴곳 `코스`가 있거나 수집 뒤 → `코스`(같은 안id, 새 버전)
    5. 최신 안 버전에 대한 `코드점검` 경고 없음 → `점검`
    6. 최신 안 버전에 대한 검증 실행 없음 → `검증`
    7. 그 밖(검증 통과) → `담당자에게`, 이유 "검증 통과 · 담당자 검토"
  - `돌리기(기록, runs루트: Path, 실행함수=None, 최대단계: int = 12) -> list[dict]` — 단계마다 `다음_할일` → 처리기 → `저장`, 반환은 고른 행동 목록. `담당자에게`이거나 처리기가 한도로 보류하면 멈춤. 마지막에 `결정이력`에 `행동='담당자에게'`(이유 포함) 한 줄.
  - CLI: `python 총괄.py <기록id> [--모의]` — `--모의`는 정해진 가짜 응답(코스 → 검증 반려(수집) → 수집 → 코스 → 검증 통과)으로 돌려 흐름만 보여 줌, AI 비용 0.

- [ ] Step 1: 테스트 — 규칙 표 각 줄(7개)을 기록 상태로 만들어 `다음_할일` 결과 확인; `돌리기`를 `--모의` 응답으로 돌리면 행동 순서 `코스, 점검, 검증, 수집, 코스, 점검, 검증, 담당자에게`; 검증이 계속 반려하는 가짜 함수 → 재시도 한도로 `담당자에게` 종료 · 최대단계 이하.

- [ ] Step 4: PASS + 전체 PASS

- [ ] Step 6: 커밋 `feat: 규칙 총괄과 되돌림 실행기 추가`
