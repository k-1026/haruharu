# 공유 기획 기록 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 기획 하나를 구조화된 기록 파일 하나로 다루는 모듈을 만들고(권한 · 한도 · 결정 이력 포함), 기존 저장본을 이 형태로 가져오고, 코드 도구가 기록을 입력으로 받게 한다.

**Architecture:** 새 모듈 `app/기획기록.py`가 기록의 생성 · 저장 · 읽기 · 쓰기(권한 검사) · 실행 기록 · 한도 확인을 맡는다. 모든 쓰기는 `결정이력`에 한 줄씩 남는다. `app/기록가져오기.py`가 runs/의 기존 저장본을 기록으로 변환하고, `app/기록도구.py`가 기존 검사 함수(`운영검토.출발가능요일` · `시간표검사.시간표_검사`)를 기록 기준으로 감싼다. 에이전트 · 총괄 · 화면은 이후 계획.

**Tech Stack:** Python 3 표준 라이브러리(json, pathlib, datetime, unittest, tempfile).

**Spec:** `docs/superpowers/specs/2026-11-23-자율형에이전트-design.md` (진행 순서 1)

## Global Constraints
- 기록 영역: `조건` · `근거` · `후보` · `코스안` · `경고` · `결정이력` · `실행` (+ `기록id` · `버전` · `목표` · `한도` · `생성시각`).
- 권한 분리: 작성자 문자열은 `사람:<이름>` 또는 `에이전트:<이름>` 또는 `코드:<이름>`. **`조건`은 사람만 쓴다.** 에이전트가 `후보`에 쓴 항목의 `상태`는 항상 `후보`이며, `승인`으로 바꾸는 것은 사람만 가능. 확정 자료 파일(장소 CSV 등)은 이 모듈이 절대 쓰지 않는다.
- 기록: 모든 쓰기 · 승인 · 실행은 `결정이력`에 `{시각, 작성자, 행동, 영역, 대상id, 근거, 요약}`으로 남는다. 결정이력은 추가만 하고 수정 · 삭제하지 않는다.
- 상한: `한도` 기본값 `{'같은일_재시도': 2, 'AI호출': 30}`(설정으로 변경 가능, 스펙은 숫자를 빌더에 맡김). 넘으면 실행하지 않고 사유를 돌려준다.
- 기존 runs/ 저장본은 읽기만 한다. 가져온 기록은 `runs/기획/<기록id>/기획기록.json`에 새로 쓴다.
- 커밋 메시지 `종류: 내용` + `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus
- 저장 도중 실패로 파일이 반쯤 써진 경우 → 임시 파일에 쓰고 교체해 기존 기록이 깨지지 않음. (Task 1 테스트: 저장 실패 시 기존 파일 유지)
- 에이전트가 `조건`을 바꾸거나 후보를 `승인`으로 쓰려는 경우 → `PermissionError`, 결정이력에도 남지 않음. (Task 1)
- 같은 기록을 두 번 가져오기 → 덮어쓰지 않고 오류(기존 기록 보존). (Task 3)
- 저장본에 3단계 결과가 없거나 JSON이 아닌 경우 → `코스안` 빈 목록, `경고`에 "코스 결과 없음"으로 가져옴. (Task 3)
- 기록id에 `..` · `/` → `ValueError`. (Task 1)

### Task 1: 기록 구조 · 저장 · 권한 쓰기

**Files:**
- Create: `app/기획기록.py`
- Test: `app/test_기획기록.py`

**Interfaces:**
- Produces:
  - `새_기록(조건: dict, 작성자: str, 목표: str = '', 기록id: str | None = None) -> dict` — 작성자는 `사람:`로 시작해야 함. 기록id 기본값은 `YYYYMMDD_HHMMSS_<6자리>`. 결정이력 첫 줄 `행동='생성'`.
  - `저장(기록: dict, 루트: Path) -> Path` — `루트/기획/<기록id>/기획기록.json`, UTF-8, `ensure_ascii=False`, 임시 파일 후 `replace`.
  - `읽기(루트: Path, 기록id: str) -> dict`
  - `추가(기록, 영역: str, 항목: dict, 작성자: str, 근거: str = '') -> str` — 항목에 `id`(영역 접두 + 순번, 예 `후보-3`) · `작성자` · `시각` 부여, 에이전트가 `후보`에 쓰면 `상태='후보'` 강제. 반환 id. 허용 영역: `근거 · 후보 · 코스안 · 경고`.
  - `조건_변경(기록, 값: dict, 작성자: str, 근거: str)` — 사람만.
  - `승인(기록, 후보id: str, 작성자: str, 근거: str)` — 사람만, 상태 `후보 → 승인`.
  - 위반은 `PermissionError`, 잘못된 영역 · id는 `ValueError`.

- [ ] Step 1: 테스트 — 생성 후 영역 키 전부 존재 · 결정이력 1줄; 에이전트 `후보` 추가 시 상태 `후보`(항목에 `상태='승인'`을 넣어도); 에이전트 `조건_변경` · `승인` → PermissionError이고 결정이력 길이 불변; 사람 승인 후 상태 `승인` · 결정이력에 `행동='승인'`; `저장`→`읽기` 왕복 동일; 기록id `../x` → ValueError; `json.dump`를 패치해 예외 → 기존 파일 내용 유지.
- [ ] Step 2: 실행 `app\.venv\Scripts\python.exe -m unittest test_기획기록 -v` (app 폴더) → FAIL(모듈 없음)
- [ ] Step 3: 구현
- [ ] Step 4: 같은 명령 PASS + 전체 `-m unittest discover -p "test_*.py"` PASS
- [ ] Step 5: 커밋 `feat: 공유 기획 기록 모듈(권한·결정 이력) 추가`

### Task 2: 실행 기록 · 한도

**Files:**
- Modify: `app/기획기록.py`
- Test: `app/test_기획기록.py`

**Interfaces:**
- Produces:
  - `한도_확인(기록, 에이전트: str, 행동: str, 대상: str = '') -> tuple[bool, str]` — `실행`에서 같은 (에이전트, 행동, 대상)의 `결과='실패'|'반려'` 횟수가 `같은일_재시도` 이상이면 `(False, '재시도 한도 …')`; `AI호출` 합이 한도 이상이면 `(False, 'AI 호출 한도 …')`.

- [ ] Step 3: 구현
- [ ] Step 4: PASS + 전체 PASS

### Task 3: 기존 저장본 가져오기

**Files:**
- Create: `app/기록가져오기.py`
- Test: `app/test_기록가져오기.py`

**Interfaces:**
- Consumes: Task 1 `새_기록 · 추가 · 저장`
- Produces: `가져오기(runs루트: Path, 시험id: str, 작성자: str = '사람:가져오기') -> dict` 와 CLI `python 기록가져오기.py <시험id>`(저장 경로 출력).
  - `조건` = 원본 `1단계_선택.json`의 `조건` + 시험 `3단계_입력.json`의 `코스작성조건`(키 `코스작성조건`).
  - `근거` = `3단계_전달_준비.json`의 `근거목록` 각 항목(작성자 `코드:가져오기`, 근거 필드에 원래 ID 보존).
  - `경고` = `경고목록` + 코스 `남은경고`.
  - `코스안` = `[{'안id':'A','코스':<3단계_결과.md JSON>,'출처시험id':시험id}]`.
  - 결정이력 각 줄의 `근거`에 원본 파일 경로.
  - 시험id = `<실행>/<회차>/통합시험_*`; 원본 = 앞 두 조각.
  - 기록id = 시험id의 마지막 조각; 같은 기록이 이미 있으면 `FileExistsError`.

- [ ] Step 1: 테스트 — 임시 runs/에 최소 저장본(1단계_선택 · 3단계_전달_준비 근거 2 · 경고 1 · 시험 폴더 3단계_입력 · 3단계_결과 칸 1 · 남은경고 1) 만들고: 근거 2 · 경고 2 · 코스안 1 · 조건에 `코스작성조건`; 결과 파일 없을 때 코스안 0 · 경고에 "코스 결과 없음"; 두 번째 가져오기 FileExistsError; 원본 파일 수정시각 불변.
- [ ] Step 2: FAIL 확인
- [ ] Step 3: 구현
- [ ] Step 4: PASS + 전체 PASS
- [ ] Step 5: 실제 12:10 저장본으로 CLI 실행 → 기록 파일 생성 · 근거 200 · 코스안 1 확인(출력 기록)
- [ ] Step 6: 커밋 `feat: 기존 저장본을 공유 기획 기록으로 가져오기`
