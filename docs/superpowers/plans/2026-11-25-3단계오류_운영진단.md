# 3단계 실행 오류와 운영 진단 구현 계획

사용자 요청: 긴 명령행 때문에 중단되는 3단계를 수정하고 서비스 운영자용 관리자에서 실패 단계·원인을 즉시 파악한다. 기획 직원의 화면과 구분한다.

설계: 지침 축약 대신 SDK의 system prompt 파일 입력을 사용해 내용을 보존한다. 호출별 임시 파일을 만들고 정상·오류·취소 때 정리한다. 관리자 화면은 상태 배지, 단계 목록, 실패 원인/조치 카드, 접힌 원문 순서다. 기존 실패 기록은 수정하지 않고 읽어서 요약한다. 전달 검사와 실행 결과를 구분한다.

- [x] 긴 한국어 지침의 SDK 명령행 크기·내용 보존·실패/취소 정리 회귀 시험 → 실패 확인 → 파일 전달 구현.
- [x] 과거 하위 오류·최신 시험 선택·오류 없는 중단·깨진 JSON 시험 → 실패 확인 → 읽기 전용 운영 진단 API 구현.
- [x] 관리자 목록 상태·첫 실행 자동 선택·단계/원인 카드·원문 접기 구현과 검증.
- [x] 관련 시험·전체 시험 시도·실제 화면 확인, 유휴 서버 반영, 작업현황·반영 목록 기록.

검증: 선택 Python 64개·Node 65개 통과. 전체 Python 284개 중 기존 실패 1·fixture 누락 오류 2는 작업현황에 이름과 사유를 기록했다. 8790 실제 HTTP와 IAB의 최신 실패/완료 전환·상세 오류·반응형 배치를 확인했다. 실제 AI 실행은 하지 않았다.

기존 개인 체크아웃의 미커밋 변경을 보존한다. 실제 AI 호출·설정 변경·commit·push는 범위에 넣지 않는다. 사용자가 바로 수정을 지시한 범위의 구현 결정을 적용하며 별도 디자인 승인 대기는 하지 않는다.
