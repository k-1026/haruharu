# 일정 시간·걷기 표시 Implementation Plan

> 실행: 이 세션에서 직접 순서대로 구현한다. 별도 에이전트·실제 AI 실행·커밋·push·네이버 API 연결 없음.

**Goal:** 코스 일정 시각에 맞춰 지도 분위기를 자연스럽게 바꾸고 걷기 경로·마커를 작고 명확하게 정리한다.

**Architecture:** 순수 지도 모델에서 일정 시각 보간과 둥근 경로 geometry를 계산한다. Three.js와 SVG 대체 지도는 같은 경로 좌표와 보간 시각을 사용한다. 화면의 현재 시각·외부 API를 사용하지 않는다.

**Tech Stack:** 기존 JavaScript·Three.js·SVG·CSS·Node test.

**Spec:** 이번 사용자 요청. 경로 #E39432, 크림 테두리 #FFF9EF, 예정 경로 #F5D4A8, 작은 방향 화살표만 #29324A. 기본 안쪽 5~6px, 테두리 포함 9~10px. 오후부터 저녁으로 전환하고 도로·동선은 밝게 유지한다. 큰 입체 핀/화살표·권역 링은 없앤다. 코스·좌표·확정 상태와 다른 작업의 변경은 보존한다.

## Review Focus

- 시각 미정·오류는 현재 시각으로 채우지 않고 '시각 미정 · 낮 기준'으로 표시한다.
- 다음날 오전 선택은 다시 낮으로 전환한다. 자정 통과 구간은 올바르게 보간한다.
- 지나온 길은 선택한 재생 범위만 강조하며 단일 구간 재생으로 앞 구간까지 방문한 것으로 표시하지 않는다.
- 캐릭터와 진행 표시는 같은 실제 경로의 누적 거리 보간을 사용한다.
- 가까운 시점에서 고정 크기 번호 마커·작은 화살표·그림자가 장애물처럼 커지지 않아야 한다.

## 구현 중 확인

### 후속 요청: 속도·하늘·장소 맥락

- 긴 구간을 24초에 압축하지 않는다. 지도 미리보기 기본 속도는 거리 기준 25m/s(실제 걷기 아님)로 낮추며 1×/2×/4× 조절을 제공한다. `previewSeconds(distanceMetres,speed)`를 먼저 시험한다.
- 카메라는 수평선이 보이도록 pitch를 낮추고 하늘색·옅은 원경 안개를 시간대에 맞춘다. 가까운 도로/동선 대비는 유지한다.
- 걷기 중 화면에 들어오는 장소 이름을 유지하며 출발→다음 장소·남은 거리·구간 진행을 상시 안내한다. 화면 밖 장소로 마커를 임의 이동하지 않는다.
- 사용자 요청으로 캐릭터 상하 바운스·추가 다리 진동을 없애고 원본 걷기 GIF만 사용한다.
- 최종 실제 화면 확인을 사용자가 허용했으므로 같은 로컬 코스로 근접 시점·오후→저녁·이름·속도·정지 상태를 확인한다. 실제 AI·커밋 없음.

- Node 65개·JS 구문·diff 공백 검사 통과. 백엔드 변경 없음.
- Chrome에서 새 번호/식사 마커·작은 방향 화살표·크림/오렌지 경로, 20:00 야시장 선택 시 저녁 지도와 도로 대비, 가까운 정면 걷기 시작과 설명 패널 자동 숨김을 확인했다.
- 걷기 화면에서 CSS의 `display:flex`가 `hidden`을 덮어 출발 마커가 남는 문제를 발견해 명시적인 숨김 규칙으로 고쳤다. 원본 GIF의 회색 배경·가로 여백은 원본을 수정하지 않고 CSS 자르기와 부드러운 타원 마스크로 완화했다. 완전 투명한 3D 모델/모션으로 바꾼 것은 아니다.
- 다른 창의 화면 조작과 겹쳐 최종 가까운 걷기·오후 전환 재확인은 사용자에게 확인 가능한 시점을 요청한 상태다. SVG 대체 모드 육안 확인도 별도다. 실제 AI·커밋·push 없음.

### 추가 요청: 원본 보존 투명 모션

- 원본 GIF 6개는 유지하고 Windows 기본 이미지 처리와 코드로 투명 APNG를 별도 생성한다. C# 변환기·파생본/원본 해시 manifest·프레임/간격/투명도 시험을 추가한다. 실제 AI·외부 이미지 API·패키지 설치는 하지 않는다.
- WebGL와 SVG 대체 지도를 파생 파일에 연결하고 원형/회색 타원 마스크를 제거한다. 작은 그림자는 유지한다. 짧은 창에서 진행 안내가 캐릭터 발을 가리지 않도록 위로 배치한다.
- 치킨 이모티콘은 메뉴 확정으로 오해할 수 있어 중립적인 '식사'로 교체한다. 발자국은 사용자 검토 중이며 현재 구현/기본 표시에 추가하지 않는다.
- 도보 geometry는 유지한다. 강사 참고 코드의 예시 곡선과 구분하며 대중교통 경로는 아직 미연결이다. 지도를 더 귀엽게 꾸미는 전체 디자인 변경으로 확대하지 않는다.

- 투명 APNG 6개 생성·연결 완료. SHA-256·원본 GIF/APNG의 30프레임·간격·PNG CRC/순서·투명 픽셀·캐릭터 픽셀 검사 통과. Windows 기본 API로 처리했으며 실제 AI·외부 API·패키지 설치 없음.
- Chrome에서 최신 파일을 읽어 정면·뒤/옆면의 투명한 걷기, 꼬리·발·그림자와 중립적인 '식사' 표시를 확인했다. 짧은 창에서 진행 안내를 위로 옮겨 발을 가리지 않도록 했다. SVG 대체 모드는 코드 연결/구문 검사이며 이번 육안 점검은 WebGL이다.
- 최근 기획이 '멈춤'인 것과 서버 명령을 확인한 후 8790 서버만 재시작했다. 새 서버 PID 17636·파생 모션 HTTP 200(image/png)을 확인했다. Node 66개·관련 Python 8개·C# 자체 시험·diff 공백 검사 통과. 기존 삭제 파일·무관한 변경 보존, 실제 AI 실행·커밋·push 없음.

### 이전 요청의 최종 후속 확인

- 사용자가 화면 확인을 허용한 뒤 열려 있는 다른 Chrome의 로컬 코스 탭에서 최신 파일을 강력 새로고침했다. 위의 가까운 화면/오후 전환 확인 대기는 이번 검증으로 해소했다. 최소화된 별도 창과 예전 파일이 남은 Aside 화면을 최신 검증 화면으로 취급하지 않았다.
- 정면과 따라보기에서 하늘·원경 안개·캐릭터·장소 이름·출발→도착·남은 거리/진행 표시를 확인했다. 멀리 모이는 화살표는 현재 구간 주변만 표시하고, 캐릭터 얼굴과 겹치는 이름표를 위로 배치했다. 프로그램의 상하 바운스·다리 진동은 제거했으며 원본 GIF의 걷기 모션은 유지한다.
- 1× 재생에서 14:44 오후와 남은 거리 감소를 관찰했고, 점검을 위해 4×로 가속해 18:00 저녁 도착을 확인했다. 최신 버전 재검증에서도 18:00·'도착했어요'·비활성 '재생 완료'를 확인했다. 기본 재생 속도는 새 지도 진입 시 1×이며 점검이 끝난 열린 탭은 4×/재생 완료 상태다.
- 도착 직전 반올림한 100%가 도착 갱신을 막는 문제를 수정했다. 진행률은 도착 전 99% 이하로 표시하고 도착 이벤트에서 안내를 강제로 갱신한다.
- Node 66개, 지도 JS 구문, diff 공백 검사 통과. SVG 대체 모드의 색·속도·진행 규칙은 구현/구문 확인이며 이번 육안 검증은 WebGL 모드다. 원본 GIF 배경 잔여·실제 입구/현장 통행·다른 화면 크기는 별도 한계다. 실제 AI 실행·커밋·push 없음.
