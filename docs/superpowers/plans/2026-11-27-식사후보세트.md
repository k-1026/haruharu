# 식사 후보 세트 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 저녁은 치킨 1곳 이상이 필수인 정식 후보 세트(시스템 제안 + 직원 수정 → 관광객 선택)로, 점심은 선택 사항으로 바꾸고, 시장은 구역형 카드로 따로 표시한다.

**Architecture:** 기존 `app/단계3_코스검토/식사선택.py`의 `비교`·`묶음반영`·`관광객묶음`을 확장해 저녁에도 후보 묶음을 쓰게 하고, 후보에 `분류`·`구역형`·`치킨` 값을 붙인다. 직원 화면(`plan.js`)은 이 값만 보고 체크 가능 여부를 정하며, 규칙 검증은 서버가 계속 맡는다.

**Tech Stack:** Python 3 + unittest(`python -m unittest discover -s app -p "test_*.py" -q`), 브라우저 JS(`app/담당자화면/*.js`, node `.cjs` 시험), CSV 장소 자료.

**Spec:** `docs/superpowers/specs/2026-11-27-식사후보세트-design.md`

## Global Constraints

- 저녁 세트 저장은 치킨 후보(구역형 제외) 0개면 거절한다. 치킨이 여러 곳인 것은 허용한다.
- 점심에는 치킨 식사를 넣지 않는다(기존 `(치킨 옵션)` 점심 제외 규칙 유지). 점심은 치킨 필수·최소 개수 규칙을 적용하지 않는다.
- 시장(`장소유형=='시장'`)은 구역형이며 치킨 필수 조건과 "바로 담기 가능"에 세지 않는다.
- 후보 수 상한 12개 유지. 직원 저장 없이도 공통 코스는 변경하지 않는다(관광객 선택은 개인 지도에만).
- 도보 N분 기본값은 20분이며 임시 제안값이다(화면에서 "임시 기준" 표시, 직원이 바꿀 수 있게는 하지 않고 서버 인자로만 둔다).
- 장소 자료 CSV(`research/data/장소운영정보_중구동구_데모코스_2026.csv`)에는 메뉴 분류 열이 없다. 설문 메뉴 매칭은 이번 범위에서 제외하고 `메뉴그룹`은 만들지 않는다(후속).
- 파일 수정은 개인 브랜치. 커밋은 사용자 확인 후.

## Review Focus

- 후보 중 치킨이 전부 "담을 수 없음"인 저녁: 저장 불가이며 이유를 화면에 보여 준다(Task 2, 4).
- 식사 기준 장소가 서문시장(시장)인 점심: 구역형 카드 1장, 식당 후보와 이름이 겹치지 않는다(Task 1, 3).
- 후보 0개로 저장한 점심(또는 저장 안 한 점심): 오류 없이 "자유롭게 해결"만 표시(Task 5).
- 기존에 저장된 점심 `후보묶음` 데이터(2곳 이상)가 그대로 열린다(Task 2).
- 같은 후보 중복 선택, 이동시간 자료 없는 후보: 기존처럼 거절/비활성(Task 2).
