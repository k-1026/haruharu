# 3단계 주문서 + 코드 조립 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 3단계에서 AI는 짧은 주문서(장소 P번호·머무는 시간·근거·운영주체·한 줄 이유)만 쓰고, 코드가 지금 형식의 완성 코스 JSON을 조립해 AI 호출 한 번을 60초 안에 끝낸다.

**Architecture:** 새 모듈 `app/코스조립.py`가 ① 후보표 만들기 ③ 주문서 검사 ④ 조립을 맡는다. ②는 새 지시문 `.claude/agents/코스주문.md`로 한 번 호출한다. 관리자 3단계(`관리자실행.py`)와 자율 흐름(`처리기.py`)이 같은 함수를 부른다. 조립 결과는 기존 `단계연결.코스_검사`·`시간표검사.시간표_검사`·화면이 그대로 읽는 형식이다.

**Tech Stack:** Python 3 표준 라이브러리(csv·json·re·unittest), 기존 `run_stage`/`에이전트실행` AI 호출.

**Spec:** `docs/superpowers/specs/2026-11-25-3단계주문서조립-design.md`

## Global Constraints

- AI 제한 시간: `run_stage.역할_제한초['코스주문.md'] = 60`. 늘리지 않는다.
- 목표 크기: AI가 받는 글 ≤ 15,000자, AI가 쓰는 주문서 ≤ 3,000자(시연 1박2일 A/B 기준).
- 장소 후보 상한: 설정 `HARUHARU_COURSE_CANDIDATES`, 기본 30. 근거 후보 상한 40.
- 지침 `지침/3_코스검토/*.md` 12개와 `.claude/agents/코스검토.md`는 수정하지 않는다(읽기만).
- 장소명·운영시간·이동시간 같은 사실 값은 코드만 쓴다. 틀린 주문서는 추측해서 고치지 않고 문제 목록으로 돌려준다. 자동 재호출은 하지 않는다.
- 동명 방지: 조립한 장소명은 `대구광역시 ○○구 <괄호 앞 이름>` 형태.
- 이름 맞추기: `장소정보._이름()`(괄호·접두 제거)만 쓴다. 같은 정규화 이름이 둘 이상이면 맞추지 않고 `미확인`.
- 치킨 장소 = 장소명에 `(치킨 옵션)`. 가족 코스는 장소를 빼지 않고, 주문서 `이유`에 `맥주|치맥|술|주점`이 있으면 문제.
- 시각: 담당자 시작시각이 있으면 `확정`, 없으면 `10:00` `가정`. 이동은 대중교통분 → 없으면 도보분 → 둘 다 없으면 다음 칸 시각 `미정`.
- 확정조건은 담당자 입력과 C6·C7 결과로만 true. 꾸미지 않는다.
- 저장: 주문서 원문 `3단계_주문서.json`, 후보표 `3단계_후보표.json`, 조립본 `3단계_결과.md`·`3단계_구조화.json`.
- 팀 규칙: 커밋 메시지 `feat:`/`fix:`/`docs:` + 한국어. **커밋 전 바뀐 파일과 메시지를 사용자에게 보여 주고 확인을 받는다**(CLAUDE.md 6장). 무관한 기존 변경은 커밋에 넣지 않는다.
- **시작 전 확인:** 작업 트리에 사용자의 커밋 안 된 변경이 있다(`app/총괄.py`·`근거추출.py`·`기획실행.py`·`대안비교.py` 등). 그중 `총괄.py`는 Task 7이 고친다. 시작 전에 사용자에게 그 변경을 먼저 커밋할지, 아니면 이 작업을 새 worktree에서 할지 묻는다.
- 이미 실패하던 시험 3개(마지막 커밋 cda35b8에서도 실패): `test_기존결과`·`test_흐름`(삭제된 `시험자료/실제_2단계결과_20261122.md`를 찾음), `test_관리자실행.test_실행실패는_민감정보없이_보존`(오류 메시지 원문이 상태에 저장됨). 이 계획의 통과 기준은 "이 3개 외 전부 통과"이며, 이 3개를 새로 깨뜨리거나 고친 척하지 않는다.
- 시험 실행 위치: `app/` 폴더. 단일 `python -X utf8 -m unittest test_코스조립 -v`, 전체 `python -X utf8 -m unittest discover -p "test_*.py"`, 화면 `node --test test_담당자표시.cjs`.

## Review Focus

1. **장소 CSV가 커질 때** — 300행으로 부풀려도 후보표 글자 수가 30곳 기준과 같아야 한다(Task 1 `test_후보표는_데이터가_커져도_상한을_지킨다`).
2. **AI가 코드블록·설명문을 섞어 답할 때** — 주문서 앞뒤에 문장이나 ```json 블록이 있어도 `에이전트실행.JSON_꺼내기`로 읽혀야 한다(Task 2 `test_설명문이_섞인_주문서도_읽는다`).
3. **이동 CSV에 없는 구간** — 다음 칸 시각을 지어내지 않고 `미정`, 그 뒤 칸도 `미정`이어야 한다(Task 3 `test_이동시간이_없으면_다음칸부터_미정`).
4. **B안 바꾼칸이 A의 시간 흐름을 바꿀 때** — B안 시각은 B안 기준으로 다시 계산되어야 한다(A 시각 복사 금지, Task 5 `test_B안은_시각을_다시_계산한다`).
5. **이전 버전 장소가 후보 상한 밖일 때** — 고쳐 쓰기·부분수정에서도 이전 장소의 P번호가 있어야 한다(Task 1 `test_이전코스_장소는_항상_후보에_들어간다`).
