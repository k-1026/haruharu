# 하네스 — 2~5단계를 실제 AI로 시험하고 점수표 남기기

## 무엇인가
정해 둔 시험 상황으로 **실제 AI**를 불러 단계 결과(수요 요약·코스·홍보 문구·결재 파일)를 만들고, 시간과 규칙 위반을 **점수표**로 남기는 코드입니다.
지시문이나 코드를 고친 뒤 "나아졌나, 나빠졌나"를 숫자로 보려고 씁니다.

| 검사 | 무엇으로 | 하는 일 |
|---|---|---|
| 회귀테스트 `app/시험/test_*.py` | 가짜 AI | 부품이 깨지지 않았나 |
| 제품 안 검증(총괄·검증 에이전트) | 실제 AI | 코스 한 개를 그때그때 고침 |
| **하네스(여기)** | 실제 AI | 제품 밖에서 손님처럼 시험하고 점수를 남김 |

> 왜 따로 필요한가: 11/25에 3단계가 60초 제한에 걸려 멈췄지만 가짜 AI 시험 391개는 모두 통과했습니다. 가짜 AI는 시간이 걸리지 않으니까요.

## 언제 돌리나 (항상 돌리지 않음 — 토큰이 듭니다)
- 지시문(`지침/`, `.claude/agents/`)을 고쳤을 때
- 코스 코드(`app/단계3_코스검토/`)나 홍보 코드(`app/단계4_홍보검토/`)를 고쳤을 때
- 장소·이동 CSV를 고쳤을 때
- 발표 전 확인

## 한눈에: 시험 상황 5개 (`--상황` 이름)
| 단계 | 상황 이름 | AI | 1회 시간 |
|---|---|---|---|
| 2 수요 근거 | `일본인커플_중구_가을_1박2일_수요` | 요약 1번 (제한 30초) | 약 15초 |
| 3 코스 | `일본인커플_중구_가을_1박2일` (기본, 치킨 빼기) | 주문서 1번 (제한 60초) | 약 25초 |
| 3 코스 | `일본인커플_중구_가을_1박2일_치킨선택` | 주문서 1번 | 약 30초 |
| 4 홍보 | `일본인커플_중구_가을_1박2일_홍보` | 홍보 1~2번 (제한 420초) | 약 2분 |
| 5 산출물 | `일본인커플_중구_가을_1박2일_산출물` | 없음 (토큰 0) | 1초 미만 |

1단계는 AI 없이 코드로만 조건을 확인해서 하네스가 따로 없습니다(2단계 하네스가 1단계 코드도 같이 돌림).
고친 단계만 돌리면 됩니다. 발표 전에는 다섯 개를 한 번씩 돌리세요.

```powershell

```
```powershell
python -m app.하네스.돌리기 --반복 3
```
```powershell
python -m app.하네스.돌리기 --상황 일본인커플_중구_가을_1박2일_치킨선택
```
- 시험 상황 2개: 기본(치킨 빼기 — `/plan/` 기본값은 11/26부터 치킨 선택이라 일부러 빈칸으로 덮어씀) · `_치킨선택`(담당자가 치킨 저녁을 고름 → 후보표와 저녁 바꾸기 후보에 치킨이 뜨는지 확인). 점수표 비교는 같은 상황끼리만 합니다.
- 1회에 3단계 AI 호출 1번(약 25초, 받은 글자 약 8천·쓴 글자 약 1.3천)입니다.
- AI 답은 매번 달라질 수 있어서, 규칙은 "N번 중 몇 번 지켰나"로 봅니다. 발표 전에는 `--반복 3`을 권합니다.

## 3단계 — 무엇을 채점하나 (코드만, 토큰 0)
| 항목 | 기준 | 어디서 |
|---|---|---|
| 시간 | 3단계 AI 응답 60초 이하 | `3단계_크기.json` |
| 크기 | 받은·쓴 글자 수 (기록만, 목표 받은 1.5만·쓴 3천) | `3단계_크기.json` |
| 형식 | 조립되고 제품 형식 검사(`단계연결.코스_검사`) 통과 | `3단계_전달_검사.json` |
| 치킨 | 담당자가 골랐을 때만, 안마다 저녁 1번까지 | 채점.py |

| 후보표 밖 | 숙박·2일차오전 고정칸 외 장소가 모두 후보표 안 | 채점.py |
| 숙박 | 1박2일이면 숙박 칸 있음 | 채점.py |

실패·중단이면 `AI_오류.json` 내용이 점수표에 그대로 들어갑니다.

## 2단계(수요 근거) — 돌리기와 채점
```powershell
python -m app.하네스.돌리기 --상황 일본인커플_중구_가을_1박2일_수요
```
- 경로: 담당자 화면(`/plan/`)과 같은 `기획실행._단계작업`을 1단계(코드)·2단계(AI 요약)까지만 돌리고 멈춥니다. 가상설문 CSV는 화면과 같은 업로드 코드로 올립니다.
- 이 단계는 고정본을 쓰지 않습니다. 2단계 결과가 바로 시험 대상이기 때문입니다.

| 항목 | 기준 |
|---|---|
| 시간 | 요약 AI 30초 이하 |
| 형식 | 요약 JSON이 읽히고, 3단계로 넘기는 검사(`전달_검사`) 통과 |
| 기관 자료 | 가상설문 행이 조건에 맞게 적용됨 (적용 행 수 > 0) |
| 숫자 | 요약에 나온 숫자가 AI에 준 근거·조건 안에 모두 있음 (지어낸 숫자 없음) |

## 4단계(홍보) — 돌리기와 채점
```powershell
python -m app.하네스.돌리기 --상황 일본인커플_중구_가을_1박2일_홍보
```
- 입력 고정본: 11/26 담당자가 확인을 마친 코스(`최신기획` B안 2버전, 톤 A+B, SNS 카드뉴스·리플릿)와 그 근거목록. 1~3단계 AI는 부르지 않습니다.
- 11/27 제품 변경(확정 코스 홍보 직결)에 맞춤: 홍보 화면이 시작·종료·둘째 날 오전·겹침을 다시 묻지 않으므로, 하네스도 확정 코스를 `_확정코스`(그대로 복사)로 넘기고 담당자 선택은 톤앤매너·홍보물만 씁니다. 고정본 `3단계_확정.json`은 예전 흐름에서 만든 것이라 '확정조건'·담당자결정 3줄이 남아 있습니다(내용 영향 없음, 다음에 새 실행으로 바꾸면 됨). 11/27 실제 실행: 124.1초, 7개 모두 통과.
- 경로: 담당자 화면 '홍보물 만들기'와 같은 `홍보실행._실행`(AI 1번 → 제품 검사 → 걸리면 한 번 다시 쓰기). 하네스는 AI 호출 앞뒤로 시간만 잽니다.
- 시간이 깁니다: 제품 제한이 호출 한 번에 **420초**(`run_stage.py`)이고, 11/26 실제 실행은 110초였습니다. 다시 쓰기까지 가면 AI를 2번 부릅니다.
- 받은 글자는 요청문+에이전트 본문만 셉니다(에이전트가 도구로 읽은 지침 파일은 못 셈).

| 항목 | 기준 | 어디서 |
|---|---|---|
| 시간 | AI 호출마다 420초 이하, 오류 없음 | `하네스_크기.json` |
| 형식·참조 | 제품 검사(`단계연결.홍보_검사`: 장면ID·번역 상태·상호·용어집·출처ID) 통과 | `4단계_검사.json` |
| 첫 시도 통과 | 다시 쓰기 없이 한 번에 통과 (지시문이 잘 먹히는지) | 호출 횟수 |
| 내부 표시 | 관광객이 보는 글(제목·본문·말풍선·번역·코스카드)에 R53 같은 근거 ID·'미확인'·'AI 초안' 없음 | 채점_4단계.py |
| 금지 표현 | `지침/4_홍보검토/5_표현_필터.md` 1장의 낱말(최고의·원조·최초·365일·치킨의 수도 등) 없음. 번역은 역번역으로 봄 | 채점_4단계.py |
| 번역 | 조건 언어권 언어만, 모든 장면에 번역 | 채점_4단계.py |
| 식비 | "식비 미정·포함 여부" 안내 없음 (앱은 식사 미제공 → 개별 결제) | 채점_4단계.py |

코드로 못 보는 것(다음에 `.claude/agents/검증.md`로): 스토리가 사실인지, 수치가 근거표와 같은지, 출처 등급이 맞는지.

**AI에 보내는 글이 큽니다 (11/27 측정, 약 18.7만 자):** 근거목록 약 10만 자(362행) · 지침 동봉 약 6.7만 자 · 확정 코스 약 1.9만 자(남은 경고 1.1만 자). 줄이는 후보: ① 코스 장소의 근거만·필요한 칸만 보내기 ② 지침 중 이 코스에 해당하는 줄만 보내기 ③ 3단계처럼 'AI는 짧게, 코드가 조립'. 제품 코드(`홍보실행._요청`)를 바꾸는 일이라 발표 뒤 별도 작업. 고친 뒤 이 하네스로 글자 수·시간·규칙을 비교합니다.

## 5단계(산출물) — 돌리기와 채점
```powershell
python -m app.하네스.돌리기 --상황 일본인커플_중구_가을_1박2일_산출물
```
- 경로: 화면 '최종 산출물 만들기'의 핵심인 `산출물.묶기 → 산출물.저장`. 입력은 4단계와 같은 확정 코스 + 11/26 실제 4단계 결과(고정본). AI 없음.
- 담당자가 표현 필터를 모두 '그대로둠'으로 확인했다고 보고 만듭니다(화면에서는 이 확인 없이 만들 수 없음). 코스 이름 확정·랜딩 주소 붙이기는 하지 않습니다.

| 항목 | 기준 |
|---|---|
| 만들기 | 오류 없이 결재 파일·제안서·홍보물 묶음 세 파일이 만들어짐 |
| 제품 대조 | `산출물.대조`(코스 장면·경고·미확인 표시)에 불일치 없음 |
| 장소 | 코스의 관광지가 세 파일에 모두 나옴 (식사 칸은 방식 미선택이면 권역만 쓰는 규칙이라 뺌) |
| 경고 | 3단계 남은 경고(W1 등)가 묶음 기록(`5단계_묶음.json`)에 모두 보존됨 — 결재 파일·제안서는 공개용이라 경고를 빼는 설계 |
| 공개 파일 | 세 파일에 R53 같은 내부 ID·'미확인' 표시 없음 |

## 3단계 입력: 1·2단계 고정본을 씁니다
- `시험상황/고정입력/` 의 `3단계_전달_준비.json`은 2026-11-26 `/plan/` 실행(가상설문 CSV 13행 적용, 검사 통과)을 복사한 것입니다.
- 왜: 2단계 AI를 매번 부르면 토큰이 들고, 요약이 매번 달라져 3단계 변화만 비교할 수 없습니다.
- 2단계 코드·자료를 크게 바꿨다면 새로 `/plan/`을 한 번 돌려 고정본을 바꿔 넣고, 점수표 비교가 끊긴다는 점을 기록하세요.

## 3단계는 어떤 경로를 부르나
`/plan/` 화면과 관리자 화면 모두 `app/서버/관리자실행.py`의 `코스시험.저장 → 시작`으로 3단계를 돌립니다. 하네스도 같은 함수를 부르기만 하고 제품 동작은 바꾸지 않습니다.
단, `/plan/`은 3단계 뒤에 B안 보완·총괄 단계가 더 있습니다. 하네스는 **3단계 첫 응답만** 봅니다.
