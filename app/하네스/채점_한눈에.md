# 하네스 채점 — 발표용 정리

> 우리 AI 에이전트가 "매번, 같은 기준으로, 규칙을 지키는지"를 숫자로 보여 주는 장치입니다.

## 1. 왜 하네스가 필요한가

- AI는 같은 조건을 줘도 **매번 조금씩 다른 답**을 냅니다. 한 번 잘 나왔다고 해서 다음에도 잘 나온다는 보장이 없습니다.
- 우리 서비스의 사용자는 대구시 관광 담당자·관광재단·여행사입니다. 이들이 받는 결과물(코스·홍보물·결재 파일)이 **휴무일 장소, 과장 광고, 지어낸 수치**를 담으면 그대로 행정 문서와 홍보물로 나갑니다.
- 그래서 "보기에 괜찮다"가 아니라 **규칙을 어겼는지 코드로 세어** 기록합니다.

| 구분 | 기존 단위 시험 (`app/시험/`) | 하네스 (`app/하네스/`) |
|---|---|---|
| AI | 가짜 AI(미리 적어 둔 답) | **실제 AI** |
| 보는 것 | 코드가 고장 났는지 | AI 결과가 규칙을 지키는지, 시간 안에 끝나는지 |
| 채점 | 코드 | **코드** (AI가 AI를 채점하지 않음, 토큰 0) |
| 기록 | 통과/실패만 | 날짜별 점수표 + 이전 실행과 비교 |

## 2. 어떻게 돌아가나

```
시험 상황(조건 고정) → 제품 코드 그대로 실행(실제 AI) → 결과 파일 → 채점 코드(규칙 검사) → 점수표 저장 · 이전과 비교
```

- **제품 코드를 바꾸지 않습니다.** 담당자 화면(`/plan/`)이 부르는 것과 같은 함수를 하네스도 부릅니다. 그래서 하네스 결과는 곧 실제 화면 결과입니다.
- **시험 조건**: 일본어권 · 중구 · 가을 · 1박2일 · 커플 · 자율이용, 가상설문 CSV(13행) 사용.
- **단계별로 따로 돌립니다.** 고친 단계만 시험하면 시간과 비용이 덜 듭니다. 앞 단계 결과가 필요하면 저장해 둔 **고정본**(예전에 실제로 나온 결과)을 넣어, 앞 단계의 흔들림이 섞이지 않게 합니다.
- **반복 실행**: `--반복 5`처럼 같은 조건을 여러 번 돌려 "5번 중 몇 번 통과"를 봅니다. AI의 들쭉날쭉함을 숫자로 확인하는 방법입니다.

## 3. 단계별 채점 기준과 이유

### 2단계 — 수요 근거 요약 (AI 1번)

| 항목 | 이유 |
|---|---|
| 요약 30초 이내 | 제품에 정한 시간 상한. 넘으면 화면에서 멈춤 |
| 3단계 전달 검사 통과 | 다음 단계가 읽을 수 있는 형식인지 |
| 기관 자료(가상설문) 반영 | 담당자가 올린 데이터가 실제로 쓰였는지 |
| **요약에 근거 밖 숫자 없음** | AI가 통계를 지어내면 결재 문서가 틀림. 요약 속 숫자가 근거표에 모두 있는지 대조 |

### 3단계 — 코스 (AI 1번)

| 항목 | 이유 |
|---|---|
| 60초 이내 | 제품 시간 상한 |
| 형식 검사 통과 | 코드가 시간표로 조립할 수 있는지 |
| 치킨은 저녁 1번까지 | 팀 결정: 치킨은 저녁 선택 옵션, 메인 고정 아님 |
| **낮 치킨 식사 없음** | 낮은 대구 관광, 치킨은 해설·스토리 요소로만 |
| 휴무·운영시간·시간 충돌 없음 | 문 닫은 곳으로 안내하면 상품 신뢰가 무너짐 |
| **후보표 밖 장소 없음** | AI가 존재하지 않거나 검증 안 된 장소를 만들지 않았는지 |
| 1박2일이면 숙박 칸 있음 | 목표인 "체류 연장·숙박 연계"를 지키는지 |
| A/B안 둘 다(또는 B 불가 이유) | 담당자가 비교해 고를 수 있어야 함 |
| (치킨 선택 시) 후보표·저녁 후보에 치킨이 보임 | 담당자가 치킨을 골랐으면 실제로 선택지에 나와야 함 |

### 4단계 — 홍보 문구·번역 (AI 1번, 검사에 걸리면 1번 더)

| 항목 | 이유 |
|---|---|
| 호출마다 420초 이내 | 제품 시간 상한 |
| 제품 검사 통과 | 장면 ID·후보 식당·번역 표기·출처 ID 형식 |
| 첫 시도에 통과 | 다시 쓰기가 잦으면 시간·비용이 두 배 |
| **공개 문구에 내부 표시 없음** | 관광객이 보는 글에 'R53', '미확인', 'AI 초안' 같은 내부 기록이 새면 안 됨 |
| **금지 표현 없음** | 원조·최고의·365일·치킨의 수도 등 확인 안 된 과장 표현(지침 5_표현_필터) |
| 번역 언어·장면 빠짐 없음 | 일본어권 조건이면 모든 장면에 일본어가 있어야 함 |
| 식비 미정 안내 없음 | 공개 홍보물에 "식비 포함 여부 미정" 같은 내부 메모가 나가지 않게 |

### 5단계 — 결재 파일·제안서·홍보물 묶음 (AI 없음)

| 항목 | 이유 |
|---|---|
| 만들기 오류 없음 · 세 파일 생성 | 최종 산출물이 실제로 나오는지 |
| 코스·경고 대조 불일치 없음 | 세 파일이 서로 다른 내용을 말하면 안 됨 |
| 코스 장소가 세 파일에 모두 나옴 | 빠진 장소가 없는지 |
| 남은 경고가 기록에 모두 보존 | 공개 문서에서는 경고를 빼지만, 담당자용 기록에는 남아야 함 |
| 공개 파일에 내부 표시 없음 | 4단계와 같은 이유 |

## 4. 최근 결과 (2026-11-27, 실제 AI)

| 단계 | 걸린 시간 / 상한 | AI 입력·출력 글자 | 결과 |
|---|---|---|---|
| 2 수요 근거 | 15.5초 / 30초 | — | 4/4 통과 |
| 3 코스 (치킨 빼기) | 25.8초 / 60초 | — | 모두 통과 |
| 3 코스 (치킨 선택) | 29.6초 / 60초 | — | 모두 통과 |
| 4 홍보 | 124.1초 / 420초 | 받은 약 18.7만 자 · 쓴 약 7,500자 | 7/7 통과 |
| 5 산출물 | 0.01초 | AI 없음 | 6/6 통과 |

점수표 예시 (4단계, `결과/점수표_20261127_075243.md`에서 발췌):

| 항목 | 결과 | 메모 |
|---|---|---|
| 공개 문구에 내부 표시 없음 | 통과 | 공개 글 45곳 확인 |
| 금지 표현 없음 | 통과 | 없음 |
| 번역 언어·장면 맞음 | 통과 | 일본어 7행 |

점수표 머리에는 **커밋 번호**와 **이전 실행과의 비교**("항목 결과 같음 · 116.8초→124.1초")가 적혀, 코드를 바꾼 뒤 좋아졌는지 나빠졌는지 바로 보입니다.

## 5. 하네스로 실제로 잡아낸 것

1. **치킨을 0개로 세던 오류** — 코스를 조립하면 장소 이름에서 "(치킨 옵션)"이 빠져, 치킨 저녁이 있어도 없다고 판정했습니다. 후보표의 치킨 장소 이름과 대조하도록 고쳤습니다.
2. **규칙보다 엄격한 채점** — 처음에는 "치킨 선택 시 A안 저녁에 치킨 1번"을 요구했지만, 지침은 "어느 단계에서도 치킨을 고정하지 않는다"였습니다. "저녁 후보에 치킨이 보이는가"로 바꿨습니다. 채점 기준도 지침과 맞춰 검증해야 한다는 점을 확인했습니다.
3. **공개 문서의 경고 처리 확인** — 결재 파일·제안서에 경고가 없어 실패로 나왔는데, 코드를 보니 공개용이라 일부러 빼는 설계였습니다. 경고는 담당자용 기록에 모두 남는지로 채점을 바꿨습니다.
4. **4단계 입력이 너무 큼** — AI가 한 번에 약 18만 자를 받습니다(근거목록 약 10만 자, 지침 약 6.7만 자). 시간과 비용의 주원인이라 발표 뒤 줄일 과제로 기록했습니다.
5. **제품 흐름 변경 반영** — 11/27 "확정 코스 홍보 직결"(홍보 화면에서 일정을 다시 묻지 않음) 변경 뒤에도 4단계가 그대로 통과하는지 바로 확인했습니다.

## 6. 한계와 다음 과제

- **코드로 보지 못하는 것**: 스토리가 사실인지, 출처 등급이 맞는지, 문구가 매력적인지. → 독립 검증 에이전트(지침 `검증.md`)로 볼 예정.
- **조건이 하나뿐**: 지금은 일본인 커플 · 중구 · 1박2일만. → 가족(술 없음)·당일·다른 언어권·동구 조건 추가.
- **단계 연결**: 지금은 4단계 결과를 고정본으로 5단계에 넣음. → 4→5단계를 이어 돌리기.
- 실제 화면에서 실패한 기록을 시험 상황으로 바꿔 쌓기.
