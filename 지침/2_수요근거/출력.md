# 2단계 수요 근거 — 출력

## 화면에 나오는 결과

역할표 2단계의 "수요 분석 요약 + 근거표 + 경고"다. 화면에 보이는 것과 3단계로 넘기는 것은 **같은 내용이지만 분량이 다르다.** 화면은 읽기 쉽게 줄이고, 넘기는 것은 줄이지 않는다 (2026-11-19 MVP 실행에서 근거표가 29행이라 화면에서 읽기 어려웠다).

## 1. 화면 출력 형식

```
## 수요 분석 요약
- 방문객: ...
- 좋았던 점: ...
- 음식: ...   ← 치킨 · 닭 관련 값은 순위와 상관없이 별도 한 줄 (근거표.md 2장)
- 숙박: ...
- 보조: ... (방문 목적 · 동반자)
(문장마다 출처 · 연도 · 표본. 항목당 대표 값 1~2문장. 나머지 값은 근거표에 둔다)
해석: ...  ← 수요의 세기 · 근거의 강약만. 코스 · 장소를 고르거나 막는 말은 쓰지 않는다

## 체류 기간 추천  ← 1단계에서 "추천받기"를 골랐을 때만 (`추천.md`)

## 근거표  ← 항목당 기본 3행만 펼쳐 보이고 나머지는 "더 보기" (`근거표.md` 4장)
| ID | 항목 | 원자료 항목명 | 수치 | 파일 · 행 위치 | 출처 | 연도 | 표본 · 대상 | 한계 | 경고 |
(열 이름은 이대로 쓴다. 앱이 이 열 이름으로 근거목록을 만든다. ID 하나에 수치 하나)

## 더 보기 (접힌 행)  ← 접힌 행도 위와 같은 10열 표로 쓴다

## 경고 (E3)
- [W1 경고 종류] 문구 (적용 근거: R03 · R04)  ← 없으면 "없음". 경고마다 "적용 근거"를 반드시 붙인다. 빠지면 앱 검사에서 연결 누락으로 걸린다. 연속된 ID는 `R08~R12`처럼 범위로 써도 된다

## 담당자 선택 (E3)
- 조건 바꾸기(1단계로) / 경고를 남기고 진행  ← 담당자가 고르기 전에는 "미선택"
```

### 1-1. 근거표 작성 규칙 (앱이 읽는 형식)

2026-11-22 실제 실행에서 아래 세 가지 때문에 3단계 전달 검사를 통과하지 못했다. `## 근거표`와 `## 더 보기` 절의 표는 모두 이 규칙을 지킨다.

| 규칙 | 지키지 않은 예 (11-22) | 이렇게 쓴다 |
|---|---|---|
| 근거 행이 있는 표는 위 10열 머리를 그대로 쓴다. 열을 줄이지 않는다 | `\| ID \| 조건 · 항목 \| 수치 \|`처럼 3열로 줄이고 출처 · 파일을 표 위 글로 씀 | 같은 값이어도 행마다 출처 · 파일 · 행 위치를 칸에 채운다 |
| 한 행에 R 하나, 한 칸에 근거 하나 | `\| 2026 \| R18 대구 약령시… · R19 … \|`처럼 근거 여러 개를 한 칸에 묶음 | R18 · R19를 각각 한 행으로 쓴다 |
| 수치 칸에는 숫자 하나와 단위만. 계산 설명은 괄호 안에 둔다 | 괄호 밖에 숫자가 둘 이상 | `115,400명 (계산값: 32,214 + 38,368 + 44,818)` |
| 파일 약칭을 쓰면 머리를 `\| 약칭 \| 파일 \|`로 둔다 | — | 앱이 약칭 표를 근거 행으로 읽지 않고, 파일 칸의 F1 … 을 경로로 바꾼다 |

앱은 괄호 밖의 숫자를 수치로, 괄호 안을 `수치_설명`으로 나눠 담는다. 괄호 밖 숫자가 하나가 아니면 그 행은 "수치가 숫자 하나가 아님"으로 걸린다.

## 2. 3단계로 넘기는 것

> 실제 전달 형식(JSON 필드 · 앱 검사)은 `지침/공통/단계_넘김.md` 4장이 정의한다 (초안). 아래는 담을 내용의 설명이다.

담당자가 "경고를 남기고 진행"을 고르면 아래 블록이 3단계로 간다. "조건 바꾸기"를 고르면 1단계로 돌아가고 3단계로는 넘기지 않는다.

```
## 3단계로 넘기는 것
1. 조건: 방문객 · 시기 · 언어권 · 지역(목록, 여러 구 가능) · 체류 기간 (1단계 그대로)
   - 확정 체류 기간: 당일 / 1박2일 / 미선택   ← 추천받기였으면 담당자가 고른 값
2. 담당자 선택 (E3): 경고를 남기고 진행 / 미선택
3. 수요 분석 요약 (화면과 같은 문장)
4. 근거표 전체 (화면에서 접은 행 포함). 행마다 근거 ID (R01 …) · 원자료 항목명 · 파일 · 행 위치. ID 하나에 수치 하나
5. 경고 목록: 경고 ID (W1 …) · 종류 · 문구 · 적용 근거 ID
6. 체류 기간 추천 (추천받기였을 때)
7. 대구 도착 · 출발 지점 (동대구역 · 서대구역 · 대구공항 · 고속버스터미널 등 비율): 정리본이 없으면 "미확보"로 적는다 ([자료 필요]). 외국인은 인천 · 김해로 입국해 KTX · 버스로 들어올 수 있으므로 공항 비율만으로 채우지 않는다. 2026-11-19 확인: 보유한 외래관광객조사 2024 원자료 · 코드북에는 입국 공항 · 국내 진입 교통수단 문항이 없고, 대구관광실태조사 해당 표는 미확보
8. 확인 전 표시 (받은 그대로 보관):
   - 올린 기관 데이터가 있었으면 E2 처리 결과 (다시 올림 / 경고 달고 씀 / 뺌)
   - 근거표 · 요약에서 `[자료 필요]` 로 남긴 칸
   - "쓰지 않는 수치" 중 담당자가 올려서 "확인 전 수치"로 알린 것
```

### 3단계가 이 블록을 쓰는 법

| 블록 항목 | 3단계에서 쓰는 곳 | 2단계가 지키는 것 |
|---|---|---|
| 근거 ID | 장소별 근거 "넣은 이유 · 근거 수치"에서 `R07`처럼 가리킴 | 같은 실행 안에서만 같은 ID. 조건이 바뀌면 새로 매기고 이전 ID를 다시 쓰지 않는다 |
| 경고 ID · 적용 근거 ID | 장소가 쓴 근거 행에 달린 경고를 장소 근거 "이어받은 경고"에 자동으로 모은다 | 경고마다 적용 근거 ID를 빠뜨리지 않는다. 지우거나 합치지 않는다 |
| 항목 (방문객 · 좋았던 점 · 음식 · 숙박) | 3단계가 코스 칸(낮 · 점심 · 저녁 · 밤 · 숙박)과 짝짓는다 (3단계 `3_코스_짜기.md` 1장). **짝짓기는 3단계가 한다** | 2단계는 장소 · 코스 칸을 고르거나 표시하지 않는다 |
| 자료 속 장소 이름 | 3단계가 장소 운영 정보의 공식 명칭과 맞춘다 | 자료에 적힌 이름 그대로 넘긴다. 같은 장소의 다른 표기("서문시장&야시장" · "서문시장(야시장)")를 2단계가 묶지 않는다 |
| 대구 도착 · 출발 지점 | 참고만 한다. 3단계는 이 값으로 코스 시작 · 종료를 정하지 않는다 (코스 시작 · 종료는 담당자가 정하거나 3단계 후보를 담당자가 확인, 3단계 `2_입력.md` 5-2) | "미확보"여도 그대로 넘긴다 |

## 3. 3단계와 합의할 것

항목을 바꾸면 3단계 `2_입력.md` 1장도 같이 고친다 (사람2 브랜치).

- 근거 ID · 경고 ID 형식 (`R01` · `W1`)을 3단계가 받아 쓰는지.
- 근거표 전체를 표로 넘길지 파일(CSV 등)로 넘길지 `[자료 필요: 코스 검토 담당과 합의]`.
- "확정 체류 기간"이 "미선택"으로 넘어오면 3단계가 시작하지 않고 담당자에게 되묻는지.
