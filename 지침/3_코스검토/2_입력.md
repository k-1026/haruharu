# 3단계 코스 검토 — 입력

## 1. 2단계에서 받는 것

2단계 `출력.md`의 "3단계로 넘기는 것" 블록을 그대로 받는다 (`지침/2_수요근거/출력.md` 2장). 실제 전달 형식(필드 이름 · 앱 검사)은 `지침/공통/단계_넘김.md` 4 · 5장을 따른다.

| 받는 것 | 내용 | 3단계에서 쓰는 곳 |
|---|---|---|
| 조건 | 지역 · 계절 · 체류 기간 · 대상 국가, 언어권 (1단계 그대로). 지역은 중구 · 동구 중 여러 개. 기본값은 없다 (빠지면 1단계가 알리고 멈춤, 사람1 `지침/1_기획조건/입력.md` "받을 때 규칙"). MVP 테스트는 중구 | 코스 틀 (`3_코스_짜기.md` 1장) |
| 확정 체류 기간 | 당일 / 1박2일 / 미선택 (추천받기였으면 담당자가 고른 값) | 숙박 칸 · 일차 |
| 담당자 선택 (E3) | 경고를 남기고 진행 / 미선택 | 시작 조건 (아래) |
| 수요 분석 요약 | 화면과 같은 문장 | 장소별 근거 "넣은 이유" |
| 근거표 전체 | 행마다 **근거 ID** (`R01` …). 항목 · 수치 · 단위 · 출처 · 출처 ID · 연도 · 대상 · 표본 · 한계 · 자료 속 장소 이름 | 장소별 근거에서 `R07`처럼 ID로 가리킨다 (`5_장소_근거.md`) |
| 경고 목록 | **경고 ID** (`W1` …) · 종류 · 문구 · 적용 근거 ID 목록 | 장소가 쓴 근거 ID에 달린 경고를 "이어받은 경고"에 ID째 모은다 |
| 체류 기간 추천 | 추천받기였을 때 | 참고 |
| 코스 작성 조건 (있으면) | 시작 지점 · 시작 시각 · 종료 지점 · 종료 시각 · 치킨 선택 (선택 / 안함 / 미선택). **식사 칸마다 식사 방식 (지정식 / 자유식 / 미선택) · 지정식이면 식당 · 식비 포함 (포함 / 불포함 / 미정)**, **2일차 오전 구성 (후보로 일정 추가 / 자유시간 / 종료 장소로 바로 / 미선택)**, **운영 방식 (단체 동행형 / 개별 이동형 / 미정)** (2026-11-22 추가). 앞 단계에서 담당자가 정한 값만, 없으면 미선택 · 미정 | 5-2 코스 시작 · 종료, 5-1 치킨, `3_` 1-1 · 1-2 |
| 대구 도착 · 출발 지점 | 비율 또는 "미확보" | **코스 시작 · 종료를 정하는 데 쓰지 않는다** (5-2). 참고로만 보여 준다 |
| 확인 전 표시 · 미확인 사항 | 기관 데이터 E2 처리 결과, `[자료 필요]` 칸, 확인 전 수치 | 받은 그대로 보관하고 4단계로 넘긴다 |

**3단계를 시작하지 않는 경우:** 확정 체류 기간이 "미선택"이거나 담당자 선택(E3)이 "미선택"이면 코스를 만들지 않고 담당자에게 되묻는다 (2단계 `출력.md` 3장, `단계_넘김.md` 5장).

**ID 규칙:** 근거 ID · 경고 ID는 2단계가 매긴 그대로 쓴다. 3단계가 새로 매기거나 합치거나 지우지 않는다. 조건이 바뀌어 2단계가 새 ID를 매기면, 이전 ID를 가리키던 3단계 결과는 "다시 확인 필요"가 된다.

- 코스 시작 · 종료 장소와 시각 — **필수 항목이 아니다.** 앞 단계에서 담당자가 이미 정한 값이 있으면 그대로 받고, 없으면 3단계에서 정한다 (5-2). 2단계의 "대구 도착 · 출발 지점" 통계(입국 공항 · 대구 진입 교통수단)는 코스 생성의 필수 입력이 아니며, 통계가 없다고 코스 시작 · 종료 장소를 추측하지 않는다 (사람1 `1120_유저플로우_보완안_사람1.md` 0장 · 2-3 ②, 2026-11-20 반영)

- 블록 항목: 2026-11-20 사람1 2단계 `출력.md` 2장 · `단계_넘김.md` 4장에 맞춤 (R · W ID 형식을 3단계가 받아 씀, 미선택이면 시작 안 함). 근거표를 표로 넘길지 파일로 넘길지는 `단계_넘김.md`(JSON 객체 목록)를 따른다. 항목이 바뀌면 이 파일과 2단계 `출력.md`를 함께 고친다.

## 4-1. 앞 단계가 바뀌었을 때 — 이전 코스 다루기

사람1 1120 보완안 3-1 · 3-2 반영, 2026-11-20 사람2 결정. 1단계 조건이나 2단계 근거가 바뀌면 3단계 코스는 "다시 확인 필요"가 된다. 담당자가 "새로 만들기" / "이전 코스 가져와 다시 확인" 중에 고르고, 에이전트는 바뀐 곳에 따라 **기본값을 먼저 보여 주기만** 한다.

| 바뀐 곳 | 먼저 보여 주는 기본값 | 이유 |
|---|---|---|
| 1단계 조건 (지역 · 계절 · 언어권 · 체류 기간) | **새로 만들기.** 이전 코스는 "이전 조건 결과"로 보관 (지우지 않음) | 지역 · 체류 기간이 바뀌면 코스 틀(칸 · 숙박 · 지역) 자체가 달라진다 |
| 2단계 근거만 (기관 데이터 교체 · 근거 수치 변경) | **이전 코스 가져와 다시 확인** | 장소 · 시간은 그대로 쓸 수 있는 경우가 많다. 대체안 · 직접 수정 · 겹침 선택 작업을 버리지 않는다 |

**가져올 때 규칙 (2단계 근거만 바뀐 경우)**

1. 장소 · 시간 · 코스 시작 · 종료는 그대로 둔다. 시작 · 종료는 "확정"에서 "후보 (담당자 확인 전)"로 되돌린다.
2. 장소별 근거를 새 근거 ID로 다시 잇는다. 못 이으면 "근거 없음"으로 표시한다 (`5_장소_근거.md`).
3. 충돌(E4) · 겹침(E7) · 체크리스트를 다시 돌린다. 이전 겹침 선택은 남기되 "다시 확인"으로 표시한다.
4. 다시 확정하기 전까지 4단계 장면은 "다시 확인 필요"다 (`../4_홍보검토/8_코스_변경.md` 4장).

- 앱은 아직 결과 버전 · "다시 확인 필요" 표시를 구현하지 않았다. 화면에서 "가져오기"를 언제 넣을지는 3.3 화면 작업 때 정한다. MVP 화면에 "새로 만들기"만 먼저 넣어도 이 지침과 어긋나지 않는다.

### 5-1. 치킨 비중 단계 (B10)

| 단계 | 치킨 비중 | 에이전트가 하는 것 |
|---|---|---|
| 1 (지금) | 해설 · 스토리 같은 **요소** + 저녁 **선택지 중 하나** | 저녁 칸에 치킨을 다른 음식과 나란히 후보로만 보여 준다. 담당자가 고르지 않으면 넣지 않는다 |
| 2 | 저녁 **추천 1순위** + 낮 체험 **후보 추가** | 저녁 후보 중 치킨을 먼저 보여 준다. 담당자가 뺄 수 있다 |
| 3 | 치킨이 코스의 **주제**. 치킨 식사는 하루 1번까지 | 장소 고르기와 해설에 치킨을 우선 반영한다. 식사는 하루 1번 |

- 어느 단계에서도 치킨을 "고정"(무조건 들어감)하지 않는다. 바뀌는 것은 얼마나 먼저 · 자주 보여 주느냐뿐이다 (B10).
- 단계를 올리는 기준(상시 치킨 체험 수, 인지도 지표 등)의 수치는 정하지 않았다 `[자료 필요: 팀 확정]`. 단계 값은 팀이 바꾼다.

### 5-2. 코스 시작 · 종료 장소와 시각

사람1 `1120_유저플로우_보완안_사람1.md` 0장 · 2-3를 반영했다 (2026-11-20). 이전의 "1박2일 첫 · 마지막 구간 = 대구공항(가정)"은 쓰지 않는다.

1. **정하는 방법:** 담당자가 코스 시작 장소 · 시각, 종료 장소 · 예정 시각을 미리 지정하거나, 에이전트가 코스와 함께 후보를 제안하고 담당자가 확인한다.
2. **후보 제안:** 에이전트는 코스의 첫 장소 · 마지막 장소와 `5장` 시작 시각 후보로 제안한다. 역 · 공항은 담당자가 고른 경우에만 시작 · 종료 장소가 된다. 제안값에는 "후보 (담당자 확인 전)"을 붙인다.
3. **미정 허용:** 시작 · 종료가 정해지지 않아도 코스 초안은 만든다. 초안 생성을 막지 않는다.
4. **확정 조건:** 시작 · 종료 장소와 시각이 담당자 확인으로 확정되지 않으면 "코스 확정"을 완료하지 않는다. 초안은 보관한다 (`12_코스_체크리스트.md` C7). 이것은 "진행을 막지 않는다"(`1_역할.md`)의 예외로, 확정 단계에서만 적용한다.
5. **1박2일:** 날짜 · 일차를 함께 표시한다 (예: 1일차 10:00 시작 · 2일차 ○○:○○ 종료). 단체가 함께 모이는지, 매일 따로 출발하는지 같은 운영 방식은 이 항목으로 정하지 않는다.
6. **범위 밖:** 관광객 픽업, 기차표 등 교통편 제공, 코스 시작 전 · 종료 후 이동은 다루지 않는다. 시작 장소가 역 · 공항이어도 "그곳에서 코스를 시작한다"는 뜻일 뿐 픽업 · 교통편 제공이 아니다. 교통 연계는 향후 검토로 남긴다.
7. **이어받기:** 확정값은 4단계(홍보 안내)와 5단계(문서)로 넘긴다 (`6_출력.md`). 바뀌면 4단계 관련 안내 문구 · 번역을 다시 확인한다.
