# 자율 이용 상품의 기획 초안

2026-11-24 사용자 요청 적용. 팀 공통 운영 기준을 확정한 기록이 아니다. 입력의 `기획모드`가 `자율이용`일 때 아래 규칙을 우선한다. 기존 확정·홍보·산출물 실행의 기준은 별도로 보존한다.

## 코드와 AI의 역할

- 전체 총괄은 자료 확인 → 수요 분석 → A/B 코스 작성 → 결과 검사 → 필요한 검증·보완까지 진행 상태·실패·결정 이유를 관리한다.
- 자료 선택·근거표·표본 및 변동 경고·형식·시간표 검사는 코드가 한다. 정해진 순서와 완료 판단을 위해 AI를 부르지 않는다.
- 수요 AI는 코드가 고른 근거를 요약·해석한다. 코스 AI는 한 번의 작성 요청에서 A와 B를 제안한다. 독립 검증은 각 안을 확인한다. 오류의 해결 방향을 정해야 할 때만 AI 총괄을 부른다.
- 자료가 부족하거나 응답이 잘못되면 확보한 기록과 이유를 보존한다. 반복을 늘려 완료한 것처럼 만들지 않는다. 역할별 제한 시간·호출 한도를 따른다.

## 상품 안의 자율성

| 구분 | 초안에서 다루는 법 |
|---|---|
| 권장 일정 | 방문 순서·예상 시각·권장 체류시간. 강제 집결 시각이나 예약 확정이 아니다 |
| 자유 이용 구간 | 관광·식사·자유시간을 운영시간 안에서 선택할 수 있도록 제안한다 |
| 운영시간 | 자료에서 확인된 장소의 영업·휴무·마감 조건. 권장 일정과 대조한다 |
| 예약·이용권 유효시간 | 실제로 입력·확인된 조건만 적용한다. 미정인 사용처·유효시간·포함 혜택·예약을 만들지 않는다 |
| 집결·해산 | 단체 동행·교통·예약 때문에 필요한 상품에서만 별도 설정한다. 자율 이용 초안의 필수 입력이 아니다 |
| 숙박·둘째 날 오전 | 1박2일이면 권역·후보·관광 또는 자유시간 구성을 제안한다. 객실·체크인·오전 구성을 담당자가 먼저 확정하도록 요구하지 않는다. 당일형에 숙박·둘째 날을 추가하지 않는다 |

초안에서는 미정인 운영 입력을 채우려고 사람의 선택을 대신 기록하거나 `확정조건`을 true로 바꾸지 않는다. 실제 예약 시각 위반·휴무·잘못된 동선·일정 충돌·필수 지역 위반은 계속 검사한다.

## A/B 비교

- A안: 입력한 요청과 희망을 우선한 권장 구성.
- B안: 이동·운영 부담을 줄이도록 희망·방문 순서·자유 구간을 조정한 구성. 무엇을 왜 바꿨는지, 좋아진 점과 남은 한계를 적는다.
- 지역·계절·언어권·체류기간 등 필수 조건을 자동 변경하지 않는다. B안의 '조건 조정'은 조정 가능한 희망·구성을 뜻하며 필수 조건 완화를 뜻하지 않는다.
- A를 복제하거나 말만 바꾼 안은 B로 등록하지 않는다. 다른 대안을 만들 근거가 없거나 AI 응답에 B가 없으면 미생성 이유를 표시한다. 기존 저장본의 B를 꾸며 넣지 않는다.
- A/B 선택·초안 저장은 판매 확정·예약·홍보 승인과 다르다. 두 안 모두 검사 상태를 따로 남긴다.

## 기획 화면과 운영 로그

- 기획자에게는 코스 비교·권장 일정·자율 구간·주요 보완 이유를 짧게 제공한다. 집결·해산·숙소 확정·기존 상품 겹침 처리 선택을 초안의 할 일로 강요하지 않는다.
- 기존 상품 겹침은 기존 골목투어·스탬프투어와 비슷한지 보는 내부 차별화 참고다. 자동 금지나 관광객의 이용 불가를 뜻하지 않는다.
- `/admin/`은 서비스 제공자의 읽기 전용 실행·오류·검사·원문 조회다. 코스 수정 화면으로 연결하지 않는다. 기존 개발용 수정 파일·API와 저장 원본은 보존한다.
