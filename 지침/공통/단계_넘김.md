# 단계 넘김 — 단계 사이에 주고받는 JSON

상태: 초안 v0.2 (2026-11-22). 팀 검토 전. 3→4·4→5는 integration/stage-1-5에 병합된 PR #10의 M1 점검 3장 제안을 옮긴 통합시험용 형식이다. PR 병합을 JSON 세부 규칙의 공동 합의·실제 시험 완료로 간주하지 않는다.

## 1. 원칙

- 단계 사이는 글이 아니라 JSON으로 넘긴다. 화면은 이 JSON을 표 · 카드 · 알림으로 바꿔 보여 준다.
- 지침에 "JSON으로 출력"이라고 적는 것으로 끝내지 않는다. **앱이 받기 전에 검사한다** (3장). 검사에 실패하면 다음 단계로 넘기지 않고 같은 단계를 다시 실행한다.
- 이 파일이 넘김 형식의 단일 정의다. 각 단계 `출력.md` · 입력 파일은 이 파일을 가리키고, 형식을 바꾸면 이 파일을 먼저 고친다.
- 값을 모르면 칸을 비우지 않고 `"미확인"` 또는 `"미확보"`로 쓴다. 없는 값을 추정해 채우지 않는다.

## 2. 모든 단계 JSON의 공통 머리

| 필드 | 형식 | 뜻 |
|---|---|---|
| 프로젝트ID | 문자열 | 어느 기획인지 (앱이 부여) |
| 실행ID | 문자열 | 그 기획의 몇 번째 실행인지 (앱이 부여) |
| 단계 | 정수 1~5 | 이 결과를 만든 단계 |
| 결과버전 | 정수 | 같은 단계를 다시 실행할 때마다 +1 (앱이 부여) |
| 기준_결과버전 | 객체 | 이 결과가 쓴 앞 단계 버전. 예: `{"1": 2, "2": 1}` |
| 상태 | `확정` / `다시확인필요` | 앞 단계가 바뀌면 앱이 `다시확인필요`로 바꾼다 |

에이전트는 머리를 쓰지 않는다. 앱이 붙이고, 에이전트는 본문만 만든다.

## 3. 1단계 → 2단계

| 조건.체류기간 | `당일` / `1박2일` / `추천받기` | |

### 4-1. 코스작성조건 (3단계 전 담당자 입력)

| 필드 | 형식·허용값 | 비고 |
|---|---|---|
| 시작지점 · 종료지점 | 문자열 또는 `미확인` | 역·공항 기본값 없음. 종료는 관람을 마치고 코스가 끝나는 장소 |
| 시작시각 · 종료시각 | `HH:MM` 또는 `미확인` | 일차는 시간표에 명시. 미정이어도 초안 생성 가능 |
| 시작일차 · 종료일차 | 정수 `1` / `2` 또는 `미정` | 앱 구현 초안. 당일은 1만 선택 가능. 이전 기록의 누락 일차는 미정으로 읽으며 자동 지정하지 않음. 종료 일차·시각은 시작보다 빠를 수 없음 |
| 치킨선택 | `선택` / `안함` / `미선택` | 식당·메뉴를 강제하는 값이 아님 |
| 2일차오전구성 | `후보일정추가` / `자유시간` / `종료장소로바로` / `미선택` / `해당없음` | 당일은 해당없음. 1박2일 미선택이면 초안만 생성 |
| 2일차점심포함 | `포함` / `미포함` / `미정` / `해당없음` | 앱 구현 초안·팀 공통 형식 확정 전. 담당자의 명시적 선택이며 당일은 해당없음. 기존 입력에 없으면 미정으로 읽음 |
| 운영방식 | `단체동행형` / `개별이동형` / `미정` | 재집결 또는 다음 일정 도착 안내에 사용 |
| 식사목록 | 객체 목록 | 일차 · 시간칸 · 방식(`지정식`/`자유식`/`미선택`) · 식당(미지정은 `미선택`) · 식비포함(`포함`/`불포함`/`미정`) |
| 결정기록 | 객체 | 실제 입력 시각·입력경로. 입력자 이름을 추정하지 않음 |

- 입력 순서 초안: 시작·종료 → 치킨 옵션 → 2일차 오전 → 운영 방식 → 일차별 식사 방식·지정 식당·식비. 웹에서도 같은 내용을 담당자에게 받으며 관리자 로그 화면과 구분한다.
- 일정 확정 전에는 빈칸을 미선택·미정으로 남긴다. 포함 여부가 미정이면 점심 시간대 중첩을 검토하고 담당자가 정한다. 식사 방식·식비 설정만으로 식사·식당을 임의 추가하지 않는다. 담당자가 별도로 점심 ‘포함’을 선택한 수동 수정에서는 미정 시각·권역의 식사 칸을 둘 수 있지만, 이동·운영·시간 충돌 재검토와 담당자 코스 확정은 별도다.
- 2단계 수요 결과가 유효하지 않으면 코스 입력을 이유로 검사를 우회하지 않는다.

## 5. 앱이 검사하는 것

| 검사 | 실패하면 |
|---|---|
| 필수 필드 누락 | 같은 단계 재실행 |
| 자료형 (수치가 숫자인지, 체류기간이 허용값인지 등) | 재실행 |
| 근거ID · 경고ID 중복 | 재실행 |
| 경고의 적용근거ID가 근거목록에 없음 | 재실행 |
| 담당자판단의 채택근거ID가 근거목록에 없음 | 재실행 |
| 근거 수치가 `파일 · 행위치`의 CSV 값과 다름 | 재실행, 반복되면 담당자에게 알림 |
| 확정체류기간 또는 담당자선택_E3가 `미선택` | 3단계 시작 안 함, 담당자에게 되묻기 |
| 조건.지역이 빈 목록 · 필수 조건 누락 | 1단계 실행 전 입력을 다시 받음 (기본값을 넣지 않음) |
| 앞 단계 결과버전이 `기준_결과버전`과 다름 | 상태를 `다시확인필요`로 표시 |

## 6. 3단계 → 4단계 · 4단계 → 5단계 (통합시험용 초안)

`단계_넘김.md` 4장과 같은 방식으로 적었다. 공통 머리(2장)는 앱이 붙인다. 키는 4장처럼 한글로 두고, 영문 전환은 7장 결정을 따른다.

### 6-3. 통합시험 보완안 — 공동 확인 전

- 출처: integration/stage-1-5 `정리본/M1_점검_3·4단계.md` 3장(PR #10). 위 제안을 통합시험에 사용하되 공동 합의·실제 시험 완료로 표시하지 않는다.
- AI의 확정조건은 판정 자료이다. 앱은 담당자가 시작·종료와 E7 처리, 1박2일 오전 구성을 확인하기 전에는 4단계를 실행하지 않는다. 미선택을 자동 확정하지 않는다.
- 장면을 가리키는 키는 `안 + 칸ID`(4단계는 `안 + 장면ID`)이다. 안이 없으면 공통이며 동일 조합은 중복 불가. 여러 안에서 같은 칸ID를 쓰면 안을 명시한다.
- 칸 시각의 미정 값은 빈 문자열로 전달한다. 가정 시각은 가정 표시를 보존하고 홍보 시 '약'을 붙인다. 머무는시간과 다음까지 이동시간은 별개다.
- 식사목록의 자유식 식당은 빈 문자열. 2→3 입력의 미선택 값은 3단계 출력에서 빈 문자열로 바꾸며 지정식 식당이 미선택이면 오류다. 후보를 확정 방문지로 바꾸지 않는다.
- 출력의 번역 상태는 공통 지침과 같은 `AI 초안 / 검토 중 / 검토 완료`로 통일한다. 기존 제안의 붙여쓴 값은 같은 뜻으로 읽되 저장은 공백 있는 표준값을 사용한다. 에이전트는 AI 초안만 생성한다.
- 식비 미정은 내부 결과에 남기고 관광객용 코스 카드에서 포함·불포함을 추정하지 않는다. 표시 생략과 미확인 기록을 구분한다.
- 원자료 수치 대조, 결과 버전 관리, 시안 이미지 생성은 JSON 형식 검사 통과만으로 완료되지 않는다.
