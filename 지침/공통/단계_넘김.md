# 단계 넘김 — 단계 사이에 주고받는 JSON

상태: 초안 v0.1 (2026-11-20). 팀 검토 전. 1→2, 2→3은 구체적으로 적었고 3→4, 4→5는 3·4단계 담당(예진)과 정한 뒤 채운다.

## 1. 원칙

- 단계 사이는 글이 아니라 JSON으로 넘긴다. 화면은 이 JSON을 표 · 카드 · 알림으로 바꿔 보여 준다.
- 지침에 "JSON으로 출력"이라고 적는 것으로 끝내지 않는다. **앱이 받기 전에 검사한다** (3장). 검사에 실패하면 다음 단계로 넘기지 않고 같은 단계를 다시 실행한다.
- 이 파일이 넘김 형식의 단일 정의다. 각 단계 `출력.md` · 입력 파일은 이 파일을 가리키고, 형식을 바꾸면 이 파일을 먼저 고친다.
- 값을 모르면 칸을 비우지 않고 `"미확인"` 또는 `"미확보"`로 쓴다. 없는 값을 추정해 채우지 않는다.

## 2. 모든 단계 JSON의 공통 머리

| 필드 | 형식 | 뜻 |
|---|---|---|
| 프로젝트ID | 문자열 | 어느 기획인지 (앱이 부여) |
| 실행ID | 문자열 | 그 기획의 몇 번째 실행인지 (앱이 부여) |
| 단계 | 정수 1~5 | 이 결과를 만든 단계 |
| 결과버전 | 정수 | 같은 단계를 다시 실행할 때마다 +1 (앱이 부여) |
| 기준_결과버전 | 객체 | 이 결과가 쓴 앞 단계 버전. 예: `{"1": 2, "2": 1}` |
| 상태 | `확정` / `다시확인필요` | 앞 단계가 바뀌면 앱이 `다시확인필요`로 바꾼다 |

에이전트는 머리를 쓰지 않는다. 앱이 붙이고, 에이전트는 본문만 만든다.

## 3. 1단계 → 2단계

| 필드 | 형식 | 비고 |
|---|---|---|
| 조건.방문객 | 문자열 | |
| 조건.시기 | 월 목록 (정수) | 예: [3, 4, 5] |
| 조건.언어권 | 문자열 목록 | |
| 조건.지역 | 문자열 | |
| 조건.체류기간 | `당일` / `1박2일` / `추천받기` | |
| 자료목록 | 객체 목록 | 자료 · 파일 · 고른행(열=값) · 재는방식 |
| 공통자료 | 문자열 목록 | |
| 추천요청 | 참/거짓 | |
| 알림 | 객체 목록 | 종류 · 문구. 없으면 빈 목록 |
| 담당자선택 | `알림을남기고진행` / `미선택` | |

## 4. 2단계 → 3단계

| 필드 | 형식 | 필수 | 비고 |
|---|---|---|---|
| 조건 | 3장의 조건과 같음 | ○ | |
| 확정체류기간 | `당일` / `1박2일` / `미선택` | ○ | `미선택`이면 3단계가 시작하지 않는다 |
| 근거목록 | 객체 목록 | ○ | 아래 |
| 경고목록 | 객체 목록 | ○ | 없으면 빈 목록 |
| 요약 | 문자열 | ○ | 화면 요약과 같은 문장 |
| 추천 | 문자열 | | 추천받기였을 때 |
| 담당자판단 | 객체 | ○ | 채택근거ID 목록 · 경고확인여부 · 선택한 체류유형 |
| 코스작성조건 | 객체 | | 시작지점 · 시작시각 · 종료지점 · 종료시각 · 치킨선택(`선택`/`안함`/`미선택`). 값은 담당자가 정한다. 없으면 `미확인` |
| 대구도착출발지점 | 객체 | ○ | 값이 없으면 `"미확보"` |
| 미확인사항 | 문자열 목록 | ○ | `[자료 필요]` 칸, 기관 데이터 없음, 확인 전 수치 |

**근거목록 한 행**

| 필드 | 형식 | 뜻 |
|---|---|---|
| 근거ID | `R` + 숫자 | 같은 실행 안에서만 유일 |
| 항목 | `방문객` / `좋았던점` / `음식` / `숙박` / `보조` | |
| 수치 | 숫자 | 문자가 아니라 숫자 |
| 단위 | 문자열 | 명 · % · 박 · 건 |
| 출처 | 문자열 | |
| 출처ID | 문자열 | `research/sources.md`의 ID. 모르면 `미확인` |
| 파일 · 행위치 | 문자열 | 어느 CSV의 어느 행인지. 앱이 값을 대조한다 |
| 연도 | 문자열 | |
| 대상 | 문자열 | |
| 표본 | 정수 또는 `미확인` | |
| 한계 | 문자열 | |
| 계산값 | 참/거짓 | 계산식은 `계산식` 필드에 |
| 장소명_자료표기 | 문자열 | 자료에 적힌 이름 그대로 (묶지 않는다) |

**경고목록 한 행**: 경고ID(`W`+숫자) · 종류 · 문구 · 적용근거ID 목록 (비어 있으면 안 됨).

## 5. 앱이 검사하는 것

| 검사 | 실패하면 |
|---|---|
| 필수 필드 누락 | 같은 단계 재실행 |
| 자료형 (수치가 숫자인지, 체류기간이 허용값인지 등) | 재실행 |
| 근거ID · 경고ID 중복 | 재실행 |
| 경고의 적용근거ID가 근거목록에 없음 | 재실행 |
| 담당자판단의 채택근거ID가 근거목록에 없음 | 재실행 |
| 근거 수치가 `파일 · 행위치`의 CSV 값과 다름 | 재실행, 반복되면 담당자에게 알림 |
| 확정체류기간이 `미선택` | 3단계 시작 안 함, 담당자에게 되묻기 |
| 앞 단계 결과버전이 `기준_결과버전`과 다름 | 상태를 `다시확인필요`로 표시 |

## 6. 3단계 → 4단계 · 4단계 → 5단계 (자리만)

- 3→4: 코스 장면ID · 장소ID · 시각 · 근거ID · 이어받은 경고. `[자료 필요: 3·4단계 담당과 합의]`
- 4→5: 장면ID와 이어진 문구 · 언어 · 번역 검토 상태 · 금지 표현 검사 결과. `[자료 필요: 합의]`
- 5단계는 상태가 `확정`인 결과만 쓴다. 코스 · 수치 · 문구 · 경고가 세 문서(결재 · 제안서 · 홍보물)에서 같은지 대조한 결과를 JSON으로 남긴다.

## 7. 확인 필요

- 필드 이름을 한글로 쓸지 (CLAUDE.md는 CSV 열에만 한글 규칙. JSON 키는 영문으로 하자는 의견이 나올 수 있다) `[자료 필요: 팀 확정]`
- 장소를 가리키는 공통 장소ID (3단계 `장소_운영정보`와 합의)
- 시험값 (표본 작음 100명 미만, 변동 큼 2배)은 경고 종류 판정에 쓰며 팀 확정 전
